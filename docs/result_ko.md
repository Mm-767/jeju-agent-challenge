# 행사 효과 나란히 결과 설명자료

문제 정의, Agent 구조, 주요 기능, 실행 결과, 검증 방법과 한계, 센터 활용 방안

이 문서는 결과물이 무엇을 풀고, 어떻게 동작하며, 어디까지 믿을 수 있는지를 설명합니다. 설치와 사용 순서는 사용자 매뉴얼(manual_ko.pdf), 데이터 항목은 데이터 활용 명세(data_spec_ko.pdf)에 있습니다. 숫자는 모두 이 결과물의 코드와 동봉 데이터로 직접 계산하거나 측정한 값이고, 날짜를 함께 적었습니다.

## 1. 문제 정의

읍면 축제를 맡은 담당자는 결과보고서와 다음 해 예산 자료에 축제가 지역 소비에 준 영향을 적어야 합니다. 제주빅데이터센터의 카드 이용 현황(읍면동) 데이터에는 그 답이 들어 있지만, 흔히 쓰는 "작년 같은 달과 비교"로는 축제의 몫을 가려낼 수 없습니다.

| 문제 | 동봉한 공개 유동인구로 계산한 크기 | 단순 비교에서 생기는 일 |
|---|---|---|
| 계절 | 한림읍 8월 방문 지수 2024년 1.44, 2025년 1.40(연평균 = 1) | 성수기 축제는 효과와 상관없이 "늘었다"가 나온다 |
| 요일 | 한림읍 토요일 1.19, 수요일 0.89 | 주말이 많이 낀 행사가 부풀려진다 |
| 매년 열리는 축제 | 작년 같은 달에도 같은 축제가 있었다 | 효과가 있어도 차이가 0 근처로 나온다 |
| 자료 기간 | 카드 자료는 2023년 8월부터 | 2024년 7월 이전 행사는 작년 값이 없다 |

그래서 이 결과물은 다음 물음에 답합니다. **행사 기간에 개최 읍면의 관광객 카드 소비가, 행사 전 흐름이 나란했던 비교 읍면보다 더 늘었는가.** 답은 "비교 읍면보다 몇 % 더 늘었다"와 그 차이가 평소에도 생기는 크기인지까지이고, 축제 때문이라고 단정하지 않습니다.

여기에 센터 환경의 조건 두 가지가 붙습니다. 센터 카드 데이터의 값은 외부 AI로 보낼 수 없고, 결과물은 반출 기준(역산 불가, 10 미만 처리)을 지켜야 밖으로 나갑니다.

## 2. Agent 구조

AI는 센터 데이터를 볼 수 없는 상태에서 계산 계획만 세우고, 계산은 외부 연결이 잠긴 PC 안에서 코드가 합니다.

| 단계 | 외부 연결 | AI가 하는 일 | 코드가 하는 일 |
|---|---|---|---|
| 공개 단계: 방문 판단 | 열림 | 공개 유동인구를 조회 도구로 직접 보고 행사 기간 방문이 늘었는지 판단, 비교를 흐릴 행사가 있는 후보를 이유와 함께 뺌 | 행사 달·기준 기간 계산, 섬·다른 축제 규칙 제외, 유동인구 거리로 비교 후보 순위, AI 제출의 숫자 근거 대조 |
| 공개 단계: 계산 계획 | 열림 | 업종 묶음 4개 가운데 선택과 이유, 결과 문장 틀 4개, 방법 문단, 이 행사만의 한계 | 필수 빈칸, 인과 단정 표현, 숫자 근거 검사, 가상 데이터 리허설 |
| 센터 단계 | 잠김 | 하지 않음. 잠긴 뒤의 AI 호출은 보내지 않고 막는다 | 카드 CSV 검사, 10 미만 칸 묶기, 비교 계산, 행사 전 흐름과 행사 없던 달 확인, 보고서와 PDF |

- **모델.** Anthropic Claude Haiku 5.5(claude-haiku-5-5). 도구는 조회 도구 get_visit_series와 제출 도구 submit_judgement, submit_plan입니다. 제출 도구는 정해진 모양으로만 받고, 코드가 검사해 통과시키거나 이유를 붙여 돌려보냅니다. 단계마다 최대 3번입니다.
- **AI가 쓴 결과 숫자 0개.** AI가 쓴 글의 숫자는 입력이나 조회 결과에 있어야 통과합니다. 결과 숫자가 필요한 자리는 빈칸으로 쓰고 코드가 계산 뒤 채웁니다.
- **외부 전송 경계.** 외부로 요청을 보내는 코드는 egress.py 하나이고, 실행 중 외부 주소는 https://api.anthropic.com 하나입니다. 첫 센터 파일을 받기 직전에 잠그고, 보낸 요청은 모두 「AI에 보낸 내용」에 남습니다.
- **대체 경로.** 키가 없거나 AI가 3번 안에 통과하지 못하면, 계산할 수 있는 읍면 행사 26개는 미리 만든 계획으로 끝까지 동작합니다. 장소 확인에서 고른 읍면이 계획의 읍면과 같을 때만 씁니다.

## 3. 주요 기능

| 화면 | 기능 |

| 2 장소 확인 | 행사 파일에 장소 열이 없어 AI가 짐작해 둔 개최 읍면과 이유를 보여 주고, 사람이 확정한다 |
| 3 AI 비교 계획 | 방문객 판단과 이유, 비교할 읍면, 비교에서 뺀 읍면(규칙·AI 구분), 비교할 업종과 이유 |

| 5 보고서 | 결론, 상황, 과제, 방법, 결과, 한계와 활용 순서의 화면과 PDF, 그림 2장, 활용 사유 문안 |
| 늘 보이는 것 | AI 연결 상태, AI에 보낸 내용의 건수와 기록, 끝낼 때 결과 지우기 켜기·끄기, 작업 기록 |
| 자가 점검 | 무작위 표시값을 심은 가상 CSV로 끝까지 돌려 7개 항목 판정 |

## 4. 실행 결과

### 예시 행사

가파도청보리축제(대정읍, 2024년 4월 6일~28일)를 2026년 11월 16일 실제 AI로 실행한 결과입니다. 카드 숫자는 센터 명세서 구조를 따른 가상 데이터입니다.

| 항목 | 결과 |
|---|---|
| 장소 | AI 짐작 대정읍(가파도). 가파도는 대정읍 가파리에 속한 섬이라 카드와 유동인구가 대정읍으로 집계된다 |
| 조회 | 대정읍, 1순위 후보 성산읍, 2순위 후보 한경면의 날짜별 방문 곡선 3번 |
| 검사 | 방문 판단 1번, 계산 계획 2번 돌려보낸 뒤 통과 |
| 방문 판단 | 증가 약함. 행사 기간 대정읍 방문 +20.7%, 비교 읍면들 +13.6%(실제 공개 데이터) |
| 뺀 후보 | 한경면. 행사 마지막 날 고산리 유적에서 열린 선사 축제 |
| 업종 묶음 | 관광 소비 전체(24개 업종) |
| 결과 | 대정읍의 관광 소비가 성산읍보다 20.5% 더 늘었다. p값 0.062, 행사 없던 15개 달 가운데 이번보다 큰 차이 0번 |
| 결과물 | 보고서 PDF 1개, 그림 png 2장, 활용 사유 문안 |

### 시험 행사 5개의 AI 단계 측정 (2026년 11월 16일)

가파도청보리축제, 2025 보롬왓 튤립축제, 마노르블랑 봄에 꽃향기축제, 혼인지 수국 축제, 2024 자청비 와흘메밀문화제를 각 3번 실행했습니다.

| 항목 | 결과 |
|---|---|
| 계획이 끝까지 세워짐 | 15회 중 13회. 실패 2회는 와흘에서 난 API 연결 오류와 응답 시간 초과였고, 와흘만 3회 더 돌려 모두 통과 |
| 조회 도구를 쓴 실행 | 정상 실행 13회 모두, 실행당 평균 2.2번 |
| 돌려보낸 횟수(정상 13회) | 0번 8회, 1번 5회. 이유는 모두 크기 표현이나 빠진 빈칸 |
| 같은 행사 3회의 방문 판단이 같음 | 3회 모두 정상 실행된 4개 행사 모두 |
| 같은 행사의 업종 묶음이 같음 | 5개 행사 모두(와흘은 추가 실행 포함 4회) |
| 같은 행사 3회의 남긴 비교 후보가 같음 | 4개 행사 중 1개 |
| 같은 행사 3회의 가상 데이터 결론이 같음 | 4개 행사 모두 |
| 호출, 비용, 시간 | 실행당 호출 3~4번, 0.009달러, 27~56초(평균 41초) |

전날(11/15) 같은 측정에서는 15회 모두 통과했지만 돌려보낸 횟수가 0번 3회, 1번 8회, 2번 4회였습니다. 같은 시기 행사 이름의 숫자 조각이 날짜를 깨뜨리는 검사기 오탐이 섞여 있어 고친 뒤 다시 측정했습니다. 네트워크가 멈춘 두 번은 510초와 362초를 기다렸는데, 이후 외부 호출에 벽시계 시간 제한(연결 5초, 응답 60초)을 넣어 넘기면 끊고 대체 경로로 넘어가게 했습니다.

같은 시험을 Sonnet 5.5로 5회 돌리면 모두 통과했지만 실행당 0.199달러로 Haiku 5.5(0.0132달러)의 15배여서 Haiku 5.5를 씁니다.

## 5. 검증 방법과 한계

### 계산 검증: 가상 데이터 두 판

시험 행사의 행사 달에 효과를 심은 판과 심지 않은 판을 만들어, 비교 후보는 규칙 순위 그대로 두고 업종 묶음 두 가지로 계산했습니다(2026년 11월 16일).

| 시험 행사 | 업종 묶음 | 효과를 심은 판 | 심지 않은 판 |
|---|---|---|---|
| 가파도청보리축제 | 관광 소비 전체 | 더 늘었다 +20.5%, p 0.062 | 평소 수준 −7.4%, p 0.25 |
| 가파도청보리축제 | 먹거리·음료 중심 | 더 늘었다 +31.3%, p 0.062 | 평소 수준 +0.9%, p 0.81 |
| 혼인지 수국 축제 | 관광 소비 전체 | 더 늘었다 +13.4%, p 0.067 | 평소 수준 −5.9%, p 0.33 |
| 혼인지 수국 축제 | 먹거리·음료 중심 | 더 늘었다 +11.1%, p 0.067 | 덜 늘었다 −7.5%, p 0.067 |
| 와흘메밀문화제 | 관광 소비 전체 | 더 늘었다 +19.5%, p 0.056 | 평소 수준 −0.2%, p 0.94 |
| 와흘메밀문화제 | 먹거리·음료 중심 | 더 늘었다 +14.9%, p 0.056 | 평소 수준 −4.1%, p 0.33 |
| 보롬왓 튤립축제, 마노르블랑 꽃향기축제 | 두 묶음 | 계산 불가 | 계산 불가 |

효과를 심은 판은 6개 조합 모두 잡았고, 심지 않은 판은 6개 가운데 1개가 "덜 늘었다"로 잘못 나왔습니다. 행사 없던 달이 14개라 p값의 최솟값이 0.067이고, 우연히 이런 결과가 나올 확률이 약 7%인 것과 맞는 크기입니다. 보롬왓과 마노르블랑은 같은 장소 축제가 이어져 행사 없던 달이 8개뿐이라 계산하지 않았습니다(기준 9개).

### 자동 시험과 윈도우 시험

- 자동 시험 74개: 계산, 센터 CSV의 이상 형식(겹치는 달, 중복 행, 다시 저장해 바뀐 인코딩, NA), 10 미만 처리, 숫자 근거 대조, 계획 검사, 리허설, 자가 점검, 결과 삭제.
- 윈도우 시험: 제출할 묶음을 그대로 만들어 윈도우 서버에서 install.bat, run.bat, 예시 경로, PDF와 맑은 고딕, 결과 삭제, 자가 점검까지 44항목을 돌립니다. C 드라이브 바로 아래와, 한글과 공백이 든 바탕 화면 폴더 두 곳에서 모두 통과했습니다.

### 한계

- 이 방법은 비교일 뿐 인과를 증명하지 않습니다. 같은 시기 행사 읍면에만 생긴 다른 일은 가려내지 못합니다.
- 검증은 가상 데이터로만 했습니다. 실제 카드 데이터에서 효과 크기와 계산 불가 비율은 다를 수 있습니다.
- 행사 전 흐름 값은 3개월 평균이라 한 달짜리 가짜 값으로 구한 평소 흔들림보다 덜 흔들립니다. 그래서 이 확인은 통과하기 쉬운 쪽으로 기울어 있습니다.
- 같은 장소에서 축제가 이어지는 곳은 평소 흔들림을 계산할 달이 모자라 계산하지 못합니다. 시험 행사 5개 중 2개가 그랬습니다.
- 읍면 12곳만 다룹니다. 동 지역은 법정동과 행정동을 맞출 수 없어 뺐습니다.
- 같은 시기 행사 제외는 행사 파일에 있는 행사만 봅니다. 장소는 AI가 이름으로 짐작한 값이라 틀릴 수 있습니다. 무작위 30건 가운데 공개 자료로 장소를 확인한 25건에서 20건이 맞았고(80%), 시험 행사 5개는 3개가 맞았습니다. 그래서 장소 확인 화면에서 사람이 고칩니다.
- 같은 행사를 다시 실행하면 AI가 남기는 비교 후보가 달라질 수 있습니다(3회 실행에서 4개 행사 중 1개만 같음). 비교 순서와 교체는 코드가 정해 측정에서는 결론이 바뀌지 않았습니다.

## 6. 센터 활용 방안

- **결과보고서와 예산 자료.** 보고서 PDF를 반출 승인 뒤 그대로 붙입니다. 문장은 비교 읍면 대비 차이까지만 쓰므로 인용해도 과장이 되지 않습니다.
- **축제 사이 비교.** 같은 방식으로 여러 축제를 계산하면 상대 효과와 p값을 같은 잣대로 놓고 볼 수 있습니다.
- **반출 신청.** 센터 문형("(툴)으로 분석 후 (가공)으로 가공하여 (내용)의 보고서 작성 및 (어디)에 활용")을 채운 활용 사유를 화면에서 복사합니다. 결과 폴더에는 png와 pdf만 만들고, 원래 금액·건수·인원은 어디에도 없습니다.
