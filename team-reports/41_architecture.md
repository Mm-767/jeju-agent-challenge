# 41. 시스템 아키텍처: 「행사 효과 나란히」의 모듈 경계와 인터페이스

작성: 시스템 아키텍트, 2026-11-13. 근거는 40_plan_brief.md, 30_pm_decision.md, 22_tech_lead.md, 14_ai_engineer.md, 23_product_designer.md(5·6절), 16_compliance_officer.md(1-13절, 4절), 00_brief.md(일부), app/ 아래 코드 직접 확인, Anthropic API 참고 문서(claude-api 스킬에 들어 있는 2026-11-03 기준 자료)다. 웹 검색은 하지 않았다. 확인하지 않은 기술 사실은 "추정" 또는 "기억 기반"으로 표시했다. 코드는 만들거나 고치지 않았다.

## 결론 5줄

1. 구조의 뼈대는 "공개 단계에서 계획을 끝내고, 센터 단계에서는 로컬 코드가 계산만 한다"는 두 구간 분리다. LLM 호출은 개최 읍면 제안과 분석 계획 작성 두 곳뿐이고 둘 다 센터 CSV를 불러오기 전에 끝나며, CSV를 불러오는 순간 유일한 외부 통신 모듈(outbound.py)이 잠긴다.
2. 분석 한 건을 서버 메모리의 작업 객체 하나로 다루고, 진행 상황(계획, 리허설, 재시도 기록)은 1초 간격 폴링으로 화면에 준다. 이 방식은 추천이며 사용자 결정이 필요하다. 엔드포인트는 정적 파일을 빼고 12개다.
3. 디스크에는 out/report(PDF·png)와 out/work(외부 전송 기록) 두 곳에만 쓴다. 센터 CSV는 원래 폴더에서 한 번 흘려 읽어 읍면 12곳 집계만 메모리에 두고, 결과 삭제는 기본 켜짐이며 확인을 받은 뒤 지운다.
4. 계획 JSON의 형식 강제는 기존 보고서가 적은 "도구 강제 호출" 대신 구조화 출력(output_config.format)으로 해야 한다. 참고 자료상 Sonnet 5.5는 도구 강제 호출을 400 오류로 거절하므로, 기존 방식대로 만들면 Haiku에서 Sonnet으로 모델을 바꾸는 순간 깨진다.
5. 사용자 결정이 필요한 세부 설계는 진행 표시 방식(3-1절), 계산 라이브러리, LLM 호출 방식, PDF 라이브러리, 차트 표시 방식, 센터 CSV 폴더 지정 방식(10절)의 6가지이고, 각각 비교표와 추천을 붙였다.

## 0. 이 문서에서 쓰는 이름

다른 설계자가 같은 말을 쓰도록 처음에 정해 둔다.

- **작업(Run)**: 분석 한 건이다. 행사 선택부터 보고서까지의 상태를 서버 메모리에 담은 객체이고, 서버는 한 번에 하나만 들고 있다.
- **공개 단계**: 행사 확인, 개최 읍면 확정, 비교 읍면 후보, 계획 작성까지다. 공개 데이터(허브 행사 파일, 허브 유동인구 스냅샷, 공개 명세)만 다루고 LLM을 부를 수 있다.
- **센터 단계**: 센터 CSV 불러오기, 계산, 반출 점검, 보고서 생성이다. 외부 통신이 잠긴 상태로만 돈다.
- **잠금**: outbound.py가 모든 외부 호출을 거절하는 상태다. 센터 CSV(예시 가상 CSV 포함)를 읽기 직전에 걸리고, 작업을 버리거나 서버를 다시 켤 때만 풀린다.
- **계획**: LLM이 내는 JSON 한 개다. 비교 읍면 순위, 비교할 달, 업종 범위, 빈칸 문장 틀이 들어 있다.
- **미리 만든 계획**: 개발 중에 LLM으로 만들어 리허설을 통과한 계획을 파일로 저장한 것이다. API 키가 없거나 호출이 실패할 때 쓴다.
- **바탕 칸**: 결과 숫자를 계산하는 데 쓰인 (연월, 읍면, 업종) 단위의 집계 칸이다. 10 미만 검사는 이 칸에 한다.

허브 실시간 호출은 정상 흐름에 넣지 않는다. 분석 기간(2023-08~2026-08)의 유동인구는 스냅샷에 다 들어 있고, 허브는 2026-09부터 0건이라 실시간 호출로 더 얻는 값이 없다(브리핑 3절). 그래서 이번 범위의 외부 통신 지점은 LLM 하나다. "최신 값 받기" 버튼을 남기기로 하면(PM 4-3절 자르는 순서 2번) 그 호출도 outbound.py 안의 함수 하나로만 둔다.

### 1-2. 분석 한 건의 흐름

1. 화면 0에서 사용자가 행사를 고르거나 "예시로 해 보기"를 누른다. 서버가 작업을 만들고, agent.py가 행사 이름과 주관·주최 기관 이름을 보고 개최 읍면을 제안한다. 키가 없으면 이 단계를 건너뛰고 사용자가 읍면 12곳 목록에서 고른다.
2. 화면 1에서 사용자가 개최 읍면과 날짜를 확인한다. 확인 전에는 다음 단계로 가지 않는다.
3. 서버가 hub.py로 행사 읍면과 나머지 11곳의 일별 방문 인구, 유사도 표, 같은 기간에 열린 다른 행사 목록을 만든다. agent.py가 이것을 LLM에 주고 계획을 받는다. plan.py가 형식을 검사하고, calc.py가 동봉한 가상 CSV로 계획을 실제로 돌려 본다(리허설). 오류가 나면 오류 문장을 LLM에 돌려줘 고치게 한다. 모든 과정이 작업 기록에 한 줄씩 쌓이고, 화면은 폴링으로 이를 받아 보여 준다.
4. 화면 1에 비교 읍면 후보와 이유, 제외한 후보와 이유가 나온다. 화면 2에 계획이 요구하는 달 목록으로 만든 "받아 올 센터 파일 체크리스트"가 나온다.
5. 사용자가 센터 CSV 폴더 경로를 넣는다(예시 모드는 동봉 가상 CSV). 서버는 읽기 직전에 outbound.py를 잠그고, card.py가 각 파일의 머리글과 첫 행의 base_year_month만 빠르게 검사해 달별 체크 결과를 돌려준다.
6. 사용자가 "계산하기"를 누르면 card.py가 필요한 달의 파일을 제자리에서 흘려 읽어 읍면 12곳 집계를 메모리에 만든다. calc.py가 계획의 후보 순서대로 10 미만 검사(export.py), 사전 추세 검사, 이중차분, 가짜 시점 검사를 하고, report.py가 빈칸을 채워 png와 PDF를 out/report에 쓴다. 이 단계에는 LLM 호출이 없다.
7. 화면 4에서 PDF·png, 반출 배지, 활용 사유 문안이 나온다. "끝내기"를 누르면 지울 파일 목록을 보여 주고 확인을 받은 뒤 지우고, 메모리의 작업과 센터 집계를 버리고, 잠금을 푼다.

### 1-3. 모듈 경계 규칙

다른 설계자가 코드를 나눠 쓸 때 어기면 안 되는 규칙이다. QA가 grep 한 줄로 검사할 수 있게 일부러 단순하게 정했다.

1. 네트워크를 여는 코드는 outbound.py에만 있다. 다른 파일은 anthropic, urllib.request, httpx, socket을 import하지 않는다. 개발용 tools/는 예외다(런타임에서 import하지 않는다).
2. agent.py의 함수는 공개 자료형(행사, 개최 읍면, 유동인구, 유사도 표, 공개 명세, 가상 데이터 리허설 결과)만 인자로 받는다. 센터 집계(CardTable)와 실행 결과(Result)를 받는 함수는 agent.py에 만들지 않는다.
3. card.py가 만든 CardTable은 calc.py, export.py, report.py로만 간다. API 응답, 작업 기록, 파일에 CardTable 원본을 넣지 않는다.
4. outbound.py는 잠긴 동안 어떤 호출도 보내지 않고, 보내려던 시도를 "막힘"으로 전송 기록에 남긴다.
5. 디스크 쓰기는 out/ 아래로만 한다. 경로는 config.py의 상수로만 만든다.

### 2-1. 최종 형태

```

  outbound.py            유일한 외부 통신: call_llm, 잠금, 전송 기록
  hub.py                 허브 스냅샷 읽기(행사, 유동인구), 유사도 표
  agent.py               개최 읍면 제안, 계획 작성·검사·리허설·재시도 고리
  plan.py                계획 JSON 형식(스키마), 검사, 필요한 달 목록
  card.py                센터 CSV 폴더 검사, 흘려 읽기 집계

  static/                화면(화면 설계자가 파일 구성을 정한다)

  assets/NanumGothic.ttf 차트·PDF용 글꼴(라이선스는 보안·컴플라이언스 설계자 확인)
  data/

    dummy/card_effect/   효과를 심은 가상 카드 CSV 37개월
    dummy/card_none/     효과를 심지 않은 판
    dummy/card_marker/   자가 점검용 표시값 판(새로 만듦)
    presets/{행사ID}.json 미리 만든 계획(개최 읍면 + 계획)
  tools/                 개발용. 런타임에서 import하지 않는다
    build_spec.py
    make_dummy_card.py
    fetch_population.py
    (AI 설계자가 만들) 계획 통과율 측정 스크립트. 통과한 계획을 data/presets에 저장한다
  tests/                 QA 설계자가 정한다
  out/                   실행 중 생성물만. 제출 ZIP에는 빈 폴더로도 넣지 않는다(서버가 시작할 때 만든다)
    report/
    work/
  requirements.txt
  .env.example           빈 값의 키 예시(제출 ZIP용)
  .env                   실제 키. 제출 ZIP에 넣지 않는다
```

파일이 10개인 이유는 설계자 경계에 맞추기 위해서다. plan.py는 AI 설계자(계획을 만드는 쪽)와 분석 설계자(계획을 읽는 쪽) 사이의 약속이고, export.py는 보안·컴플라이언스 설계자가 규칙을 정하는 곳이라 따로 뒀다. 그 밖의 공통 유틸 파일, 기반 클래스, 인터페이스 계층은 만들지 않는다.

### 2-2. 이미 만든 파일의 판단

| 파일 | 판단 | 이유 |
|---|---|---|

| spec/card_v02.json | 유지 | 런타임의 컬럼 순서, 코드값, 읍면 12곳 목록의 기준이다. card.py, plan.py, agent.py가 읽는다 |

## 3. FastAPI 엔드포인트

### 3-1. 작업 단위와 진행 표시 방식 (사용자 결정 필요)

오래 걸리는 단계는 계획 작성이다. LLM 호출 한 번에 몇 초에서 수십 초, 재시도까지 하면 1분 안팎이 걸릴 수 있다(추정). 그 동안 계획, 검사, 리허설, 재시도 기록이 화면에 한 줄씩 나와야 "AI가 일하는 장면"이 된다.

| 기준 | A. 작업 없이 동기 응답 | B. 작업 객체와 폴링 | C. 작업 객체와 서버 전송 이벤트(SSE) |
|---|---|---|---|
| 진행 표시 | 끝날 때 기록이 한꺼번에 나온다 | 1초 간격으로 쌓인다 | 생기는 즉시 나온다 |
| 서버 코드 | 가장 적다. 단계마다 요청 한 번 | 단계를 백그라운드로 돌리고, 작업 조회 엔드포인트 하나를 더한다 | B에 더해 기록을 흘려보내는 스트리밍 응답과 대기열이 필요하다 |
| 화면 코드 | fetch 한 번 | 상태가 "진행 중"인 동안 1초마다 다시 조회 | EventSource, 끊겼다 다시 붙을 때 중복 처리 |
| 실패 모드 | 요청 하나가 1분 가까이 열려 있다. 새로고침하면 진행 중인 결과를 잃는다 | 거의 없다. 새로고침해도 작업 번호로 다시 조회한다 | 연결 끊김과 재연결. 백신이나 DLP가 스트림을 모아 두었다 한꺼번에 보낼 가능성(추정, 127.0.0.1이라 낮을 것으로 봄) |
| 시험 | curl 한 번 | curl 두 번 | 스트림을 받는 별도 옵션 필요 |
| 기획서 캡처 | 같다 | 같다 | 같다 |

추천은 **B(작업 객체와 폴링)**다. 진행 장면을 살리면서 서버 쪽 추가는 조회 엔드포인트 하나이고, 실패 모드가 가장 적다. 1초 늦게 보이는 것은 시연에 영향이 없다. A는 가장 단순하지만 평가자가 1분 가까이 아무 변화 없는 화면을 보게 된다. C는 B보다 얻는 것(1초 미만의 즉시성)에 비해 끊김 처리가 늘어난다. 고른 뒤 ADR로 남긴다.

아래 3-2~3-5절은 B를 전제로 썼다. A로 가면 백그라운드 단계가 동기 응답으로 바뀌고 `GET /api/runs/{id}`만 빠진다.

### 3-2. 작업 상태

서버는 작업을 하나만 들고 있다. 새 작업을 만들면 이전 작업과 그 센터 집계를 메모리에서 버리고 잠금을 푼다. 센터 값이 메모리에 없으면 샐 값도 없기 때문이다. 진행 중인 단계가 있으면 새 작업 만들기를 409로 거절한다.

| 단계(step) | 상태(state) | 이때 일어나는 일 | 다음으로 가는 호출 |
|---|---|---|---|
| venue | working | LLM이 개최 읍면을 제안 중 | 자동으로 waiting_user가 된다 |
| venue | waiting_user | 제안(노란색)을 보여 주고 확인을 기다림 | `POST /api/runs/{id}/venue` |
| plan | working | 유사도 표, 계획 작성, 검사, 리허설, 재시도 | 자동 |
| plan | waiting_user | 비교 후보와 체크리스트 표시 | `POST /api/runs/{id}/card` |
| card | waiting_user | 파일 검사 결과 표시(빠진 달은 빨간 글씨) | `POST /api/runs/{id}/execute`, 또는 다른 폴더로 `card` 다시 호출 |
| result | working | 집계, 계산, 반출 점검, png, PDF | 자동 |
| result | done | 결과와 저장 화면 | 새 작업 또는 `POST /api/cleanup` |
| 아무 단계 | error | 그 단계에서 멈춘 이유와 할 일 표시 | 새 작업 |

### 3-4. 요청·응답 필드

모든 날짜는 "YYYY-MM-DD", 연월은 "YYYYMM" 문자열이다. 금액은 원, 인원은 명, 건수는 건, 증가율은 퍼센트, 차이는 퍼센트포인트다.

**GET /api/status**
```json
{
  "mode": "public",                    // "public"(공개 데이터 모드) | "center_locked"(센터 데이터 모드, 외부 AI 연결 잠김)
  "llm": {"available": true, "model": "claude-haiku-5-5", "reason": null},  // 키가 없으면 available=false, reason="API 키가 없습니다"
  "hub_snapshot": {"first": "2023-08-01", "last": "2026-08-31", "collected": "2026-11-13"},
  "delete_on_finish": true,
  "transmissions": {"sent": 4, "blocked": 0, "center_data": 0},
  "leftover_files": 0,                 // 지난 실행에서 남은 out/ 파일 수. 0이 아니면 화면이 "남은 파일 지우기"를 권한다
  "run_id": "r7f3a"                    // 지금 들고 있는 작업. 없으면 null
}
```

**GET /api/events**
```json
{
  "events": [
    {"id": "ev0123", "name": "휴애리 유럽 수국축제", "start": "2024-07-19", "end": "2024-09-15",
     "days": 59, "organizer": "...", "host": "...", "sponsor": "...", "preset": true}
  ]
}
```
`preset`은 미리 만든 계획이 있는 행사(시험 행사)인지다. 키가 없을 때 화면이 이 행사들만 고를 수 있게 하는 데 쓴다.

**POST /api/runs**
요청: `{"event_id": "ev0123", "example": "effect"}`. `example`은 `null`(실제 센터 파일을 넣을 작업), `"effect"`, `"none"` 중 하나이고, 예시 모드에서는 화면 2에서 해당 가상 CSV가 자동으로 들어간다.
응답: `{"run_id": "r7f3a"}`. 진행 중인 단계가 있으면 409.

**GET /api/runs/{id}?since=12**
```json
{
  "run_id": "r7f3a",
  "example": "effect",
  "state": "working",
  "step": "plan",
  "log": [ {"t": "14:03:22", "actor": "ai", "kind": "plan", "text": "같은 달 구좌 당근축제가 열린 구좌읍은 비교 후보에서 뺐습니다."} ],
  "log_total": 15,                     // since 번째 이후 기록만 log에 담는다
  "event": { "...": "Event" },
  "venue": { "...": "Venue" },
  "plan_view": {                       // 계획 중 화면에 보일 부분. plan 원문도 함께 준다
    "source": "llm",                   // "llm" | "preset"
    "visit_check": {"increased": true, "reason": "..."},
    "controls": [{"emd": "표선면", "rank": 1, "reason": "..."}],
    "excluded": [{"emd": "구좌읍", "reason": "..."}],
    "required_months": ["202307", "202401", "..."],
    "attempts": 2
  },
  "charts": {"population": "/out/report/r7f3a_population.png"},
  "card_check": { "...": "CardCheck" },
  "result": { "...": "Result" },
  "report": { "...": "Report, 파일은 /out/report/ 주소로" },
  "selfcheck": null,
  "error": null                        // {"code", "message", "action"}
}
```
`since`를 빼면 기록 전체를 준다. 다른 필드는 작아서 매번 전부 준다. 작업 번호가 지금 들고 있는 작업이 아니면 404 `{"code": "run_gone"}`를 준다(옛 탭이 조회하는 경우).

**POST /api/runs/{id}/venue**
요청: `{"emd": "남원읍", "start": "2024-07-19", "end": "2024-09-15"}`. `emd`는 읍면 12곳 중 하나여야 한다. 동 지역 행사는 화면에서 "이번 범위에서는 분석할 수 없습니다"로 멈추고 이 호출을 하지 않는다.
응답: `{"ok": true}`. 검사에 실패하면 400 오류 응답(3-5절).

**POST /api/runs/{id}/card**
요청: `{"folder": "C:\\Users\\...\\Desktop\\요청파일"}` 또는 `{"example": true}`. 경로 앞뒤의 따옴표와 공백은 서버가 지운다(탐색기의 "경로로 복사"가 따옴표를 붙인다).
응답: CardCheck(4절). 이 호출 직전에 잠금이 걸리므로, 응답을 받은 뒤 `/api/status`의 mode는 `"center_locked"`다.

**POST /api/runs/{id}/execute**
요청 본문 없음. 응답 `{"ok": true}`. card_check.ok가 거짓이면 409. 필요한 달 중 일부만 빠진 경우의 진행 여부는 분석 설계자가 정한다(행사 달이 빠지면 진행 불가가 기본).

**GET /api/transmissions**
```json
{"records": [
  {"t": "2026-11-13T14:03:20", "host": "api.anthropic.com", "purpose": "plan", "attempt": 1,
   "request": "{...보낸 본문 전문...}", "response": "{...받은 본문 전문...}",
   "blocked": false, "block_reason": null}
]}
```
요청 머리글(API 키가 들어 있음)은 기록하지 않는다. 본문만 기록한다.

**POST /api/selfcheck**
응답 `{"run_id": "..."}`. 끝나면 작업의 `selfcheck`에 `{"passed": true, "markers_found": 0, "calls_checked": 3, "blocked_after_lock": true}`가 담긴다. 표시값 판 생성 방식과 판정 규칙은 QA·보안 설계자가 정한다.

**GET /api/cleanup**
```json
{"delete_on_finish": true,
 "files": [{"path": "out/report/r7f3a_report.pdf", "kind": "report", "bytes": 182344},
           {"path": "out/work/transmissions.jsonl", "kind": "work", "bytes": 40211}],
 "memory": {"run": true, "center_data": true}}
```

**POST /api/cleanup**
요청: `{"include_reports": false}`. 결과 삭제가 켜져 있으면 out/work 전부와(include_reports가 참이면) out/report 전부를 지운다. 꺼져 있으면 파일은 두고 메모리만 비운다. 어느 쪽이든 작업과 센터 집계를 버리고 잠금을 푼다.
응답: `{"deleted": ["..."], "failed": [{"path": "...", "reason": "다른 프로그램이 파일을 열고 있습니다"}], "mode": "public"}`.

**POST /api/settings**
요청: `{"delete_on_finish": false}`. 응답: `/api/status`와 같다. 이 설정은 메모리에만 두고 서버를 켤 때마다 켜짐으로 돌아간다.

### 3-5. 오류 응답 형식

동기 호출의 오류는 HTTP 400 또는 409와 아래 본문이다. 백그라운드 단계의 오류는 작업의 `state="error"`와 같은 모양의 `error` 필드다.

```json
{"code": "card_header_mismatch",
 "message": "이 파일은 카드 이용 현황(읍면동)_v02 형식이 아닙니다.",
 "action": "센터 조회 화면에서 받은 Results_로 시작하는 CSV를 넣어 주세요."}
```

원인 한 문장과 할 일 한 문장이다(23번 5-1절). 메시지에는 파일 이름, 컬럼 이름, 개수만 넣고 센터 CSV의 셀 값은 넣지 않는다.

## 4. 핵심 데이터 구조

내부 자료형은 표준 라이브러리 dataclass로 쓰고, API 응답은 dataclasses.asdict로 바꿔 보낸다. 요청 본문은 FastAPI가 이미 쓰는 pydantic 모델로 받아 신뢰 경계에서 검사한다. 필드 이름은 다른 설계자가 바꿔도 되지만, 바꾸면 이 표를 함께 고친다.

### 4-1. 행사와 개최 읍면

```python
@dataclass
class Event:                  # 허브 행사 파일 한 줄. 공개 데이터
    id: str                   # "ev0123". 원본 파일의 행 번호. 스냅샷 파일이 바뀌지 않는 한 고정
    name: str                 # 콘텐츠명
    start: date               # 시작일
    end: date                 # 종료일
    organizer: str            # 주관(없으면 빈 문자열)
    host: str                 # 주최
    sponsor: str              # 후원

@dataclass
class Venue:                  # 개최 읍면 후보와 확정값
    emd: str | None           # 읍면 12곳 중 하나. 동 지역이거나 판단할 수 없으면 None
    kind: str                 # "eup_myeon" | "dong" | "unknown"
    reason: str               # 판단 근거 한 문장. 어떤 단어(행사 이름, 주관 기관)를 보고 정했는지
    source: str               # "llm" | "preset" | "user"
    confirmed: bool           # 사용자가 확인했는가. 거짓이면 계획 단계로 가지 않는다
    start: date               # 사용자가 확인한 날짜. 행사 파일 값과 다르게 고칠 수 있다
    end: date
```

### 4-2. 비교 읍면 후보(코드가 계산하는 유사도 표)

```python
@dataclass
class Similarity:             # 행사 읍면을 뺀 11곳 각각. 공개 유동인구로 코드가 계산
    emd: str
    corr: float               # 행사 전 기간 일별 방문 인구(visitPop을 하루 16행 더한 값)의 상관계수, -1~1
    level_ratio: float        # 행사 전 기간 평균 방문 인구의 비(후보 / 행사 읍면), 단위 없음
```

지표 종류와 행사 전 기간의 길이(예: 8주)는 분석 설계자가 정한다. 같은 기간에 다른 행사가 열린 후보를 빼는 판단은 LLM이 한다. 행사 파일에 장소 열이 없어서 코드는 다른 행사가 어느 읍면에서 열렸는지 모르고, LLM이 행사 이름을 보고 판단해야 하기 때문이다(브리핑 3절).

### 4-3. 분석 계획(LLM이 내는 JSON)

```json
{
  "event_emd": "남원읍",
  "visit_check": {"increased": true, "reason": "행사 기간 방문 인구가 행사 전 8주 평균보다 뚜렷이 많습니다."},
  "controls": [
    {"emd": "표선면", "reason": "행사 전 방문 인구 흐름이 가장 비슷합니다."},
    {"emd": "성산읍", "reason": "..."},
    {"emd": "안덕면", "reason": "..."}
  ],
  "excluded": [{"emd": "구좌읍", "reason": "같은 달에 구좌 당근축제가 열렸습니다."}],
  "event_months": ["202407", "202408", "202409"],
  "pre_months": ["202401", "202402", "202403", "202404", "202405", "202406"],
  "placebo_months": ["202403"],
  "biz_codes": [],
  "small_cell_steps": ["merge_biz", "drop_control"],
  "texts": {
    "headline": "행사 달 {{event_emd}}의 관광객 카드 이용 증가율은 비교 읍면보다 {{diff_pp}}퍼센트포인트 {{direction}}.",
    "method": "...",
    "usage_reason": "Python 기반 비교 지역 분석 Agent로 분석 후 증감률 차이로 가공하여 {{event_name}} 지역 소비 효과 결과보고서 작성 및 {{use_place}}에 활용."
  }
}
```

| 필드 | 뜻 | 검사(plan.validate) |
|---|---|---|
| event_emd | 확정한 개최 읍면 | 사용자가 확인한 값과 같아야 한다 |
| visit_check | 공개 유동인구로 본 방문 증가 판단과 이유 | increased가 거짓이면 화면이 "효과를 찾기 어려운 행사"라고 먼저 알리고 계속할지 묻는다 |
| controls | 비교 읍면 1~3순위와 이유. 배열 순서가 곧 교체 순서다 | 읍면 12곳 안, 행사 읍면 아님, 중복 없음. 2곳 미만이면 계획은 유효하지만 작업이 "비교할 수 있는 읍면이 부족합니다"로 끝난다(PM 2-1절 위험 3) |
| excluded | 뺀 후보와 이유 | controls와 겹치지 않음 |
| event_months | 행사 달 | 카드 데이터 범위(202308~202608) 안 |
| pre_months | 행사 전 비교 기간(사전 추세 검사에도 씀) | 범위 안, 행사 달보다 앞 |
| placebo_months | 가짜 시점 검사에 쓸 행사 없는 달 | 범위 안, 행사 달과 겹치지 않음 |
| biz_codes | 업종 범위. 빈 배열이면 전체 업종 | 명세의 업종 42개 안 |
| small_cell_steps | 10 미만 칸이 생기면 적용할 순서 | 허용 값은 "merge_biz"(세부 업종을 묶음), "drop_control"(그 후보를 뺌) 두 가지뿐이다 |
| texts | 빈칸이 든 문장 틀 | 빈칸 이름이 허용 목록 안. 빈칸 밖에 숫자가 있으면 그 문장을 버린다(14번 4-2절) |

정해 두는 것과 맡기는 것:

- 관광객 구분(tour_type이 개별·단체)과 지표의 기본값(이용 금액)은 계획 필드로 두지 않고 코드에 고정한다. LLM이 틀릴 수 있는 자리를 줄이기 위해서다. 바꾸려면 분석 설계자가 필드를 더한다.
- 달 목록의 뜻(전년 같은 달을 쓸지, 행사 전 몇 달을 쓸지)과 이중차분 식은 분석 설계자가 확정한다. 위 필드 이름은 초안이다. 주의할 사실 하나: 카드 데이터가 2023년 8월부터라서 2024년 7월 이전 행사는 전년 같은 달이 없다(브리핑 3절의 수록 기간에서 나온 계산).
- 빈칸 이름 허용 목록은 report.py가 갖고, 숫자 빈칸(diff_pp 등)은 분석 설계자가 calc.py 결과의 numbers 키와 맞춰 정한다. 방향 단어(높았습니다, 낮았습니다)도 코드가 채운다.
- 필요한 달 목록(체크리스트)은 `plan.required_months(plan)`이 event_months, pre_months, placebo_months와 분석 설계자가 정한 추가 달을 합쳐 만든다.

### 4-4. 계획 작성 결과

```python
@dataclass
class PlanOutcome:
    plan: dict | None         # 검사와 리허설을 통과한 계획. 실패하면 None
    source: str               # "llm" | "preset"
    attempts: int             # 계획 작성 LLM 호출 횟수(첫 작성 포함)
    passed: bool
    failure: str | None       # 실패 이유 한 문장(사용자용)
```

"최대 3회"의 뜻이 자료마다 다르다. PM 2-1절은 "오류가 나면 최대 3회 고친다"(호출 최대 4번), 3-2절 통과 기준은 "3회 안에 통과"(호출 최대 3번)다. 이 문서는 호출 합계 최대 3번으로 적었고, AI 설계자가 확정한다.

### 4-5. 센터 CSV 검사와 집계

```python
@dataclass
class CardFile:               # 폴더 안 CSV 한 개의 빠른 검사 결과
    name: str                 # "Results_20261113_090000.csv"
    month: str | None         # 첫 데이터 행의 base_year_month. 파일 이름의 날짜는 다운로드 시각이라 쓰지 않는다
    ok: bool
    problem: str | None       # 문제가 있으면 사용자용 한 문장(값 없이)

@dataclass
class CardCheck:
    folder: str
    files: list[CardFile]
    needed: list[str]         # 계획이 요구한 연월
    missing: list[str]        # needed 중 없는 달
    duplicates: list[str]     # 같은 달 파일이 두 개 이상인 달
    ok: bool                  # 형식 오류 파일과 중복이 없고, 계산에 꼭 필요한 달이 모두 있으면 참

@dataclass
class CardTable:              # 센터 집계. 메모리에만 있고 calc·export·report로만 간다
    cells: dict[tuple[str, str, str, str], tuple[int, int, int]]
        # (연월, 읍면, 업종코드, 관광 구분) 를 열쇠로 (이용자 수 명, 이용 건수 건, 이용 금액 원) 합계
        # 읍면 12곳 행만 남긴다. 최대 37개월 x 12곳 x 42업종 x 4구분이라 작다
    months: set[str]
    files: list[dict]         # [{"name", "month", "rows", "sha8"}]. 계산 근거표(PDF 끝)에 쓴다
    skipped: dict[str, int]   # {"숫자가 아닌 칸": 3, "다른 달 행": 0}. 개수만, 값은 없음
```

이용자 수를 업종이나 집단에 걸쳐 더하면 같은 사람이 여러 번 셀 수 있다. 결과 지표를 금액·건수 위주로 할지, 이용자 수를 어떻게 쓸지는 분석 설계자가 정한다.

### 4-6. 실행 결과와 반출 점검

```python
@dataclass
class ExportCheck:
    ok: bool                  # 사전 점검 기준을 모두 만족하면 참. 배지 "반출 신청 가능(사전 점검 기준)"
    items: list[dict]         # 조항별 한 줄. [{"rule": "인원·건수 10 미만 칸 처리", "passed": True, "note": "업종을 묶어 해결"}]
    actions: list[str]        # 실제로 한 처리. "업종을 하나로 묶었습니다", "안덕면을 후보에서 뺐습니다"
    cells_checked: int        # 검사한 바탕 칸 수
    cells_under_10: int       # 처리 전 10 미만 칸 수. 처리 뒤 결과에 남은 수는 0이어야 ok

@dataclass
class Result:
    status: str               # "ok" | "no_result"
    reason: str | None        # no_result일 때 사용자용 한 문장
    event_emd: str
    control_emd: str | None   # 최종 비교 읍면
    tried: list[dict]         # 계획 순서대로 [{"emd": "표선면", "outcome": "pretrend_fail" | "small_cells" | "used"}]
    numbers: dict[str, float] # 빈칸 이름과 값. 예: diff_pp(퍼센트포인트), event_growth_pct(%), control_growth_pct(%)
    pretrend: dict            # {"passed": bool, "value": float, "threshold": float}
    placebo: dict | None      # {"passed": bool, "diffs": [{"ym": "202403", "diff_pp": 0.4}]}. 자르는 순서 4번이면 None
    series: dict              # 차트용. {"months": [...], "event": [...], "control": [...]}. 행사 전 평균을 100으로 둔 지수
    warnings: list[str]       # 누락 월, 건너뛴 칸 수
    export: ExportCheck
```

series를 지수로 두는 이유는 그림에 단순집계 값(합계)을 드러내지 않기 위해서다(16번 2-2절의 응용집계 조항). 지수가 응용집계로 인정되는지는 운영진 답을 받지 못했으므로(PM 7절 질문 1) 배지는 "사전 점검 기준"으로만 쓴다.

### 4-7. 보고서

```python
@dataclass
class Report:
    pdf: str | None           # out/report 아래 파일 이름. 자르는 순서 5번이면 None
    pngs: list[str]           # "r7f3a_trend.png"(센터 데이터, 지수), "r7f3a_population.png"(공개 데이터)
    sentences: list[str]      # 빈칸을 채운 문장
    dropped: list[str]        # 틀에 숫자가 있어 버린 문장의 원래 틀
    limits: list[str]         # 고정 한계 문구 4개(PM 4-2절 7번)
    usage_reason: str         # 활용 사유 문안(채운 것)
    application: dict         # 반출 신청 항목. {"title", "description",
                              #   "files": [{"name", "kind": "분석결과", "dataset": "카드 이용 현황(읍면동)_v02"}]}
```

파일 이름은 영문으로 하고 작업 번호를 앞에 붙인다. 반출 신청 때 "낯선 확장자·파일 깨짐" 반려를 피하기 위해서다(00번 반려 사유).

### 4-8. 작업 기록과 외부 전송 기록

```python
@dataclass
class LogEntry:               # 작업 기록 한 줄. 화면에만 보이고 외부로 보내지 않는다
    t: str                    # "14:03:22"
    actor: str                # "ai" | "code" | "user". 누가 판단했는지 화면에서 구분하게 한다
    kind: str                 # "venue" | "plan" | "check" | "rehearsal" | "retry" | "lock"
                              # | "data" | "calc" | "export" | "report" | "warn" | "error"
    text: str                 # 한국어 한 문장
```

외부 전송 기록은 out/work/transmissions.jsonl에 한 줄에 하나씩 쓴다. 필드는 3-4절 `GET /api/transmissions`와 같다.

## 5. 상태와 저장

### 5-1. 서버 메모리에만 두는 것

- 작업 객체(행사, 개최 읍면, 유사도 표, 계획, 작업 기록, 파일 검사 결과, 센터 집계, 결과, 보고서 요약)
- 잠금 상태, 결과 삭제 켜기·끄기 설정(서버를 켤 때마다 켜짐)
- 브라우저 쪽도 화면 상태를 자바스크립트 메모리에만 둔다. localStorage 같은 브라우저 저장소는 쓰지 않는다. 결과 삭제가 브라우저 저장소까지 챙길 필요가 없게 하기 위해서다(16번 1-13절).

서버를 끄면 메모리 상태는 사라진다. 지난 작업을 다시 열거나 이어 하는 기능은 만들지 않는다.

### 5-2. 디스크에 쓰는 것 (out/ 한 폴더)

| 위치 | 내용 | 센터 값 포함 | 삭제 |
|---|---|---|---|
| out/report/{작업}_report.pdf | 보고서 | 응용집계 결과(증가율 차이, 지수)만 | "끝내기"에서 선택(반출 신청을 마친 뒤 지우도록 안내) |
| out/report/{작업}_trend.png | 월별 두 선 그림 | 지수만 | 위와 같다 |
| out/report/{작업}_population.png | 공개 유동인구 그림 | 없음 | 위와 같다 |
| out/work/transmissions.jsonl | 외부 전송 기록 | 없음(설계상) | "끝내기"에서 항상 |

계획 JSON, 작업 기록, 센터 집계는 파일로 쓰지 않는다. 재현 근거는 PDF 끝의 계산 근거표(쓴 파일 이름, 연월, 행 수, 파일 지문 앞 8자리, 조건, 묶기 단계)로 남긴다(PM 4-4절, 23번 5-2절).

out/ 밖에 생기는 것도 적어 둔다. matplotlib은 글꼴 목록 캐시를 만든다(기억 기반). 센터 값은 없지만 위치를 알도록 MPLCONFIGDIR을 앱 폴더 안으로 지정하는 것을 패키징 설계자에게 권한다. Python의 __pycache__에도 데이터는 없다.

### 5-3. 센터 CSV를 디스크에 복사하지 않는 원칙

- 센터 CSV는 사용자가 지정한 폴더에서 제자리로 읽는다. 업로드 엔드포인트를 만들지 않는다. 브라우저 업로드를 받으면 FastAPI(Starlette)가 1MB가 넘는 파일을 임시 파일로 디스크에 내린다(기억 기반). 그러면 우리가 모르는 위치에 센터 데이터 사본이 생긴다.
- 읽을 때는 파일을 한 줄씩 흘려 읽으며 읍면 12곳 행만 집계에 더하고, 원본 행을 메모리에 쌓지 않는다. DuckDB 같은 임시 데이터베이스 파일도 만들지 않는다(10-1절).
- 파일은 "utf-8-sig"로 연다. 명세상 BOM이 없지만 있어도 깨지지 않게 하기 위해서다. 윈도우 기본 인코딩(CP949)으로 열리지 않도록 모든 파일 열기에 인코딩을 적는다(22번 6절).
- 예시 모드의 가상 CSV도 같은 경로로 읽고 같은 잠금을 건다. 시연과 실제가 같은 코드를 지나게 하기 위해서다.

### 5-4. 결과 삭제

1. "끝내기"를 누르면 화면이 `GET /api/cleanup`으로 지울 목록을 받아 보여 준다. 보고서 파일은 "반출 신청을 마쳤으면 함께 지우기" 체크로 따로 고르게 한다.
2. 확인하면 `POST /api/cleanup`이 파일을 지우고, 작업과 센터 집계를 메모리에서 버리고, 잠금을 푼다. 지우지 못한 파일(PDF 뷰어가 열고 있는 경우 등)은 이유와 함께 돌려준다.
3. 결과 삭제가 꺼져 있으면 파일은 남기고 메모리만 비운다. 상단 띠에 "다음에 이어 하려고 남겨 둡니다. 퇴실 시 센터 규칙에 따라 삭제될 수 있습니다"를 띄운다(23번 5-2절).
4. 사용자 확인 없이 지우는 경로는 없다. 서버를 켤 때 out/에 지난 파일이 남아 있으면 지우지 않고 개수만 `/api/status.leftover_files`로 알린다.
5. 브라우저 PDF 뷰어에서 사용자가 직접 "다운로드"를 누르면 파일이 다운로드 폴더로 가서 삭제 대상 밖이 된다. 막을 수 없으므로 매뉴얼과 화면 안내로 다룬다.

## 6. 설정

설정은 앱 폴더의 .env 한 파일과 같은 이름의 환경변수뿐이다. 환경변수가 .env보다 우선한다. config.py가 .env를 직접 읽는다(python-dotenv는 쓰지 않는다. 10줄이면 된다).

| 키 | 기본값 | 없을 때 |
|---|---|---|
| ANTHROPIC_API_KEY | 없음 | 대체 경로로 돈다. 개최 읍면은 사용자가 12곳 목록에서 고르고, 계획은 data/presets의 미리 만든 계획을 쓴다. 미리 만든 계획이 없는 행사는 "AI 연결이 없어 예시 행사만 분석할 수 있습니다"로 멈춘다. 상단 띠와 작업 기록에 "미리 만든 계획"이라고 표시한다 |
| LLM_MODEL | claude-haiku-5-5 | 기본값을 쓴다. 리허설 통과율 측정 때 claude-sonnet-5-5로 바꿔 돌리려고 둔 키다 |
| HUB_PROJECT_KEY | 없음 | 런타임은 스냅샷만 읽으므로 영향이 없다. 개발용 수집기(와 남긴다면 "최신 값 받기")만 쓴다. 제출 ZIP의 .env.example에는 빈칸으로 둔다 |

설정으로 만들지 않고 코드 상수로 두는 것: 주소 127.0.0.1, 포트 8501, 계획 작성 최대 호출 3번, LLM 호출 제한 시간(60초 정도, 추정), 결과 삭제 기본값 켜짐, 폴링 간격 1초. 바뀔 일이 없거나 바뀌면 안 되는 값이다.

미리 만든 계획은 AI 설계자의 통과율 측정 스크립트가 부산물로 저장한다. 측정 때 리허설을 통과한 계획을 `data/presets/{행사ID}.json`(`{"event_id", "venue", "plan", "model", "created"}`)으로 쓰면 대체 경로를 따로 만들 필요가 없다. 적어도 PM 4-1절의 3개(효과 있음, 효과 없음, 1순위 교체 시나리오용)는 있어야 한다.

API 키를 담은 .env는 제출 ZIP에 넣지 않는다. 평가용 키를 어떻게 넣게 할지(매뉴얼에서 .env.example을 복사해 키를 적게 할지)는 패키징 설계자가 정한다.

## 7. 오류 처리 원칙

공통 원칙은 세 가지다. 첫째, 어떤 오류도 흐름 전체를 죽이지 않고 그 단계에서 멈춰 원인과 할 일을 보여 준다. 둘째, 공개 단계는 대체 경로로 내려가고 센터 단계는 결과를 내지 않는 쪽으로 멈춘다. 셋째, 센터 데이터에서 나온 오류 문장은 외부로 가지 않는다. 잠금이 걸린 뒤라 구조적으로 갈 수 없고, 화면 문장에도 셀 값을 넣지 않는다.

| 상황 | 감지 위치 | 처리 | 사용자에게 보이는 것 |
|---|---|---|---|
| 허브 502 | 런타임에는 없음(스냅샷만 읽음). 개발용 수집기에서만 생긴다 | 수집기는 지금처럼 최대 6번 재시도하고 이어받기 한다. "최신 값 받기"를 남기면 3번까지만 시도하고 스냅샷으로 진행한다 | "허브 서버가 응답하지 않아 저장된 자료(기준일 2026-08-31)로 진행합니다" |
| 스냅샷 파일 손상·누락 | hub.py 시작 시 검사 | 서버는 뜨되 행사 선택을 막는다 | "동봉 자료가 없습니다. 압축을 다시 풀어 주세요" |

## 9. 다른 설계자에게 넘기는 인터페이스 약속

함수 이름과 입출력은 이 표를 기준으로 맞춘다. 내부 구현은 각 설계자가 정한다. 시그니처를 바꿔야 하면 이 문서를 고치고 받는 쪽에 알린다.

### 9-1. AI 에이전트 설계자

| 함수 | 입력 | 출력 | 약속 |
|---|---|---|---|
| `agent.propose_venue(event, spec, log)` | Event, 공개 명세 dict, 기록 함수 `log(actor, kind, text)` | Venue(confirmed=False) | LLM이 없거나 실패하면 `Venue(emd=None, source="user")`를 돌려준다. 예외를 밖으로 던지지 않는다 |
| `agent.make_plan(ctx, log)` | PlanContext(아래), 기록 함수 | PlanOutcome | 검사는 `plan.validate`, 리허설은 `calc.rehearse`, 호출은 `outbound.call_llm`만 쓴다. 단계가 진행될 때마다 log를 불러 화면에 실시간으로 보이게 한다 |
| PlanContext | `event: Event`, `venue: Venue`, `daily: dict[읍면, list[(date, int)]]`(공개 일별 방문 인구), `similarity: list[Similarity]`, `overlapping: list[Event]`(같은 기간 행사), `spec: dict` | | 센터 자료형은 들어가지 않는다(1-3절 규칙 2) |
| `outbound.call_llm(purpose, body)` | 용도 문자열("venue", "plan"), Messages API 요청 본문 dict(모델 이름은 config가 채움) | 응답 dict | 잠겨 있으면 `Locked`, 키가 없거나 연결·인증 실패면 `LlmUnavailable(reason)` 예외. 보내기 전에 본문을, 받은 뒤 응답을 전송 기록에 쓴다 |

형식 강제에 관한 사실 하나를 넘긴다. 14번·22번·30번은 "도구 정의의 스키마로 형식을 강제"한다고 적었다. 참고 자료(claude-api 스킬, 2026-11-03 기준)에 따르면 Sonnet 5.5는 `tool_choice`를 `any`나 `tool`로 강제하면 400 오류를 낸다. 대신 구조화 출력(`output_config.format`에 JSON 스키마를 넣는 방식)이나 `strict: true` 도구와 `tool_choice: auto`를 쓰라고 되어 있다. Haiku 5.5는 그 제한 목록에 없지만, 두 모델 모두에서 돌게 하려면 구조화 출력을 쓰는 편이 안전하다. Haiku 5.5에서 구조화 출력이 실제로 되는지는 호출 한 번으로 확인해야 한다(추정). 같은 자료에 따르면 Haiku 5.5는 생각하기(adaptive thinking)가 기본으로 켜져 있고 effort 기본값이 medium이며, 응답 앞부분을 미리 채우는 방식(prefill)은 400 오류다.

## 10. 사용자 결정이 필요한 세부 설계

모두 추천을 적었지만 최종 선택은 사용자가 하고, 고른 직후 ADR로 남긴다. 3-1절의 진행 표시 방식까지 합쳐 6가지다.

### 10-1. 센터 CSV 읽기와 계산 라이브러리

| 기준 | 표준 라이브러리(csv, statistics)로 흘려 읽기 | pandas | DuckDB |
|---|---|---|---|
| 추가 패키지 | 없음 | pandas(numpy는 matplotlib 때문에 어차피 들어온다) | duckdb 바이너리 |
| 메모리 | 읍면 12곳 집계만 남아 작다 | 필요한 달을 통째로 올린다. 실제 센터 파일 크기를 몰라 위험을 판단할 수 없다 | 작다 |
| 형식 함정 | 모든 값을 문자열로 받으므로 큰따옴표 숫자, 앞자리 0 문제가 없다 | 문자열 형식 지정이 필요하다 | 형식 명시가 필요하다 |
| 오류 문장에 셀 값 | 우리가 쓴 문장만 나온다 | 섞일 수 있다(14번 6절) | 섞인다(22번 6절, 기억 기반) |
| 코드 양 | 집계, 상관계수, 회귀를 직접 쓴다. statistics.correlation과 linear_regression은 Python 3.10부터 있다(기억 기반, 지금 venv는 3.11.9) | 가장 짧다 | SQL로 짧다 |
| 속도 | 센터 파일이 달마다 수십만 행이면 달마다 몇 초(추정) | 빠르다 | 가장 빠르다 |
| 윈도우 함정 | 없다 | 휠 하나 더 | 비영문 경로 문제 기억이 있으나 미확인(22번 6절) |

추천은 **표준 라이브러리**다. 계산이 "읍면 12곳의 달별 합계와 증가율 차이"라 무거운 도구가 필요 없고, 메모리와 오류 문장 두 가지 위험이 구조적으로 사라진다. 분석 설계자가 회귀식이나 검정에 numpy가 필요하다고 판단하면 numpy는 이미 들어와 있으니 그것을 쓴다.

### 10-2. LLM 호출 방식

| 기준 | Anthropic 공식 Python SDK | 표준 라이브러리 urllib로 직접 HTTP |
|---|---|---|
| 추가 패키지 | anthropic과 의존 패키지. 참고 자료상 1.x는 httpx2 위에서 돈다. 윈도우용 컴파일 휠이 더 들어오는지는 추정 | 없음 |
| 재시도 | 연결 오류, 408·409·429·5xx를 기본 2번 자동 재시도(참고 자료) | fetch_population.py의 재시도와 비슷한 코드 10줄 안팎을 직접 쓴다 |
| 오류 구분 | 예외 종류로 구분(RateLimitError 등) | 상태 코드로 직접 구분 |
| 구조화 출력 | 스키마 검증 도우미(messages.parse) | 응답 JSON을 직접 파싱·검증 |
| 공식 지침 | 참고 자료는 Python 프로젝트에 SDK를 기본으로 권하고, 가볍다는 이유만으로 직접 HTTP를 쓰지 말라고 한다 | 사용자가 명시적으로 원할 때 |
| 전송 기록 | 보낼 본문 dict를 그대로 기록하면 된다 | 같다 |

추천은 **공식 SDK**다. 재시도와 오류 구분을 직접 쓰지 않아도 되고 공식 지침과 맞는다. 패키지가 늘어나는 비용은 11/15 윈도우 1차 시험에서 설치가 되는지로 확인한다. 어느 쪽이든 호출 코드는 outbound.py 한 곳에만 있다.

### 10-3. PDF 라이브러리

| 기준 | fpdf2 | matplotlib의 PdfPages(이미 들어오는 패키지) | 브라우저 인쇄로 PDF 저장 |

### 10-4. 차트 표시 방식 (ADR-148에서 미정으로 남은 것)

| 기준 | 서버가 matplotlib으로 png를 만들어 화면에도 그대로 보여 줌 | 화면은 자바스크립트 차트 라이브러리, 보고서는 png |

### 10-6. 센터 CSV 폴더 지정 방식

| 기준 | 경로 입력칸(탐색기 주소창 경로를 붙여 넣음) | 서버가 윈도우 폴더 선택 창(tkinter)을 띄움 | 브라우저 폴더 선택으로 파일을 업로드 |
|---|---|---|---|
| 디스크 사본 | 없음 | 없음 | 생길 수 있다(5-3절, 기억 기반) |

| 코드 | 가장 적다 | 조금 | 업로드를 메모리로만 받도록 직접 다뤄야 해서 가장 많다 |

추천은 **경로 입력칸**이다. 센터 안내의 기본 위치("바탕화면\요청파일", 22번 6절)를 입력칸의 예시 문구로 보여 주면 편의성 차이가 줄어든다. 사본이 생기지 않는다는 원칙을 가장 단순하게 지킨다.

## 11. 열린 문제와 추정

1. **실제 센터 CSV의 크기를 모른다.** 한 달 파일이 몇 행인지에 따라 흘려 읽기 속도가 달라진다. 수십만 행이면 달마다 몇 초로 추정했다. 센터 방문 전에는 확인할 수 없다.
2. **실제 센터 CSV의 bjd 값이 명세 표기("애월읍")와 같은지 확인하지 못했다**(PM 8절 10번). 다르면 card.py의 읍면 이름 대조 한 곳만 고치면 되도록 대조를 한 함수에 모은다.
3. **구조화 출력이 Haiku 5.5에서 되는지는 참고 자료로만 판단했다.** 첫 호출로 확인한다.
4. **SDK와 fpdf2의 윈도우 설치**는 11/15 1차 시험 전까지 확인되지 않는다.
5. **응용집계 해석**(지수와 증가율 차이를 읍면 단위로 반출할 수 있는지)은 운영진 답이 없다(PM 7절 질문 1). 배지는 "사전 점검 기준"으로만 쓴다.
6. **"최대 3회"의 뜻**이 자료마다 다르다(4-4절). AI 설계자가 확정한다.
7. **가상 데이터에 교체 장면이 없다.** 지금 생성기로는 1순위 교체가 거의 일어나지 않는다(코드를 읽고 한 추론). 분석·QA 설계자가 판을 정해야 시연 시나리오 3번이 성립한다.
8. **opentelemetry-api가 왜 들어 있는지**, 외부로 무엇을 보내지 않는지 확인하지 않았다(추정).
9. **허브 스냅샷 수집이 진행 중이다.** 한림읍만 확인했고 12곳이 모두 하루 16행씩 끝까지 받아졌는지는 수집이 끝난 뒤 hub.py 시험으로 확인한다.
