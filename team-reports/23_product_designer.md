# 프로덕트 디자이너 보고서: 후보 8개의 편의성·실용성과 기획서 첫인상

작성: 프로덕트 디자이너(UX·UI 담당), 2026-11-13. 근거는 공용 브리핑(00번), 후보 정리(20번), 사용자 리서처 보고서(11번) 전체, 컴플라이언스 보고서(16번)의 4절 체크리스트와 5절 아이디어, 12·13·14·15번 보고서의 각 후보 출처 아이디어 절이다. 웹 검색은 하지 않았다. 아래 점수는 모두 1절에 적은 팀 자체 기준으로 매긴 예상치이며, 심사위원이 실제로 이 방식으로 채점한다는 근거는 없다(추론).

## 결론 5줄

1. 같은 네 기준(첫 결과까지의 부담, 비전문가가 막힐 위험, 결과물이 손에 남는 형태, 실제 서비스 활용 가능성)으로 편의성·실용성 25점을 예상하면 반출 통과형 보고서(후보 A)가 21점으로 가장 높고, 농산물 시세 브리핑(C)과 버스 수요 진단(E)이 20점, 생활폐기물(F) 19점, 행사 효과 검증(B)과 상권 진단(G) 17점, 기업 데이터(H) 16점, 방문 설계도(D) 15점 순이다.
2. 상호평가에서 기획서 첫 쪽 그림이 눈에 띄는 정도는 행사 효과 검증(B)이 5점으로 가장 높다. "행사 지역과 비교 지역의 두 선이 행사 주간에 벌어지는 그래프" 한 장이 사용자, 불편, 결과, 데이터 경계를 함께 보여 주기 때문이며, 상권 진단(G)은 다른 팀과 그림이 겹칠 가능성이 커서 2점이다(추론).
3. 두 점수 모두에서 다른 후보에게 밀리지 않는 후보는 A, B, C 셋이라 이 셋의 화면 흐름을 그렸다. 내가 권하는 제품은 B의 주제와 첫 쪽 그림 위에 A의 반출 점검·활용 사유 화면을 그대로 얹은 결합안이며, 결합하면 B의 편의성은 18점, 축제 파일의 날짜·장소 컬럼까지 확인되면 20점까지 오를 것으로 본다(추론).
4. 어느 후보를 고르든 첫 화면에 "예시 데이터로 해 보기" 버튼을 두어 심사위원이 클릭 한 번으로 결과까지 가게 하고, 상단 고정 띠에 외부 전송 건수와 결과 삭제 상태를 띄우고, 모든 숫자에 계산식과 원천 파일을 연결하고, 결과물마다 반출 가능 여부 배지를 붙여야 한다.
5. 점수를 크게 흔드는 미확인 사실은 C의 허브 농산물 API 품목·시장·갱신 여부, B의 축제 파일 날짜·장소 컬럼, D의 설계도 파일을 센터 PC에 들일 수 있는지(브리핑상 센터 반입은 CSV만 가능)이며, 확인 결과에 따라 해당 후보 점수를 다시 매겨야 한다.

## 1. 채점 방법

### 1-1. 편의성·실용성 25점을 네 축으로 나눴다 (팀 자체 기준)

| 축 | 배점 | 매기는 법 |
|---|---|---|
| 첫 결과까지의 부담 | 7 | Agent 안 단계: 3단계 이하 4점, 4~5단계 3점, 6단계 이상 2점. Agent 밖 준비: 없음 3점, 센터 조회 1~3회 2점, 4회 이상이거나 여러 종 1점 |
| 비전문가가 막힐 위험 | 6 | 사용자가 스스로 이해하거나 판단해야 하는 낯선 개념·결정의 수: 0~1개 6점, 2개 5점, 3개 4점, 4개 3점, 5개 이상 2점 |
| 결과물이 손에 남는 형태 | 6 | 6점: 반출 신청에 필요한 것(PDF·png와 활용 사유 문안)까지 나오거나, 공개 데이터 또는 원본 반출 가능 등급이라 걸림이 거의 없음. 5점: PDF·png와 반출 기준 처리는 있으나 신청 문안이 없음. 4점: 반출 기준 처리가 원안에 없음 |
| 실제 서비스 활용 가능성 | 6 | 세 항목 2점씩. 반복해서 쓸 상황의 근거(근거 있음 2, 추론뿐 1), 센터에서 쓸 이유와 센터 규칙 적합(2 또는 1), 핵심 데이터의 존재·갱신 확인(확인 2, 일부 미확인 1, 핵심 미확인 0) |

"지금 이용자가 적다"는 어느 축에도 넣지 않았다. "센터에서 쓸 이유"는 이용자 수가 아니라 센터 PC에서 실행할 때 개인 PC보다 나아지는 점이 있는지를 본다.

### 1-2. 단계를 세는 규칙

- 단계는 사용자가 직접 누르거나 입력하는 결정 한 번이다. 확인 버튼 하나도 1단계로 센다. Agent가 혼자 하는 일은 세지 않는다.
- 센터 조회 화면에서 하는 일(데이터 선택, 기간 1개월, 조건, 조회, CSV 다운로드)은 Agent 밖의 일이라 "조회 횟수"로 따로 센다.
- 모든 후보에 같은 수준의 화면 설계(확인 화면은 가능한 한 한 장으로 합침)를 가정하고 셌다.

### 1-3. 평가 환경과 실제 사용의 차이

전문가 평가는 동봉한 가상 CSV로 돌리므로 평가 환경에서는 어느 후보도 센터 조회를 하지 않는다. 그래서 심사위원이 손으로 느끼는 편의성은 설치와 Agent 안 단계에서 갈리고, Agent 밖 부담은 기획서에 적힌 실제 사용 흐름을 읽고 판단한다(추론). 센터 조회가 많은 후보는 기획서에서 Agent가 그 부담을 어떻게 줄이는지(파일명 대신 base_year_month로 월 판별, 누락 월 경고, 요청파일 폴더 안내)를 반드시 보여 줘야 한다.

### 2-1. 후보 A: 반출 통과형 현황보고서 Agent

- 주 사용자와 사용 상황: 분기마다 소비 현황자료를 새 달 데이터로 갱신하는 기관 실무자, 사업계획서에 그림 한 장이 필요한 소상공인(11번 페르소나 B와 A). 센터 분석실에서 CSV를 내려받은 뒤, 퇴실 전에 반출 신청까지 끝내야 하는 시점이다. 퇴실 시 반출 승인 자료 외에는 지워지기 때문이다(브리핑 4절).
- 첫 화면에서 하는 일: 내려받은 Results_*.csv 파일이 든 폴더를 고르고, 보고서 목적을 한 문장으로 쓰거나 예시 목적 하나를 누른다.
- 결과까지 단계: Agent 안 5단계(폴더 선택, 목적 입력, 계획 확인, 결과와 반출 점검 확인, 저장과 활용 사유 복사). Agent 밖은 데이터 1종 3개월 기준 센터 조회 3회와 반출 신청 화면 입력 1회다.
- 비전문가가 막힐 지점: 첫째, A는 어떤 데이터를 어떤 조건으로 받아야 하는지 알려 주지 않아서 사용자가 이미 알고 와야 한다(11번 막힘 1위를 풀지 않음). 둘째, 범주처리 뒤 표가 법정동에서 권역으로 거칠어지면 "내가 원한 표가 아니다"라고 느낄 수 있어 이유를 쉬운 말로 보여 줘야 한다. 셋째, 활용 사유의 "(어디)에 활용" 부분은 사용자만 아는 정보라 한 번은 물어야 한다. 덧붙여 "통과"라는 말을 쓰면 사용자가 승인이 보장된 줄 안다(16번 위험).
- 손에 남는 결과물: 반출 기준에 맞춘 PDF 보고서, png 그림, 반출 신청서에 붙여 넣을 활용 사유 문안(파일이 아니라 센터 반출 화면에 입력하는 글), PDF 안의 조항별 심사 근거표. 처리 전 표와 CSV·엑셀은 반출 불가로 표시하고 센터 안에서만 보게 한다.
- 시연 한 컷: 왼쪽에 10 미만 칸이 주황색으로 칠해진 처리 전 표, 오른쪽에 연령을 10세 단위로 묶어 모든 칸이 10 이상이 된 반출용 표가 나란히 있고, 그 아래 "합계로 되살릴 수 있는 칸 1개를 추가로 가렸습니다"라는 문장과 완성된 활용 사유 문안이 뜨는 장면이다. 반출 반려를 겪어 본 사람은 바로 쓸모를 알아볼 것이다(추론).
- 편의성·실용성 21점: 부담 5점(5단계 3점, 조회 1~3회 2점), 막힘 4점(3개), 결과물 6점, 활용 6점이다. 활용 6점의 근거는 운영진이 밝힌 이용 목적(현황자료·사업계획서)과 모든 이용자가 거치는 반출이라는 반복 상황, 결과 삭제와 외부 전송 0건이 실제로 의미 있는 센터 데이터 처리, 헤더가 확인된 카드 이용 현황(읍면동)_v02다.
- 점수가 바뀌는 조건: 후보 D의 "받을 파일 체크리스트"를 앞에 붙이면 막힘이 하나 줄어 22점이 될 것으로 본다(추론).

### 2-2. 후보 B: 행사·정책 효과 검증 Agent

- 주 사용자와 사용 상황: 행정시·읍면동 축제 담당 공무원과 축제추진위원회 사무국(15번), 지역화폐 담당 공무원(12번의 탐나는전 변형). 행사가 끝난 뒤 결과보고서나 다음 해 예산 요구 자료에 지역 소비 효과를 숫자로 써야 할 때다. 이 사용자들이 지금 효과를 어떤 방식으로 쓰는지는 확인하지 못했다(15번).
- 첫 화면에서 하는 일: 행사 이름을 검색하거나 목록에서 고른다. 정책 시점(예: 적립률이 바뀐 달)을 날짜로 넣는 길도 둔다.
- 결과까지 단계: Agent 안 5단계(행사 선택, 날짜·장소·비교 지역을 한 화면에서 확인, 받을 센터 파일 체크리스트 저장, 폴더 지정, 저장). 원안처럼 날짜 확인과 비교 지역 확인을 따로 두면 6~7단계가 된다. Agent 밖 센터 조회는 행사 달, 전년 같은 달, 행사 전 흐름을 검사할 달을 합쳐 4회 이상이다. 행사 전 몇 달이 필요한지는 계산 설계에 따라 달라진다(추론).
- 비전문가가 막힐 지점: 비교 지역이라는 개념과 "행사 전 흐름이 비슷해야 비교가 된다"는 조건, 축제 파일에 날짜·장소가 없을 때 직접 입력하는 일, 카드 데이터가 월 단위라 며칠짜리 행사 효과가 작게 나오거나 없게 나올 때의 해석이다. 공개 데이터 단계와 센터 데이터 단계가 나뉘어 있어 지금 어느 단계인지도 계속 보여 줘야 한다.
- 손에 남는 결과물: 성과보고서 PDF와 png 그래프. 핵심 숫자가 "비교 지역보다 몇 퍼센트포인트 높았다" 같은 응용집계라 반출이 상대적으로 쉽고(16번이 확인한 응용집계 조항), 공개 유동인구 그래프는 공개 데이터라 제한이 없다. 원안에는 활용 사유 문안이 없다.
- 시연 한 컷: 행사 읍면동(빨간 선)과 비교 읍면동(파란 선)이 행사 전에는 나란히 가다가 행사 주간 띠에서 빨간 선만 솟는 그래프 위에 "비교 지역보다 관광객 카드 이용 증가율이 {{차이}}퍼센트포인트 높았습니다" 한 문장이 있고, 옆 작업 기록에 "1순위 비교 지역은 행사 전 흐름이 달라 2순위로 바꿨습니다"가 찍히는 장면이다.
- 편의성·실용성 17점: 부담 4점(5단계 3점, 조회 4회 이상 1점), 막힘 4점(3개), 결과물 5점(반출 기준 처리는 있으나 신청 문안 없음), 활용 4점(반복 상황은 추론 1점, 센터 데이터를 다루고 규칙과 맞물림 2점, 축제 파일 컬럼 미확인 1점)이다.
- 점수가 바뀌는 조건: A의 반출 점검·활용 사유 화면을 붙이면 결과물 6점이 되어 18점이다. 축제 파일의 날짜·장소가 확인되면 막힘이 하나 줄고 데이터 확인이 1점 올라 20점까지 오를 것으로 본다(추론).

### 2-3. 후보 C: 농산물(월동채소) 시세·출하 브리핑 Agent

- 주 사용자와 사용 상황: 지역농협 경제사업 담당, 작목반장, 농업기술센터 지도사, 농가(12·14·15번). 출하 시기를 논의하는 회의 직전이며, 이 회의가 얼마나 자주 열리는지는 확인하지 못했다(15번). 공개 데이터만 써서 센터 PC와 개인 PC 모두에서 쓸 수 있다.
- 첫 화면에서 하는 일: 품목 버튼(당근, 월동무 등)을 누르거나 "이번 주 당근 출하해도 될까" 같은 질문을 쓴다. 기간은 기본값(최근 4주)으로 둔다.
- 결과까지 단계: Agent 안 2~3단계(품목 선택, 필요하면 기간 바꾸기, 저장). Agent 밖 준비는 없다. 외부 LLM 키는 센터 담당자가 설치 때 환경변수로 넣는다(브리핑 4절).
- 비전문가가 막힐 지점: 이동평균이나 "평소 범위" 같은 용어, 브리핑을 가격 예측으로 오해할 위험(범위를 현황과 과거 비교로 묶어야 함, 12번)이다. 사용자가 부르는 품목 이름과 API의 품종 이름이 다를 때(예: "무"와 "월동무") 찾지 못하는 문제도 생길 수 있다(추론).
- 손에 남는 결과물: 1쪽 PDF 브리핑과 png 차트. 공개 데이터만 쓰므로 10 미만·역산 기준이 걸리지 않고, 개인 PC에서 만들면 반출 절차도 없다. 센터 PC에서 만든 파일을 밖으로 가져가려면 공개 데이터 결과라도 반출 신청은 거쳐야 할 것으로 본다(추론, 확인 필요).
- 시연 한 컷: 품목 버튼 하나를 누르면 가격선, 이동평균 띠, 작년 같은 기간 점선, 한파 일수 표시가 담긴 1쪽 브리핑이 나오고, 작업 기록에 "가격이 평소 범위를 벗어나 그 무렵 기상을 추가로 조회했습니다"가 찍히는 장면이다.
- 편의성·실용성 20점: 부담 7점, 막힘 5점(2개), 결과물 6점, 활용 2점이다. 활용이 낮은 이유는 회의 반복 빈도가 추론뿐이고(1점), 센터 PC에서 실행할 때 개인 PC보다 나아지는 점이 없고(1점), API가 월동채소 품목과 제주 시장을 담는지와 지금도 갱신되는지가 모두 미확인이기 때문이다(0점. 데이터 목록상 수정일 2025-09-12, 14번).
- 점수가 바뀌는 조건: API에 월동채소 품목이 있고 2026년 값이 나오면 활용이 3~4점으로 올라 21~22점이 된다. 품목이 없으면 주제 자체를 바꿔야 한다.

### 2-4. 후보 D: 센터 방문 설계도 Agent

- 주 사용자와 사용 상황: 첫 방문을 앞둔 소상공인(전날 집에서), 연구 설계 단계의 연구자, 지난 분기와 같은 조건으로 다시 받아야 하는 기관 실무자(11번). 집 PC에서 설계 모드를, 센터 PC에서 실행 모드를 쓴다.
- 첫 화면에서 하는 일: 설계 모드에서는 목적 한 문장을 쓰거나 예시 목적 카드를 누른다. 실행 모드에서는 설계도를 열고 CSV 폴더를 고른다.
- 결과까지 단계: 설계 4단계(목적 입력, 되묻는 질문에 답, 설계도 확인, 체크리스트 저장·인쇄)와 실행 3단계(설계도 열기, 폴더 지정, 결과 저장)를 합쳐 7단계이고, 두 번에 나눠서 한다. Agent 밖 조회는 체크리스트 덕분에 헷갈리지 않지만 횟수는 줄지 않는다. 1년 추세를 데이터 1종으로 보려면 12회다(11번).
- 비전문가가 막힐 지점: 첫째, 되묻는 질문(지역 단위, 기간)에 답하는 일. 둘째, 설계도 파일을 집에서 센터로 옮기는 방법이다. 브리핑 4절에 "센터 반입은 CSV만"이라고 되어 있어 설계도 파일 반입과 부딪힐 수 있다. 우회 경로로는 설계 모드를 센터 PC에서 다시 실행하는 방법(외부 LLM에는 목적 문장과 공개 명세만 가므로 규칙상 가능해 보임)과 체크리스트를 종이로 출력해 들고 가는 방법이 있다(추론, 컴플라이언스 확인 필요). 셋째, 누락 월 경고가 뜨면 다시 조회하러 가야 한다.
- 손에 남는 결과물: 집에서는 체크리스트 PDF(공개 정보라 제한 없음), 센터에서는 합친 표·차트·컬럼 한글 설명. 원안(11번 아이디어 1)에는 10 미만 처리와 반출 문안이 없어서, 결과를 그대로 반출 신청하면 반려될 수 있다.
- 시연 한 컷: "읍 지역 카페 창업, 최근 1년 시간대별 손님 흐름" 한 문장이 데이터 이름·기간·조건이 적힌 12줄짜리 조회 체크리스트로 바뀌고, 이어서 인터넷을 끊은 상태에서 CSV 11개가 든 폴더를 넣으면 "2026년 3월 파일이 없습니다" 경고가 뜨는 장면이다.
- 편의성·실용성 15점: 부담 3점(7단계 2점, 조회 다수 1점), 막힘 4점(3개), 결과물 4점, 활용 4점(막힘 1위와 재방문이라는 반복 상황 근거 2점, 설계도 반입 경로 미확인 1점, 명세서 한글 설명의 충실도 미확인 1점)이다.
- 점수가 바뀌는 조건: 실행 모드 결과에 A의 반출 처리를 붙이면 결과물이 6점, 설계도 반입이 확인되면 활용이 5점이 되어 최대 18점이다. 편의성 점수는 낮지만 사용자가 가장 심하게 막히는 지점(무엇을 받을지 모름)을 직접 푸는 유일한 후보라, 다른 후보의 "받을 파일 안내" 화면 부품으로 쓰기를 권한다.

### 2-5. 후보 E: 버스 정류소·노선 수요 진단 Agent

- 주 사용자와 사용 상황: 교통 분야 연구자와 용역 수행 기관이 현황자료를 쓸 때, 도·행정시 교통 담당 공무원이 노선 개편 민원이나 의회 자료를 준비할 때(13번).
- 첫 화면에서 하는 일: 정류소나 노선 이름을 넣거나 "지난달 비 온 날 이 정류소 이용이 얼마나 줄었나" 같은 질문을 쓴다.
- 결과까지 단계: Agent 안 4단계(이름 입력, 비슷한 이름 후보 중 선택, 기간·조건 확인, 저장). Agent 밖 준비는 없다. 센터의 버스 승하차 데이터로 출발·도착 분석까지 하려면 조회와 폴더 지정이 더해진다.
- 비전문가가 막힐 지점: 같은 이름의 정류소나 방향별 정류소 구분(추론), "비 온 날"을 어느 관측소 기준으로 정했는지 이해하는 일이다.
- 손에 남는 결과물: PDF와 png. 허브 공개 데이터 위주이고, 센터 버스 데이터는 원본까지 반출 가능한 등급(13번)이라 반출 걸림이 적다.
- 시연 한 컷: 정류소 이름 하나를 넣으면 지도에 정류소와 가장 가까운 기상관측소가 점으로 찍히고, 비 온 날과 아닌 날의 이용자 막대가 나란히 나오며, 숫자를 누르면 호출한 API와 날짜 목록이 뜨는 장면이다.
- 편의성·실용성 20점: 부담 6점(4단계 3점, 준비 없음 3점), 막힘 5점(2개), 결과물 6점, 활용 3점(반복 상황 추론 1점, 센터에서 쓸 이유는 선택 기능인 승하차 분석뿐 1점, API가 2026년 값을 주는지 미확인이고 확인한 1건의 일일 쿼터가 1000이라 1점)이다.
- 점수가 바뀌는 조건: 허브 API가 최신 날짜 값을 준다는 것이 확인되면 활용이 4점으로 올라 21점이다.

### 2-6. 후보 F: 행정동 생활폐기물 현황·예측 Agent

- 주 사용자와 사용 상황: 제주시·서귀포시 청소행정 담당자, 행정동 주민센터, 환경 분야 연구기관이 수거 계획이나 연구 보고서를 쓸 때(13번).
- 첫 화면에서 하는 일: 행정동을 고르고 질문을 쓴 뒤, 종량제봉투 판매 CSV 폴더를 고른다.
- 결과까지 단계: Agent 안 5단계(행정동과 질문, 받을 파일 안내 확인, 폴더 지정, 결과 확인, 저장). Agent 밖 조회는 3개월이면 3회지만, 여러 해 추이를 보려면 수십 회라 운영자에게 요청하는 경로(바탕화면 "요청파일" 폴더) 안내가 필요하다.
- 비전문가가 막힐 지점: 다음 달 "예상 범위"를 숫자 하나로 오해할 위험, 봉투 판매량은 배출량이 아니라 구매량이라는 점(13번), 허브와 센터의 행정동 이름이 다를 때 맞춰졌는지 확인하는 일이다.
- 손에 남는 결과물: PDF와 png. 종량제봉투 데이터는 원본까지 반출 가능한 등급(13번)이라 반출 걸림이 거의 없다.
- 시연 한 컷: 행정동 하나의 일별 판매 막대와 방문 인구 선, 비 온 날 표시가 이어지다가 오른쪽 끝에서 다음 달 예상 범위가 회색 띠로 펼쳐지는 장면이다.
- 편의성·실용성 19점: 부담 5점(5단계 3점, 조회 1~3회 2점), 막힘 4점(3개), 결과물 6점, 활용 4점(수거 계획의 반복은 추론 1점, 센터 데이터와 규칙 적합 2점, 행정동 이름 일치 미확인 1점)이다.

### 2-7. 후보 G: 상권·관광 소비 진단 Agent

- 주 사용자와 사용 상황: 사업계획서·컨설팅 보고서를 쓰러 오는 기업·기관(13번), 창업 입지를 정하려는 예비창업자(11번 페르소나 A), 내국인 관광 감소 원인을 설명해야 하는 관광정책 담당자(12번 아이디어 2).
- 첫 화면에서 하는 일: 지역·업종·질문을 넣고 CSV 폴더를 고른다.
- 결과까지 단계: Agent 안 5단계. Agent 밖 조회는 카드 이용 현황 시간대·요일·읍면동 v02 세 종을 월마다 받아야 해서 3개월이면 9회다.
- 비전문가가 막힐 지점: 법정동 73개와 행정동 43개가 달라 "우리 동네"가 권역으로 묶이는 이유, 카드 시간대 구간의 시각 경계(명세서에서 못 찾음, 13번), 관광객과 도민 구분 컬럼(user_type, tour_type)의 뜻, 유동인구 값이 하루 시간대별 인구의 합(연인원)이라는 점까지 4개다.
- 손에 남는 결과물: PDF와 png, 범주처리는 원안에 있다. 카드 데이터는 원본 반출이 안 되는 등급이라 묶음이 커질 수 있다. 소상공인은 동네 단위를 원하는데 반출용 표는 권역 단위가 되기 쉬워 결과 만족도가 떨어질 수 있다(추론).
- 시연 한 컷: 권역 지도와 요일·시간대 격자에서 금요일 저녁 칸이 진하게 칠해지고, 같은 권역 저녁 방문 인구 선이 겹쳐지는 장면이다.
- 편의성·실용성 17점: 부담 4점(5단계 3점, 여러 종 조회 1점), 막힘 3점(4개), 결과물 5점, 활용 5점(운영진이 밝힌 사업계획서 목적과 상권분석 매쉬업의 높은 조회수라는 반복 근거 2점, 센터 데이터와 규칙 적합 2점, 시간대 경계와 지역 매핑 미확인 1점)이다.

### 2-8. 후보 H: 기업 데이터 지배기업 보호 Agent

- 주 사용자와 사용 상황: 제주 산업정책 담당자나 기업지원기관 연구원이 사업계획서·현황자료에 "제주 제조업체의 도외 구매 비중" 같은 지표를 넣으려 할 때(16번).
- 첫 화면에서 하는 일: 질문을 넣고 기업 데이터 CSV 폴더를 고른다.
- 결과까지 단계: Agent 안 5단계(질문, 받을 파일 안내, 폴더 지정, 가려진 칸 확인과 큰 묶음 제안 수락, 저장). Agent 밖 조회는 거래처·기업정보 등 여러 종이다.
- 비전문가가 막힐 지점: 산업분류 대분류·중분류 체계, 칸이 왜 가려졌는지(정책에 없는 팀 자체 기준), 큰 묶음 제안을 받아들일지 판단하는 일까지 3개다.
- 손에 남는 결과물: PDF와 png. 정책보다 엄격하게 가려 반출에 유리하지만, 팀 자체 기준이 심사 기준과 다를 수 있다(16번).
- 시연 한 컷: 업종별 막대 중 두 칸이 회색으로 가려지고 "기업 수가 적어 개별 기업이 드러날 수 있습니다"라는 설명과 "대분류로 묶으면 모든 칸을 보여 줄 수 있습니다" 버튼이 뜨는 장면이다.
- 편의성·실용성 16점: 부담 4점, 막힘 4점, 결과물 5점, 활용 3점(반복 상황 추론 1점, 센터 데이터와 규칙 적합 2점, 해당 데이터가 명세서 v13에 있는지와 컬럼이 무엇인지 미확인 0점. 기업 8종은 오래된 데이터라는 13번 지적도 있음)이다.

## 3. 상호평가: 기획서 첫 쪽 그림 한 장

판정 기준은 두 가지를 모든 후보에 똑같이 썼다. 그림 한 장이 사용자, 불편, 결과 화면, 데이터 경계를 몇 초 안에 전하는가. 그리고 다른 팀 기획서와 나란히 놓였을 때 구분되는가(20번 표의 겹칠 가능성과 브리핑 7절의 경쟁 신호). 투표자가 한 쌍을 오래 보지 않는다는 전제는 15번의 추론을 따랐다.

- A, 3점: 센터 분석실의 기관 실무자가 왼쪽에 10 미만 칸이 주황으로 칠해진 표를 들고 있고, 그 표가 오른쪽에서 권역으로 묶인 반출용 표와 PDF·활용 사유 문안으로 바뀌며, 아래 띠에 "계산은 센터 PC 안에서만, 외부 전송 0건"이 적힌 그림이다. 메시지는 선명하지만 반출 점검·현황보고서·마스킹 분석기 쪽 기획서가 비슷한 그림을 낼 가능성이 높다(추론).
- B, 5점: 축제 담당 공무원이 "축제 덕분에 지역 소비가 늘었나"라는 질문을 들고 있고, 가운데에 행사 지역과 비교 지역 두 선이 행사 주간에 벌어지는 그래프, 오른쪽에 성과보고서 PDF, 아래에 "공개 유동인구는 AI가 보고, 센터 카드 숫자는 PC 안에서 코드만 계산"이라는 두 칸 경계가 있는 그림이다. 그래프 한 장이 질문과 답을 동시에 말하고, 게시판에서 같은 주제를 밝힌 팀이 없다.
- C, 4점: 작목반장이 출하 회의 직전에 품목 버튼 하나를 누르면 가격선·작년 점선·한파 표시가 담긴 1쪽 브리핑이 나오는 그림이고, 경계는 "공개 데이터만 사용" 한 줄이다. 주제가 겹치지 않고 장면이 구체적이지만, 센터 규칙을 아는 참가자 투표자에게는 센터 데이터를 피한 공개 데이터 화면으로 보일 수 있다(추론).
- D, 4점: 집과 센터를 좌우 두 칸으로 나눠, 집 칸에서는 목적 한 문장이 조회 체크리스트로 바뀌고, 센터 칸에서는 인터넷이 끊긴 PC에 CSV 폴더만 넣으면 결과가 나오는 그림이다. 센터 칸에 AI 연결선이 아예 없어 데이터 경계가 그림 구조로 드러난다. 다만 두 칸 그림은 읽는 데 시간이 더 걸리고, 왼쪽 칸은 데이터 안내형 팀과 비슷해 보인다.
- E, 3점: 교통 공무원이 정류소 이름을 넣으면 지도 위 정류소와 비 온 날·맑은 날 막대가 나오는 그림이다. 깔끔하지만 흔한 대시보드처럼 보이고, 버스 수요 분석을 묻는 팀이 게시판에 있다.
- F, 3점: 청소행정 담당자가 행정동 하나를 고르면 판매 막대, 방문 인구 선, 다음 달 예상 범위 띠가 한 장에 나오는 그림이다. 예상 범위 띠는 눈에 띄지만 클린하우스 주제 팀이 있고, 판매량과 배출량의 차이를 아는 투표자는 의문을 가질 수 있다.
- G, 2점: 예비창업자가 "애월 카페, 언제 손님이 몰리나"를 물으면 권역 지도와 요일·시간대 격자가 나오는 그림이다. 상권분석은 경쟁이 가장 몰릴 것으로 추정되는 주제라 나란히 놓으면 구분되기 어렵다(추론).
- H, 3점: 업종별 막대 중 두 칸이 회색으로 가려지고 "개별 기업이 드러날 수 있음" 말풍선과 큰 묶음 제안 버튼이 있는 그림이다. 겹치는 팀은 없지만 "지배기업"이라는 불편이 참가자 투표자에게 한눈에 와닿지 않는다(추론).

## 4. 상위 3개 선정과 권하는 결합안

- 선정 규칙: 어떤 다른 후보와 비교해 두 점수(편의성, 첫 쪽 그림) 중 하나는 낮고 나머지 하나도 같거나 낮으면 뺐다. E는 C와 편의성이 같고(20점) 첫 쪽 그림이 낮다(3점 대 4점). D는 C와 첫 쪽 그림이 같고(4점) 편의성이 낮다(15점 대 20점). F와 H는 A에게, G는 B에게 같은 방식으로 밀린다. 남는 후보는 A(21점, 3점), B(17점, 5점), C(20점, 4점) 셋이다.
- 권하는 결합안: B의 주제와 첫 쪽 그림에 A의 4·5번 화면(반출 점검과 활용 사유)을 그대로 붙인다. 15번도 같은 결합을 제안했고 구현 범위가 늘어난다고 경고했다. 화면 부품은 A와 B가 같으므로(파일 확인, 계획 확인, 근거 패널, 저장·반출) 엔진 위에 한 벌만 만들면 되고, 추가되는 화면은 B의 행사 확인 화면 하나다(추론, 테크 리드 확인 필요).
- C는 손으로 써 보는 편의성이 가장 좋아서, 농산물 API 확인이 통과하면 실행 안정성을 가장 중시할 때의 대안이 된다.

- 본문 글자 18px, 버튼 높이 48px 이상. 영문 컬럼명은 한글 이름을 먼저 크게 쓰고 영문은 작은 회색으로 덧붙인다(11번 막힘 5위).
- 전문 용어는 화면에서 바꿔 부른다. 대조군은 "비교 지역", 범주처리는 "작은 칸 묶기", 응용집계는 "비율·증감률로 바꾸기"로 쓰고, 원래 용어는 도움말에만 둔다.
- 폴더 선택은 Chrome·Edge의 폴더 선택 대화상자와 끌어다 놓기를 둘 다 받는다. 어느 방식이 로컬 서버 구조에 맞는지는 테크 리드 확인이 필요하다.
- 저장한 결과물은 브라우저 다운로드 폴더가 아니라 Agent가 정한 결과 폴더에 쓰고 그 경로를 화면에 보여 준다. 다운로드 폴더에 흩어지면 결과 삭제 기능이 빠짐없이 지울 수 없기 때문이다.
- 오류 문구는 원인과 할 일을 한 문장씩 쓴다. 예: "이 파일은 센터에서 받은 형식이 아닙니다. Results_로 시작하는 CSV 파일을 넣어 주세요."

### 5-2. 신뢰 장치 네 가지

1. 외부 전송 표시: 상단 띠에 "외부 전송: 센터 데이터 0건, 공개 정보 n건"을 늘 띄운다. 누르면 전송 기록 표(시각, 받는 곳 주소, 보낸 내용 전문, 센터 데이터 포함 여부)가 열린다. 센터 CSV를 불러오는 순간 띠가 "센터 데이터 모드: 외부 AI 연결 잠김"으로 바뀌고 자물쇠 표시가 붙는다. 질문 문장에 숫자가 있으면 보내기 전에 막고 이유를 보여 준다. 전송 기록 화면 맨 아래에 자동 테스트 결과("표시값을 심은 가상 CSV로 검사한 결과 외부 요청에서 표시값이 0건 발견됨, 검사일")를 링크한다(16번 체크리스트).
2. 숫자 근거 연결: 화면과 PDF의 모든 숫자에 점선 밑줄을 긋는다. 화면에서 숫자를 누르면 근거 패널에 계산식(한국어 한 줄과 코드 한 줄), 원천(데이터 이름과 기준 월, 파일 이름, 행 수, 파일 지문 앞 8자리), 적용 조건, 작은 칸 묶기 단계, AI가 쓴 원래 문장 틀(예: "{{표1.1위.변화율}}")이 뜬다. 보고서 맨 위에는 "이 보고서의 숫자 n개는 모두 코드가 계산했고, AI가 직접 쓴 숫자는 0개입니다" 배지를 둔다. PDF는 클릭이 안 되므로 숫자마다 각주 번호를 달고 끝에 계산 근거표를 붙인다(14번 빈칸 채움 방식).
3. 결과 삭제 켜기·끄기: 상단 띠의 토글이고 센터 PC의 기본값은 켜짐이다. 켜짐이면 "끝내기"를 누를 때 지울 목록(작업 파일, 불러온 CSV 복사본, 전송 기록, 캐시)과 남길 목록(결과 폴더의 PDF·png)을 함께 보여 주고 확인을 받은 뒤 지운다. 꺼짐이면 "다음에 이어 하려고 남겨 둡니다. 퇴실 시 센터 규칙에 따라 삭제될 수 있습니다"를 띄운다. 사용자 확인 없이 지우지 않는다(14번 "절대 하지 않는 것").
4. 반출 가능 여부 표시: 결과물 카드마다 배지를 붙인다. "반출 신청 가능(사전 점검 기준)", "반출 어려움: 10 미만 칸 2개 남음"처럼 이유를 단 것, "반출 불가 형식(CSV·엑셀)" 세 종류다. 배지 옆에 "최종 판단은 센터 심사자가 합니다"를 고정으로 쓰고, "통과"라는 말은 쓰지 않는다(16번).

## 6. 와이어프레임

### 6-1. 후보 A: 반출 통과형 현황보고서

화면 0. 시작
- 가운데 큰 버튼 두 개: "센터에서 받은 파일 넣기"(폴더 선택), "예시 데이터로 해 보기"(동봉한 가상 CSV를 바로 불러옴).
- 버튼 아래 안내 한 줄: "센터 조회 화면에서 내려받은 Results_로 시작하는 파일이 든 폴더를 골라 주세요."
- 결과 삭제가 켜져 있으면 지난 작업 목록은 보이지 않는다.

화면 1. 파일 확인
- 파일 카드 목록. 카드마다 파일 이름 대신 "카드 이용 현황(읍면동) v02, 2025년 8월, 행 n개"를 크게 쓰고 파일 이름은 작게 쓴다. 월은 파일 안의 base_year_month로 판별한다.
- 형식 검사 결과(헤더, NA, 큰따옴표, 인코딩)를 "확인됨" 또는 쉬운 오류 문구로 보여 준다.
- 누락 월 경고: "2025년 7월 파일이 없습니다. 이대로 진행하거나 센터에서 더 받아 오세요."
- "컬럼 뜻 보기" 펼침: bjd는 법정동 코드, user_cnt는 이용자 수처럼 한글 설명.
- 버튼: "다음".

화면 2. 무엇을 만들까
- 목적 입력창 하나와 예시 칩 4~5개(지원 질문 유형을 4~5개로 좁힘, 14번). 예: "읍면동별 관광업종 이용 금액 변화", "연령대별 소비 비중".
- "이 보고서를 어디에 쓰시나요?" 선택지: 사업계획서, 논문, 현황자료, 기타(직접 입력). 활용 사유 문안에 들어간다.
- 질문에 숫자가 있으면 입력창 아래에 경고: "질문에 숫자가 있습니다. 센터 데이터 값일 수 있어 외부 AI로 보내지 않았습니다. 숫자를 빼고 다시 써 주세요."
- 버튼: "계획 세우기".

화면 3. 계획 확인
- AI가 세운 계획을 한국어 목록으로 보여 준다: 묶는 기준, 보여 줄 지표, 차트 종류, 보고서 목차.
- 추천 이유 한 줄: "합계 대신 증감률로 보여 드립니다. 반출 심사에서 비율·증감률은 수치를 포함해 반출할 수 있기 때문입니다."
- 작은 칸 묶기 순서 그림: 세부 연령, 10세 단위, 3구간 순서와 법정동, 행정시, 7권역 순서를 계단 모양으로 보여 준다.
- 하단 작업 기록 펼침: "가상 데이터 리허설에서 컬럼명 오류, 계획 수정, 리허설 통과."
- 버튼: "이대로 만들기", "고치기"(목적 입력으로 돌아감).

화면 4. 결과와 반출 점검
- 위쪽 요약 문장(빈칸 채움): "10 미만 칸 {{n}}개를 연령 10세 단위로 묶어 없앴습니다. 합계로 되살릴 수 있는 칸 {{m}}개를 추가로 가렸습니다."
- 가운데 좌우 비교: 처리 전 표(10 미만 칸 주황, 배지 "센터 안에서만 보기")와 반출용 표(배지 "반출 신청 가능(사전 점검 기준)").
- 차트 미리보기 png 2~3장.
- 반출 점검표: 조항마다 한 줄(10 미만 처리, 역산 검사, 그림 형식 png, 코드 출력 없음)과 근거 조항 출처(허브 공지 48번).
- 모든 숫자는 누르면 근거 패널이 열린다.

화면 5. 저장과 반출
- 결과물 카드: 보고서 PDF, 그림 png 여러 장, 처리 전 표(반출 불가 배지, 저장 버튼 없음), CSV·엑셀 내보내기는 회색으로 두고 "스프레드시트는 원칙적으로 반출할 수 없습니다" 설명.
- 활용 사유 문안 상자와 "복사" 버튼. 예: "Python 기반 집계 Agent로 분석 후 연령 10세 단위 범주처리로 가공하여 애월읍 관광업종 소비 현황 보고서 작성 및 사업계획서에 활용."
- 반출 신청 화면에 넣을 항목 표: 제목, 설명, 파일마다 활용 데이터 1개와 파일 구분(분석결과).
- 결과 폴더 경로와 "폴더 열기" 버튼.
- "끝내기" 버튼: 결과 삭제 확인 대화상자(지울 목록과 남길 목록).

## 8. 어느 후보를 고르든 지킬 설계 권고

- 첫 화면의 "예시 데이터로 해 보기" 버튼이 심사위원 경험의 거의 전부다. 설치 직후 한 번 눌러 결과 PDF까지 가는 경로를 매뉴얼 첫 쪽에 그림으로 넣는다(15번이 지적한 설치 실패 위험과 같은 맥락).
- 외부 LLM 키가 없거나 호출이 실패하면 "AI 없이 기본 보고서 틀로 만들기"로 자동 전환하고, 상단 띠에 "AI 연결 없음, 기본 틀 사용"을 띄운다(16번 체크리스트의 LLM 꺼짐 모드).
- 기획서 첫 쪽에는 3절의 그림 한 장과 5-2절의 상단 띠 캡처를 넣는다. 상호평가는 PDF만 보므로 신뢰 장치는 캡처로만 전달된다(14번 추론과 같음).
- 기획서는 다른 참가자에게 공개되므로 캡처에 API 키, 실제 경로 속 개인 이름, 비공개 정보가 보이지 않게 한다(20번 3절).

## 9. 다른 팀원에게 확인할 것

- 컴플라이언스 책임자: 설계도처럼 CSV가 아닌 파일을 센터 PC에 들일 수 있는가(D, 그리고 B의 체크리스트를 파일로 가져가는 경우). 공개 데이터만으로 센터 PC에서 만든 PDF도 반출 신청을 거쳐야 하는가(C, E).
- 데이터 분석가: 허브 농산물 API의 품목·시장·갱신 여부(C), 축제행사콘텐츠 파일의 날짜·장소 컬럼(B), 같은 이름 정류소가 여럿 있는지(E).
- AI 엔지니어와 테크 리드: 근거 패널에 필요한 계획 JSON, 파일 지문, 계산식 저장이 5일 범위 안에 드는가. 폴더 선택을 브라우저 대화상자로 할지 로컬 서버가 경로를 받을지. 결과물을 Agent가 정한 폴더에 쓰는 방식이 결과 삭제 기능과 맞는가.
