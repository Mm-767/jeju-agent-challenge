  - 필수 데이터 활용 적절성 20: 지정 데이터 1종 이상의 실질적 활용, 분석·처리 방법의 적절성
  - AI Agent 기술성 및 완성도 25: 목표에 따른 도구·데이터 활용, 주요 기능의 안정적 수행
  - 편의성 및 실용성 25: 사용자 편의성, 실제 서비스 활용 가능성

- 전문가 평가는 센터 운영환경과 최대한 비슷한 환경에서 제출 매뉴얼대로 실제 설치·실행한다. 오류가 나도 참가자에게 개별 연락하지 않는다. 비개발자가 따라 할 수 있는 매뉴얼이 필요하다. 평가 환경은 인터넷 가능.
- 실제 운영 시 API 비용은 센터 부담이라 비용 효율도 고려하라고 했다.
- 운영진 답변: 외부 LLM 없이 Agent 코드로 집계해 표·차트만 보여 줘도 데이터 활용으로 인정되지만 "AI Agent 대회라 AI가 어떤 역할을 하는지가 중요".

## 4. 실행 환경과 데이터 사용 규칙 (게시판 운영진 답변)

- 센터 PC: Windows 11 26H2, Intel Core i7-8700, GTX 1060 (VRAM 3GB), RAM 32GB, 고정 IP, 인터넷 가능, Chrome·Edge, 1920×1080. Python 등 설치 가능(기획서에 미리 적은 것만). 센터 담당자가 매뉴얼대로 설치, 인터넷으로 패키지·로컬 LLM 모델 다운로드 가능.
- 127.0.0.1 로컬 서버 + 브라우저 방식 가능. DLP 보안정책이 있어 데이터가 외부로 나가는 통신은 차단될 수 있다.
- 앱·웹 모두 가능. 같은 Agent를 개인 PC에서 따로 실행하게 만드는 것도 가능. 단 센터 데이터가 통신으로 외부에 나가는 구조는 불가.
- 센터 비공개 데이터 사용법: Agent가 센터 DB·API에 직접 연결 불가. 이용자가 센터 조회 화면에서 데이터 선택→기간(한 번에 1개월)→조건(같다/같지않다 등, And/Or)→조회→CSV 다운로드 후, 그 CSV를 Agent에서 파일 선택·경로 지정으로 불러오는 구조여야 한다. 지역 조건 없으면 전체 읍면동 한 파일. 여러 달은 월별로 받거나 운영자에게 요청(바탕화면 "요청파일" 폴더).
- 센터 CSV 형식: 헤더 영문 컬럼명, 쉼표 구분, 결측 NA, UTF-8(BOM 없음), 모든 값 큰따옴표, 파일명 Results_YYYYMMDD_HHMMSS.csv, 파티션 컬럼 없음. 작은 값(10 미만) 가리지 않은 원본이라는 참가자 전언 있음.
- 개발·제출은 데이터 명세서 구조를 따른 가상 데이터로 해도 된다. 평가 실행에는 더미·샘플 데이터 권장.
- 센터 이용자 현황: 대부분 기관·기업, 목적은 논문·현황자료·사업계획서 작성. 이용자는 SQL을 쓰지 않고 메뉴로 조회한다. 센터 반입은 CSV만.
- 퇴실 시 반출 승인 자료 외 삭제. 집계값 보존이 필요하면 매뉴얼에 명시. Agent에 결과 삭제 기능 ON/OFF 권장(없으면 탑재 어려울 수 있음).
- 외부 LLM 규칙: 센터 데이터 원본·조회 결과를 외부 LLM으로 보내면 불가. 집계값 전송은 센터 심의 대상이라 허용 범위를 사전에 확정해 주지 않음(11/7, 11/10). 질문 문장에 센터 데이터 값이 들어가 외부로 가도 외부 전송으로 본다. 제주데이터허브 공개 데이터는 이런 제한이 없다(공개 데이터).
- 외부 LLM 제공자 지정 없음. 널리 쓰이는 안정적 서비스 권장, VPN 필요하거나 결제 복잡한 것은 곤란. 운영 시 키는 센터 담당자가 환경변수로 설정. 평가용 외부 AI 키는 참가자가 준비해 ZIP 매뉴얼에 넣어 제출(한도 설정 가능, 비용 참가자 부담).
- 로컬 LLM: 모델 파일은 ZIP에 안 넣고 공식 배포처 다운로드 안내 가능. GTX 1060 3GB라 큰 모델은 어렵다(이건 팀이 판단할 사항).
- 외부 주소 차단: 행안부 불법광고 차단 키워드 133개가 들어간 주소는 자동 차단될 수 있다. 일상어도 포함: 코인, 아이스, 케이, 마약, 카지노, 픽업, 정산, 운반, 드랍, 실험용, 회원모집, 자동수집, 그룹방, 떨 등. "충전", "얼음", "세탁"은 차단 아님. 기획서에 적은 외부 주소는 허용 목록 등록 가능.

- 조회수 상위: 제주방문관광객 통계(Link), 내국인 관광객 카드 이용(API, 2016~2018), 서귀포시 클린하우스현황, 풍력발전현황, 읍면동 내국인 유동인구(API, 일 갱신), 채소류 재배 현황, 일별 기상 정보, 제주 방문 내국인 유동인구 추이(~2025-04), 공공와이파이 AP 정보, 방문목적별 입도객 현황(~2025-07).
- 허브 Open API(open.jejudatahub.net, 프로젝트 키)는 센터 PC에서 Agent가 직접 호출 가능. 허브 공개 데이터 원본·전처리본·DuckDB 등은 ZIP에 넣어도 됨. 허브 유동인구 API의 resdPop·workPop·visitPop은 하루 시간대별 인구 합(연인원).
- 외부 공개 데이터도 적법하면 사용 가능(출처 명시).

## 7. 경쟁 신호: 게시판 질문으로 본 다른 팀들의 개발 방향

게시판 문의 50개에서 드러난 다른 참가자들의 구상이다(질문자가 직접 밝힌 것만):
- 반출 신청 전에 결과물이 반출 기준에 맞는지 미리 점검하는 기능(beebird, sanhapark, 강태우 "반출 점검 메모")
- 센터 PC에서 방문 이용자가 실행하는 현황보고서 Agent, 최근 보고서 목록(river.kim)
- 센터 이용 안내(반출 절차, 분석실 이용 규칙)에 답하는 Agent, 허브 공개 문서 기반(뿌요탄)
- 데이터 안내 기능(허브 데이터 목록·센터 명세서로 어떤 데이터를 받아야 할지 안내) + 로컬 LLM 지원(안녕하12)
- 이용자에게 받아야 할 파일 목록을 안내하는 기능(너굴맨이처리했다구)
- 센터 CSV를 넣으면 Agent 코드가 집계하고 외부 LLM에는 마스킹 집계표만 보내 해석 문장 생성(안녕하12, 미노스, Tarkovsky)
- 클린하우스 공개데이터 기반 Agent(도톨토뤼)
- 전기자동차 충전소 데이터 분석(taeaeamin)
- 어린이집 정보, 버스 수요응답형 분석(수연에이전트)
- 소상공인 자기 가게 매출과 센터 데이터 비교 분석(한콩이아빠: 이용자 자료 반입 질문)
- 외식업 포스 데이터 기반 개발(sanhapark)
- 소상공인·예비창업자 상권분석은 센터 이용 목적과 겹쳐 많을 것으로 추정(추정임)
→ "센터 이용 도우미/데이터 안내/반출 점검/현황보고서 자동 생성"과 "CSV 넣으면 분석해 주는 범용 분석기"에 경쟁이 몰려 있을 가능성이 크다(추론).

## 9. 모든 팀원이 지킬 작업 원칙

- 한국어로 쓴다. 문장은 완결형으로, 줄임말·화살표 나열 금지. 내가 만든 번호나 라벨을 설명 없이 쓰지 않는다.
- 사실은 이 브리핑이나 확인한 출처에서만 가져온다. 주최 측 의도나 심사 성향처럼 근거가 없는 것은 "추론"이라고 붙인다. 지어낸 숫자 금지.
- 아이디어를 평가할 때는 모든 후보에 같은 기준을 똑같이 적용한다. 경쟁 쏠림(다른 팀과 겹칠 가능성)과 시연 가능성(가상 데이터로 평가 환경에서 실제로 돌아가는가)을 반드시 포함한다. "지금 이용자가 적다"는 이유만으로 아이디어를 탈락시키지 않는다.
- 보고서는 지정된 파일 경로에 쓰고, 마지막 응답에는 핵심 결론 10줄 이내 요약만 돌려준다.
