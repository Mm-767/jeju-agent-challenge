# 화면(UX·UI) 설계서: 「행사 효과 나란히」

작성: 화면 설계자, 2026-11-13. 근거는 40번 브리핑 전체, 23번 프로덕트 디자이너 보고서 전체, 30번 PM 결정 보고서 전체, 11번 사용자 리서처 보고서 1~3절, 00번 공용 브리핑 2~5절, 16번 컴플라이언스 보고서 1-13절·2절·4절, 22번 테크 리드 보고서 5~6절, 14번 AI 엔지니어 보고서 4절, 그리고 이미 만든 app/static/index.html이다. 웹 검색은 하지 않았다. "기억 기반"이라고 적은 것은 이번에 확인하지 않은 내 기억이고, "추정"은 계산이나 판단으로 낸 값이다. 코드는 만들거나 고치지 않았다.

## 결론 5줄

1. 화면은 페이지 하나 안에서 여섯 단계(행사 고르기, 장소 확인, 방문과 비교 확인, 센터 파일 넣기, 결과, 저장과 반출)를 바꿔 보여 주고, 예시 경로는 네 번 눌러 결과 화면에, 여섯 번 눌러 활용 사유 복사까지 간다.
2. 화면 가운데에 작업 영역을, 오른쪽에 AI 판단과 코드 계산을 구분해 쌓는 작업 기록을 늘 띄우며, 상단 띠는 예시 표시, 외부 AI 연결의 열림과 잠김, 외부 전송 건수, 결과 삭제 상태를 보여 준다.
3. 센터 파일이 들어오는 순간 외부 AI를 잠그므로 AI가 계산 계획을 세우고 가상 데이터로 미리 돌려 보는 일은 파일을 넣기 전에 끝나야 하고, 그래서 파일 넣는 칸은 계획이 준비된 뒤에 열리며 이것이 아키텍트와 가장 먼저 맞출 사항이다.
4. 구현 방식은 페이지 하나에 서버가 상태를 보관하는 구조, 서버가 matplotlib으로 만든 png를 화면과 반출에 같이 쓰는 방식, 1초 간격 상태 조회, 파일 고르기와 끌어다 놓기로 CSV 넣기, 방문 증가와 비교 읍면을 한 화면에 두기를 추천하며 다섯 가지 모두 사용자 결정이 필요하다.
5. 숫자 근거는 클릭 패널 대신 각주 번호와 계산 근거표로 보여 주고, 지도와 JS 차트와 채팅창과 이어 하기와 CSV 내보내기는 만들지 않으며, 기획서에는 첫 쪽 그림 1장과 화면 캡처 12장을 작업 영역 폭으로 잘라 넣는다.

## 1. 누구를 위해 어떤 기준으로 그렸나

### 1-1. 두 부류의 사용자

- 실제 사용자: 행정시·읍면 축제 담당 공무원, 축제추진위원회 사무국, 관광 관련 협회 직원(30번 2-1절). 역량은 11번 페르소나 중 기관 실무자 B와 가장 가깝다고 본다(추론). 엑셀 피벗과 차트는 능숙하고, SQL과 통계 모형은 쓰지 않는다. 결과보고서나 다음 해 예산 요구 자료에 숫자 한 줄과 그림 한 장이 필요하다.
- 심사위원: 매뉴얼대로 설치한 뒤 처음 보는 화면에서 "예시로 해 보기"를 누르고 3~5분 안에 판단한다(30번 시연 시나리오). 오류가 나도 참가자에게 묻지 않는다(00번 3절). 상호평가 투표자는 화면을 보지 못하고 기획서 PDF의 캡처만 본다.

### 1-2. 설계 기준

- 결과까지 누르는 횟수를 줄인다. 확인 버튼 하나도 한 번으로 센다(23번 1-2절의 규칙).
- 이용자가 꼭 이해해야 하는 낯선 개념은 "비교 지역" 하나로 묶는다. 사전 추세 검사, 가짜 시점 검사, 범주처리 같은 말은 화면에 쓰지 않고 쉬운 말로 바꾼다(7절).
- 공개 데이터 단계와 센터 데이터 단계를 색으로 나눠 이용자가 지금 어느 쪽인지 늘 알게 한다(23번 6-2절).
- 화면에 보이는 모든 숫자는 코드가 채운다. 공개 데이터 단계의 숫자도 같다. 그래야 "AI가 쓴 숫자 0개" 배지를 예외 없이 붙일 수 있다.
- 기준 화면은 1920×1080, 브라우저 확대 100%다. 윈도우 배율이 125%이면 브라우저가 쓰는 폭이 1536px로 줄어드므로(1920을 1.25로 나눈 값) 그 폭에서도 버튼이 가려지지 않게 한다. 노트북에서는 125%가 기본값인 경우가 많다(기억 기반).

## 2. 사용자 흐름 전체

### 2-1. 단계별로 누가 무엇을 하나

| 단계 | 화면 | 이용자가 하는 일 | AI가 하는 일(공개 정보만 봄) | 코드가 하는 일 | 외부 AI 연결 |
|---|---|---|---|---|---|
| 0 | 첫 화면 | "예시로 해 보기" 또는 "직접 분석하기"를 누른다 | 없음 | 키가 있는지 확인, 행사 목록 읽기 | 열림 |
| 1 | 행사 고르기(직접 경로만) | 검색해서 행사 하나를 고른다 | 없음 | 행사 파일 검색, 볼 수 있는 행사인지 판정 | 열림 |
| 2 | 장소 확인 | AI가 짐작한 읍면이 맞는지 고른다 | 행사 이름·주관·주최로 개최 읍면을 짐작하고 이유를 쓴다 | 읍면 12곳 목록과 대조 | 열림 |
| 3 | 방문과 비교 확인 | 비교 순서를 확인한다 | 방문이 늘었는지 판단, 같은 달 다른 행사가 있는 읍면 빼기, 비교 순서와 이유 쓰기 | 방문 인구 읽기, 행사 전 흐름이 닮은 정도 계산, 그래프 png | 열림 |
| 4 | 센터 파일 넣기 | 체크리스트를 보고 파일을 넣고 "계산 시작"을 누른다 | 계산 계획, 결과 문장 틀, 한계 문장, 활용 사유 틀을 쓰고, 가상 데이터에서 문제가 나면 최대 3번 고친다. 모두 파일을 넣기 전에 끝난다 | 계획 검사, 가상 데이터 실행, 파일 형식 검사, 연월 판별, 빠진 달 표시, 잠금 | 계획이 준비되고 첫 파일이 들어오면 잠김 |
| 계산 중 | 진행 표시(누를 것 없음) | 기다린다 | 없음 | 파일 합치기, 행사 전 흐름 확인과 비교 읍면 바꾸기, 차이 계산, 행사 없던 달 시험, 10 미만 칸 처리, png·PDF 만들기 | 잠김 |
| 5 | 결과 | 읽고 근거를 확인한다 | 없음 | 문장 빈칸 채우기 | 잠김 |
| 6 | 저장과 반출 | 쓰임을 고르고 활용 사유를 복사한 뒤 끝낸다 | 없음 | 반출 배지 판정, 결과 폴더 열기, 결과 삭제 | 잠김 |

### 2-2. 누르는 횟수

- 예시 경로: "예시로 해 보기", "장소 확인", "이 순서로 비교하기", "계산 시작"으로 네 번 만에 결과 화면이 열린다. "저장과 반출로", "복사"까지 여섯 번이다. 결과 PDF·png는 계산이 끝날 때 결과 폴더에 저절로 만들어지므로 따로 저장 버튼을 누르지 않는다.
- 직접 경로: "직접 분석하기", 행사 고르기, "장소 확인", "이 순서로 비교하기", 파일 넣기, "계산 시작", "저장과 반출로", "복사"로 여덟 번이다. 프로그램 밖에서 하는 센터 조회는 받을 달 수만큼 필요하고, 달이 많으면 운영자 요청 한 번으로 줄일 수 있다(00번 4절의 "요청파일" 폴더).

### 2-3. 잠금 때문에 생기는 화면 규칙 (아키텍트·AI 엔지니어와 맞출 것)

30번 2-1절은 "센터 CSV를 불러오는 순간 외부 통신 모듈이 잠긴다"고 정했다. 이 결정을 화면에 그대로 옮기면 다음 규칙이 따라온다.

1. AI가 할 일은 첫 센터 파일이 들어오기 전에 모두 끝나야 한다. 장소 짐작, 방문 증가 판단, 비교 순서와 바꾸는 순서, 계산 계획, 가상 데이터 리허설과 고치기, 결과 문장 틀, 한계 문장, 활용 사유 틀이 여기에 들어간다.
2. 그래서 계산 계획은 "이 순서로 비교하기"를 누를 때 서버 뒤에서 시작하고, 이용자가 체크리스트를 읽거나 센터에서 파일을 받는 동안 진행한다. 파일 넣는 칸은 계획이 준비된 뒤에 열린다. 계획 전에 파일을 넣게 하면 잠금 때문에 계획을 세울 수 없기 때문이다.
3. 잠긴 뒤에는 1~3단계로 돌아갈 수 없다. 다른 행사를 보려면 "끝내기"로 센터 파일 복사본을 지우고 처음부터 시작한다. 한 번 방문에 행사 두 개를 보려면 파일을 다시 넣어야 한다는 불편이 생기지만, 잠금 규칙을 단순하게 지키는 값으로 받아들인다.
4. 잠금은 "끝내기"에서 센터 파일 복사본을 지울 때 풀린다. 결과 삭제가 꺼져 있으면 프로그램을 다시 켤 때까지 잠김을 유지할지는 아키텍트가 정한다.
5. 잠금은 화면에서 버튼을 숨기는 것으로 끝내지 않는다. 잠긴 뒤 AI를 부르는 요청은 서버가 거절해야 한다.

### 3-1. 배치 (1920×1080)

```

+--------------+---------------------------------------------------------------+-------------------+
| 단계 막대     | 작업 영역                                                      | 작업 기록          |
```

- 23번 5-1절의 틀에서 오른쪽 "근거 패널"을 작업 기록으로 바꿨다. 30번 4-4절이 숫자를 누르면 뜨는 근거 패널을 범위에서 뺐고, 작업 기록은 AI 역할을 보여 주는 핵심 장면이라 결과 그래프 옆에 늘 보여야 캡처 한 장에 같이 담기기 때문이다(14번 4-3절).
- 23번 틀의 아래 "작업 기록 한 줄 요약" 띠는 없앴다. 오른쪽 칸과 겹친다.
- 폭이 1600px보다 좁으면 단계 막대를 200px, 작업 기록을 360px로 줄인다. 1280px보다 좁으면 가로 스크롤을 허용한다.

### 3-2. 상단 띠

띠의 칸은 다섯 개다. 서비스 이름, 데이터 칸, 연결 칸, 외부 전송 칸, 결과 삭제 칸, 그리고 도움말 버튼이다.

| 상황 | 데이터 칸 | 연결 칸 | 연결 칸 색 |
|---|---|---|---|
| 예시, 가상 파일이 들어가기 전 | 예시(가상 데이터) | 공개 데이터 단계: 외부 AI 연결 열림 | 초록 |
| 예시, 가상 파일이 들어간 뒤 | 예시(가상 데이터) | 센터 데이터 모드: 외부 AI 연결 잠김 | 진한 남색, 자물쇠 그림(인라인 SVG) |
| 직접, 파일을 넣기 전 | 비어 있음 | 공개 데이터 단계: 외부 AI 연결 열림 | 초록 |
| 직접, 센터 파일이 들어간 뒤 | 센터 데이터 | 센터 데이터 모드: 외부 AI 연결 잠김 | 진한 남색 |
| AI 키가 없음 | 그대로 | 미리 만든 계획 사용: AI 키가 없습니다 | 회색 |
| AI 호출이 실패해 바꿈 | 그대로 | 미리 만든 계획 사용: AI 연결에 실패했습니다 | 회색 |

- 연결 칸에 마우스를 올리면 풀이가 뜬다. "센터 데이터가 이 PC에 들어온 뒤로는 프로그램이 인터넷으로 나가는 요청을 막습니다. 끝내기에서 센터 파일을 지우면 풀립니다."
- 외부 전송 칸은 "외부 전송 {n}건, 센터 데이터 0건"이고, 누르면 외부 전송 기록 대화상자가 열린다(4-10절).
- 결과 삭제 칸은 켜기·끄기 스위치이고 기본값은 켜짐이다. 끄려고 누르면 작은 확인 상자가 뜬다. "끄면 끝낼 때 아무 파일도 지우지 않습니다. 센터 PC에서는 켜 두기를 권합니다. [끄기] [그대로 두기]"
- AI 키 확인은 키가 설정돼 있는지만 본다. 시작할 때 외부 AI에 시험 호출을 보내지 않는다. 비용이 들고 외부 전송 기록에 쓸모없는 줄이 생기기 때문이다. 실제 호출이 실패하면 그때 회색으로 바꾼다.

### 3-3. 단계 막대

- 두 구역으로 칠한다. 위는 "공개 데이터 단계: AI가 직접 봅니다"(초록 바탕), 아래는 "센터 데이터 단계: 이 PC 안에서만 계산합니다"(남색 바탕).
- 지금 단계는 굵게, 끝난 단계는 회색 글자와 "끝남" 표시를 단다. 잠기기 전에는 끝난 단계를 눌러 돌아갈 수 있다. 잠긴 뒤 1~3단계는 누를 수 없고, 마우스를 올리면 "센터 데이터가 들어와 AI 단계로 돌아갈 수 없습니다. 다른 행사를 보려면 끝내기 뒤 다시 시작하세요."가 뜬다.
- 첫 화면에서는 단계 막대를 흐리게 보여 앞으로의 흐름만 알린다.

### 3-4. 작업 기록 칸

- 맨 위에 요약 한 줄을 둔다. "AI 판단 {n}건, 고친 횟수 {n}번, 외부 전송 {n}건"
- 항목마다 시각, 종류 꼬리표, 한 문장이다. 꼬리표는 다섯 가지다. [AI 판단](보라), [코드 계산](회색), [검사](초록 또는 빨강), [확인](이용자가 정한 것), [외부 전송](파랑). 미리 만든 계획으로 진행할 때는 AI 판단 대신 [미리 만든 계획] 꼬리표를 쓴다.
- 새 항목은 아래에 붙고 칸이 자동으로 아래로 내려간다.
- 빈 상태 문구: "작업 기록은 여기에 쌓입니다. AI가 무엇을 보고 왜 그렇게 정했는지, 코드가 무엇을 계산했는지 모두 적습니다."
- 작업 기록은 이 PC에만 남고 외부 AI로 보내지 않는다. 끝내기에서 지운다.

### 3-5. 공통 규칙

- 글자: 본문 18px, 제목 28px, 띠와 표 안 글자 15px 이상. 버튼 높이 48px 이상. 글꼴은 윈도우 기본 "Malgun Gothic"을 쓰고 웹 글꼴 파일은 넣지 않는다. 맥에서는 "Apple SD Gothic Neo"로 대신한다(지금 index.html과 같음).
- 색만으로 뜻을 전하지 않는다. 행사 읍면은 빨간 실선, 비교 읍면은 파란 점선이고, 선 끝에 읍면 이름을 글자로 단다. 노란 표시에는 "AI 짐작" 글자가 같이 붙는다.
- 키보드: Tab으로 모든 버튼에 갈 수 있고, 포커스 테두리를 지우지 않는다.
- 오류 문구는 원인 한 문장과 할 일 한 문장으로 쓴다. 센터 파일에서 난 오류 문구에는 셀 값을 넣지 않고 열 이름과 종류만 쓴다(22번 6절 함정 9).
- 영문 열 이름이 화면에 나올 때는 한글 이름을 먼저 쓰고 영문은 작은 회색으로 덧붙인다. 예: "이용 금액 use_amt".
- 서버가 보낸 글(행사 이름, AI가 쓴 이유와 문장)은 HTML로 해석하지 않고 글자 그대로 넣는다. 행사 파일과 AI 출력은 우리가 통제하지 못하는 입력이기 때문이다.

## 4. 화면별 와이어프레임

예시 문구에는 가파도청보리축제(대정읍, 2024-04-06~04-28)를 썼다. 행사 기간이 한 달 안에 들고, 카드 데이터가 시작하는 2023년 8월부터 행사 전 8개월이 있으며, "가파도"가 대정읍에 속한다는 짐작이 쉽지 않아 AI 장면이 산다. 다만 공개 방문 인구에서 증가가 실제로 보이는지는 스냅샷 수집이 끝난 뒤 확인해야 하므로, 예시 행사는 분석 설계자와 함께 정한다. 숫자는 지어내지 않으려고 {{차이}}처럼 빈칸으로 두었다. 받을 달과 행사 전 기간 길이도 분석 설계에서 정할 값이라 "예"로 적었다.

### 4-1. 행사 고르기 (직접 경로만)

```
| 어떤 행사의 효과를 볼까요?                                                       |
| [행사 이름으로 찾기 (예: 청보리, 수국, 억새)        ]  [연도: 전체]  [v] 볼 수 있는 행사만 |
| +------------------------------+--------------------+------+------------------+ |
| | 행사 이름                     | 기간                | 일수  | 볼 수 있나         | |
| | 가파도청보리축제               | 2024-04-06~04-28    | 23일 | 볼 수 있음         | |
| | 추자도 참굴비 대축제            | 2023-10-13~10-15    | 3일  | 볼 수 있음, 짧은 행사 | |
| | ...  (10줄이 보이고 표 안에서 스크롤)                                           | |
| +-----------------------------------------------------------------------------+ |
| 행사 목록: 제주데이터허브 「VISIT JEJU 축제행사콘텐츠」 파일(2025년 9월 18일 수집).    |
| 파일에 장소가 없어 다음 단계에서 장소를 확인합니다.                                    |
| > 어떤 행사가 잘 맞나요?                                                         |
| [이전]                                                          [이 행사로 진행] |
```

- 검색은 이 PC 안에서만 한다. 검색어는 외부 AI로 가지 않는다.
- "볼 수 있나" 칸의 문구는 세 가지다. "볼 수 있음", "볼 수 있음, 짧은 행사"(마우스를 올리면 "며칠짜리 행사는 한 달 합계에 묻혀 차이가 작게 나올 수 있습니다"), "볼 수 없음: 행사 전 흐름을 볼 카드 데이터가 없습니다(카드 데이터는 2023년 8월부터)". 볼 수 있는 행사의 기준(행사 전 몇 달이 필요한지)은 분석 설계에서 정한다.
- 미리 만든 계획이 있는 행사에는 "미리 만든 계획 있음" 꼬리표를 단다. AI 키가 없으면 나머지 행사는 흐리게 하고 "AI 연결이 필요합니다"라고 쓴다.
- 줄을 누르면 고른 줄이 칠해지고 "이 행사로 진행"이 눌린다.
- 도움말 "어떤 행사가 잘 맞나요?": "행사가 한 달 안에 길게 열렸고, 그 읍면의 다른 달에는 큰 행사가 없을수록 차이가 잘 드러납니다. 카드 데이터가 월 단위이기 때문입니다."
- 빈 상태: "‘{검색어}’가 들어간 행사가 없습니다. 다른 낱말로 찾아 보세요. 행사 목록은 2025년 9월에 받은 파일이라 그 뒤 행사는 없습니다."
- 완료 기준: "청보리"로 찾으면 가파도청보리축제가 나오고, 행사 전 기간이 모자란 2023년 8월 직후 행사는 "볼 수 없음"으로 나온다.

### 4-2. 장소 확인

```
| 이 행사는 어느 읍면에서 열렸나요?                                               |
| +---------------------------------------------------------------------------+ |
| | 가파도청보리축제                                                            | |
| | 기간 2024-04-06 ~ 2024-04-28 (23일)   주관 ○○   주최 ○○   (행사 파일에서)    | |
| +---------------------------------------------------------------------------+ |
| +----------------------------- 노란 바탕 ------------------------------------+ |
| | [AI 짐작] 대정읍                                                           | |
| | 이유: ‘가파도’는 서귀포시 대정읍 가파리에 속한 섬입니다.                        | |
| | 행사 파일에 장소 열이 없어 AI가 행사 이름과 주관 기관으로 짐작했습니다.           | |
| +---------------------------------------------------------------------------+ |
| ( ) 맞습니다. 대정읍에서 열렸습니다.                                            |
| ( ) 다른 읍면입니다.  [읍면 고르기(목록)]                                        |
| ( ) 동 지역이거나 잘 모르겠습니다.                                               |
| > 왜 장소를 확인하나요?                                                         |
| [이전]                                                            [장소 확인] |
```

- 세 선택지는 처음에 아무것도 골라 두지 않는다. 고르기 전에는 "장소 확인"을 누를 수 없다(30번 2-1절, AI가 짐작한 값은 확인 전 다음으로 못 감).
- "동 지역이거나 잘 모르겠습니다"를 고르면 버튼 글자가 "다른 행사 고르기"로 바뀐다.
- AI가 기다리는 동안: 노란 상자 안에 "AI가 장소를 짐작하고 있습니다."와 돌아가는 표시(CSS).
- AI가 동 지역으로 짐작했을 때: "[AI 짐작] 동 지역(○○동). 이 서비스는 읍면 12곳만 다루므로 이 행사는 계산할 수 없습니다." 선택지는 "맞습니다(다른 행사 고르기)"와 "아닙니다. 읍면에서 열렸습니다 [목록]" 두 개다.
- AI가 짐작하지 못했을 때: "[AI 짐작] 장소를 짐작하지 못했습니다. 아시면 아래 목록에서 고르고, 모르시면 다른 행사를 골라 주세요."
- 미리 만든 계획일 때: 꼬리표가 "[미리 만든 계획]"이 되고 둘째 줄이 "AI 연결 없이 미리 정해 둔 장소입니다."가 된다.
- AI 호출이 실패했을 때: "AI 연결에 실패했습니다. [다시 시도]를 누르거나, 미리 만든 계획이 있는 예시로 해 보세요." 다음 단계도 AI가 필요하므로 장소만 손으로 고르고 넘어가게 하지 않는다.
- 도움말 "왜 장소를 확인하나요?": "센터 카드 데이터는 읍면별로 나옵니다. 장소가 틀리면 다른 읍면의 소비를 계산하게 되므로 한 번만 확인해 주세요. 이 서비스는 읍면 12곳(한림읍, 애월읍, 구좌읍, 조천읍, 한경면, 추자면, 우도면, 대정읍, 남원읍, 성산읍, 안덕면, 표선면)만 다룹니다."
- 작업 기록 예: "[외부 전송] api.anthropic.com에 행사 이름, 기간, 주관, 주최를 보냈습니다(공개 정보)." "[AI 판단] ‘가파도’가 대정읍 가파리에 속하므로 대정읍으로 짐작했습니다." "[확인] 이용자가 대정읍을 확인했습니다."
- 완료 기준: 시험 행사 5개에서 AI 짐작이 노란 상자로 뜨고, 고르기 전에는 다음으로 갈 수 없다. 이호테우축제를 고르면 동 지역 안내가 뜬다.

### 4-3. 방문과 비교 확인

```
| 행사 기간에 사람이 늘었는지 보고, 비교할 읍면을 정합니다                              |
| ① 대정읍 하루 방문 인구                                                          |

|          방문이 늘어난 행사로 보입니다.                                            |

|                                                                                 |
| ② 비교할 읍면 (위에서부터 씁니다)                                                  |
| +-----------------------+ +-----------------------+ +-----------------------+   |

| | 인구 흐름이 가장 닮았습니다| | 같은 달 큰 행사가 없습니다 |                         |   |
| +-----------------------+ +-----------------------+ +-----------------------+   |
| 1순위가 센터 데이터의 행사 전 흐름 확인에서 맞지 않으면 2순위, 3순위 순서로 바꿉니다.     |
| 바꾸는 순서를 지금 정해 두는 까닭은 센터 데이터가 들어온 뒤에는 AI에 묻지 않기 때문입니다.  |
| 비교에서 뺀 읍면: 표선면(같은 달 ‘○○축제’가 열림), 우도면(행사 전 흐름이 많이 다름) ...   |
| > 비교 지역이란?                                                                  |
| [이전]  [다른 행사 고르기]                                      [이 순서로 비교하기] |
```

- 방문 증가와 비교 읍면을 한 화면에 둔 이유와 대안은 6-2절 결정 5에 있다.
- 작은 그림은 행사 읍면(빨간 실선)과 후보 읍면(파란 점선)의 행사 전 흐름을 같은 눈금으로 맞춰 그린다. 그림 제목은 "대정읍과 안덕면, 행사 전 흐름"이다.
- 도움말 "방문 인구는 어떤 숫자인가요?": "하루 동안 시간대별로 머문 인구를 모두 더한 값이라 실제 방문한 사람 수보다 큽니다. 크기보다 늘고 줄어든 흐름을 보세요."
- 도움말 "비교 지역이란?": 두 선이 행사 전에는 나란히 가다가 행사 달에 벌어지는 그림(인라인 SVG, 화면 도움말 전용)과 함께 "행사 전에는 나란히 움직이던 두 읍면이 행사 달에 벌어진 폭을 봅니다. 날씨나 관광 경기처럼 두 읍면에 함께 닥친 변화는 두 선을 같이 움직이므로 폭에 남지 않습니다. 다만 행사 말고 다른 일이 그 읍면에만 있었다면 폭에 섞일 수 있습니다."
- AI가 기다리는 동안: 작업 영역 위에 "방문 인구를 읽고 AI가 비교할 읍면을 고르고 있습니다." 작업 기록이 실시간으로 쌓인다.
- 방문이 늘지 않았을 때: 판단 문장을 주황으로 "[AI 판단] 행사 기간 하루 방문 인구가 행사 전과 비슷했습니다. 카드 데이터에서도 차이를 찾기 어려울 수 있습니다." 버튼은 "다른 행사 고르기"(주 버튼)와 "그래도 비교하기"(보조 버튼)다.
- 비교 후보가 모자랄 때: ② 자리에 "비교할 수 있는 읍면이 2곳보다 적어 계산할 수 없습니다. 뺀 까닭은 아래와 같습니다."와 뺀 읍면 목록, "다른 행사 고르기" 버튼(30번 2-1절 위험 3).
- 방문 인구 자료가 없을 때: "{{조회 기간}} 대정읍 방문 인구를 받지 못했고 저장된 자료에도 없습니다. 인터넷 연결을 확인하고 [다시 받기]를 누르거나 다른 행사를 골라 주세요."
- 허브가 느릴 때(같은 요청이 502를 냈다가 다시 하면 되는 일이 잦음, 40번 3절): 대기 문구 "제주데이터허브에서 방문 인구를 받고 있습니다. 서버가 바쁘면 몇 번 다시 요청합니다." 다시 요청할 때마다 작업 기록에 "[외부 전송] open.jejudatahub.net 응답 오류로 {{n}}번째 요청" 한 줄.
- 작업 기록 예: "[코드 계산] 저장된 자료에서 대정읍 방문 인구 {{n}}일치를 읽었습니다." "[AI 판단] 행사 기간에 방문이 늘었다고 판단했습니다." "[코드 계산] 나머지 11개 읍면의 행사 전 흐름이 닮은 정도를 계산했습니다." "[AI 판단] 표선면은 같은 달 ‘○○축제’가 열려 비교에서 뺐습니다." "[AI 판단] 비교 순서를 안덕면, 한경면, 남원읍으로 정했습니다."
- 완료 기준: 시험 행사 5개 모두에서 그래프, 판단 문장, 후보 3곳, 뺀 읍면 이유가 1920×1080 화면에 스크롤 없이 들어간다.

### 4-4. 센터 파일 넣기

```
| 센터에서 받아 올 카드 데이터                                                     |

| +---------------------------------------------------------------------------+ |

```

계산 계획 상자의 문구는 상태에 따라 바뀐다.

| 상태 | 문구 | 색 |
|---|---|---|
| 세우는 중 | AI가 계산 계획을 세우고 있습니다. 계획은 공개 명세와 가상 데이터만 보고 만듭니다. | 회색 |
| 고치는 중 | 가상 데이터로 미리 돌려 보다가 문제가 나서 고치고 있습니다({{n}}번째 시도, 최대 3번). | 회색 |
| 준비됨 | 계산 계획이 준비됐습니다. 가상 데이터로 {{n}}번째 시도에 문제없이 돌아갔습니다. 이제 센터 파일을 넣어도 됩니다. 파일이 들어오면 외부 AI 연결을 잠그고, 이후 계산은 이 PC 안에서만 합니다. | 초록 |
| 미리 만든 계획 | 미리 만든 계획을 씁니다. AI에 묻지 않았습니다. | 회색 |
| 3번 모두 실패 | AI가 세운 계획이 가상 데이터에서 3번 모두 문제를 냈습니다. [다시 시도] 그리고 미리 만든 계획이 있으면 [미리 만든 계획으로 계속], 없으면 [다른 행사 고르기] | 빨강 |

- 계획이 준비되기 전에는 끌어다 놓는 칸을 흐리게 하고 "계산 계획이 준비되면 파일을 넣을 수 있습니다. 센터 파일이 들어오면 AI 연결을 잠그기 때문에 AI가 할 일을 먼저 끝냅니다."라고 쓴다.
- 첫 파일이 들어가면 띠가 잠김으로 바뀌고, 작업 영역 맨 위에 한 번 "센터 데이터가 들어와 외부 AI 연결을 잠갔습니다. 지금부터 인터넷으로 나가는 요청은 없습니다."가 뜬다.
- 연월은 파일 이름이 아니라 파일 안의 base_year_month로 판별해 맞는 줄에 체크한다(파일 이름은 내려받은 시각이라서, 40번 3절).
- 파일마다 결과를 끌어다 놓는 칸 아래 목록으로 보여 준다. 문구는 다음과 같다.
  - 다른 데이터: "{파일 이름}: 「카드 이용 현황(읍면동)_v02」 파일이 아닙니다. 열 이름이 다릅니다. 조회 화면에서 데이터 이름을 확인해 주세요."
  - 엑셀로 다시 저장한 파일: "{파일 이름}: 엑셀에서 열었다가 저장한 파일로 보입니다(글자 형식이 바뀌었습니다). 센터에서 내려받은 원래 파일을 넣어 주세요."
  - 같은 달 두 번: "2024년 4월 파일을 새로 넣은 파일로 바꿨습니다."
  - 필요 없는 달: "2023년 8월 파일은 이번 계산에 쓰지 않습니다."
  - CSV가 아님: "{파일 이름}: CSV 파일이 아닙니다. Results_로 시작하는 CSV 파일을 넣어 주세요."
- "계산 시작"은 계획이 준비되고 필수 달이 모두 들어왔을 때 눌린다. 필수가 아닌 달이 빠지면 버튼 옆에 "행사 없던 달로 시험할 2023년 11월 파일이 없습니다. 없이 계산하면 그 시험을 건너뜁니다."라고 쓰고 버튼은 그대로 눌리게 둔다. 어느 달이 필수인지는 분석 설계에서 정한다.
- 예시 경로: 상단에 "예시에서는 동봉한 가상 카드 데이터를 넣습니다. 실제로는 센터 조회 화면에서 받은 파일을 넣는 자리입니다." 계획이 준비되면 서버가 가상 파일을 넣고 줄이 하나씩 "확인됨"으로 바뀐다. 끌어다 놓는 칸은 흐리게 둔다.
- "목록 인쇄"는 브라우저 인쇄(window.print)를 부른다. 인쇄할 때는 행사 이름, 날짜, 데이터 이름, 조건, 받을 달 표, "센터 조회 화면에서 받는 법"만 찍히게 한다. 체크리스트를 PDF로 만드는 기능은 따로 만들지 않는다.
- 도움말 "센터 조회 화면에서 받는 법": "1. 센터 조회 화면에서 데이터 「카드 이용 현황(읍면동)_v02」를 고릅니다. 2. 기간을 위 표의 달 하나로 정합니다. 3. 조건은 걸지 않고 조회합니다. 4. CSV로 내려받습니다. 파일 이름은 받은 시각으로 붙으므로, 몇 월 파일인지는 이 프로그램이 파일 안을 보고 알아냅니다."
- 도움말 "집에서 계획을 세웠다면": "센터에는 CSV 파일만 가지고 들어갈 수 있습니다. 이 목록을 인쇄해 가거나, 센터 PC에서 같은 행사를 다시 고르면 같은 달 목록이 나옵니다." 이 문장이 참이려면 받을 달 목록을 AI가 아니라 코드가 행사 날짜에서 규칙으로 정해야 한다(11절에서 맞출 것).
- 완료 기준: 가상 파일 여러 개를 한 번에 넣으면 연월이 파일 안 값으로 맞게 체크되고, 한 달을 빼면 그 줄이 빨간 "없음"으로 남는다. 엑셀로 다시 저장한 파일, 다른 데이터 파일, 같은 달 두 번에 위 문구가 뜨고 문구에 셀 값이 없다. 첫 파일이 들어간 뒤로 외부 전송 기록이 늘지 않는다.

### 4-5. 계산 진행 (누를 것 없음)

```
| 이 PC 안에서 계산하고 있습니다. 인터넷으로 나가는 요청은 없습니다.                   |
| [끝남]   센터 파일 {{n}}개 합치기와 형식 검사                                     |
| [끝남]   행사 전 흐름 확인: 1순위 안덕면이 맞지 않아 2순위 한경면으로 바꿨습니다       |
| [진행 중] 두 읍면의 변화 차이 계산                                               |
| [기다림] 행사 없던 달로 같은 계산 해 보기                                          |
| [기다림] 10 미만 칸 처리                                                        |
| [기다림] 그림과 보고서 만들기                                                    |
```

- 계산이 끝나면 결과 화면으로 저절로 넘어간다. 이 계산은 외부 AI를 부르지 않아 짧게 끝날 것으로 본다(추정).
- 실패하면 그 줄을 빨갛게 하고 이유와 할 일을 쓴다. 예: "이용 금액 use_amt 열에 숫자로 읽을 수 없는 값이 있습니다. 센터에서 내려받은 원래 파일인지 확인해 주세요." 버튼은 "끝내기"다. 서버의 예상하지 못한 오류는 "예상하지 못한 문제가 생겼습니다. 작업 기록 맨 아래에 문제 종류를 적었습니다."로만 보여 주고, 오류 원문을 화면에 그대로 찍지 않는다.
- 완료 기준: 일부러 깨뜨린 가상 파일로 돌렸을 때 오류 문구와 작업 기록에 셀 값이 없고, 성공하면 결과 화면이 저절로 열린다.

- 왼쪽 아래 행동 막대에는 "이전"을 두지 않는다. 잠긴 뒤라 앞 단계로 돌아갈 수 없기 때문이다.
- 차이가 없을 때: 맨 위 문장이 "행사 달 대정읍의 관광객 카드 이용 증가율은 비교 읍면(한경면)과 뚜렷한 차이가 없었습니다(차이 {{차이}}퍼센트포인트).¹"이 된다. 빨간 오류처럼 보이지 않게 회색 "차이 없음" 꼬리표를 쓰고, 도움말 "차이가 없다는 결과도 보고서에 쓸 수 있습니다. 판단 기준은 근거표 1번에 있습니다."를 단다. "뚜렷한 차이"의 기준은 분석 설계에서 정한다.
- 결과를 낼 수 없을 때: 맨 위 문장이 "결과를 내지 않았습니다."이고 이유가 한 줄 붙는다. "1~3순위 비교 읍면 모두 센터 데이터의 행사 전 흐름 확인에서 맞지 않았습니다." 또는 "10 미만 칸 때문에 비교 읍면이 모두 빠졌습니다." 버튼은 "끝내기"이고 저장과 반출 단계는 건너뛴다.
- 미리 만든 계획일 때: 꼬리표가 "[미리 만든 계획]"이 되고 그 옆에 "이 결과의 계획은 AI 연결 없이 미리 만들어 둔 것입니다."를 쓴다.
- 행사 없던 달 파일이 없을 때: 가운데 카드가 "해당 달 파일이 없어 하지 못했습니다."가 된다.
- 완료 기준: 효과를 심은 가상 판에서 "높았습니다", 심지 않은 판에서 "뚜렷한 차이가 없었습니다"가 나온다. 근거표의 숫자가 스프레드시트 손계산과 같다. 화면 문장의 숫자 개수와 근거표 줄 수가 같다.

- 배지 세 가지: 초록 "반출 신청 가능(사전 점검 기준)"과 이유 "비율과 증감률만 담았고, 10 미만 칸이 없고, 합계를 싣지 않았습니다." 파랑 "공개 데이터 그림"과 이유 "제주데이터허브 공개 데이터로 그렸습니다. 10 미만 기준은 해당하지 않습니다." 주황 "반출 어려움: 10 미만 칸 {{n}}개 남음"(점검이 실패할 때만). "통과"라는 말은 쓰지 않는다(16번).
- 쓰임 목록: "행사 결과보고서", "다음 해 예산 요구 자료", "현황자료", "직접 쓰기". 고르면 글상자의 마지막 빈칸만 바뀐다. 이 빈칸 채우기는 브라우저 안에서 하고 외부 AI로 보내지 않는다. 문안의 나머지는 잠금 전에 AI가 쓴 틀에 코드가 행사 이름을 넣은 것이고 센터 숫자는 들어가지 않는다.
- "복사"를 누르면 버튼 옆에 "복사했습니다."가 2초 뜬다. 127.0.0.1은 브라우저가 안전한 주소로 취급해 클립보드 쓰기가 될 것으로 본다(기억 기반). 실패하면 글상자의 글을 모두 선택해 두고 "Ctrl+C를 눌러 복사하세요."라고 쓴다.
- "열어 보기"는 새 탭에서 브라우저 내장 PDF 보기와 그림 보기로 연다. "폴더 열기"는 서버가 파일 탐색기를 연다. 실패하면 "폴더를 열지 못했습니다. 위 경로를 파일 탐색기 주소창에 붙여 넣어 주세요."
- 공개 데이터 그림의 "활용 데이터" 칸에 무엇을 넣을지는 확인하지 못했다(11절).
- 예시 경로: 카드마다 "예시(가상 데이터)" 꼬리표를 달고, 맨 위에 "예시 결과물은 실제 센터 데이터가 아니므로 반출 신청 대상이 아닙니다. 실제로 쓸 때의 모습을 보여 드립니다."를 쓴다.
- 도움말 "반출 신청은 어떻게 하나요?": "센터 시스템에서 반출 신청을 열고, 결과 폴더의 파일을 올린 뒤 위 값을 넣습니다. 심사 결과는 최대 5일(평균 3일) 안에 이메일과 문자로 옵니다. 승인되면 마이페이지에서 내려받습니다. 퇴실하면 반출 승인 자료 외에는 지워지므로 나가기 전에 신청을 끝내세요." 근거는 00번 4·5절과 16번 2-2절 10번이다.
- 완료 기준: "열어 보기"로 PDF가 한글 깨짐 없이 열리고, "복사" 뒤 메모장에 붙이면 문안이 그대로 나오며, 배지 판정이 반출 점검 결과와 같다.

### 4-8. 끝내기 대화상자

결과 삭제가 켜져 있을 때:

```
| 작업을 끝냅니다                                                   |
| 아래 파일을 지웁니다.                                              |
|  - 넣은 센터 파일 복사본 {{n}}개                                    |
|  - 계산 중간 파일                                                  |
|  - 작업 기록과 외부 전송 기록                                        |
| 결과 폴더에 남는 파일: 성과보고서 PDF 1개, 그림 png {{n}}개             |
| [ ] 결과 PDF와 png도 지웁니다. 반출 신청을 마쳤다면 체크하세요.          |
| [돌아가기]                                         [지우고 끝내기]  |
```

- 지운 뒤 작업 영역: "다 지웠습니다. 지운 파일 {{n}}개, 남긴 파일 {{m}}개(결과 폴더). 센터에서 내려받은 원래 CSV는 다운로드 폴더에 남아 있을 수 있습니다. 이 프로그램이 만든 파일이 아니라 지우지 않았습니다. 새로 시작하려면 [처음으로]를 누르세요. 프로그램을 끄려면 검은 창을 닫으세요."
- 결과 삭제가 꺼져 있을 때: "결과 삭제가 꺼져 있어 아무 파일도 지우지 않습니다. 남는 곳: {{작업 폴더}}, {{결과 폴더}}. 퇴실할 때 센터 규칙에 따라 지워질 수 있습니다." 버튼은 "돌아가기", "지우지 않고 끝내기", "켜고 지우기"다.
- 사용자 확인 없이 지우지 않는다(14번 4-3절).
- 결과 그림과 PDF를 보낼 때 서버는 브라우저가 저장하지 않게 하는 머리말(Cache-Control: no-store)을 붙인다. 그렇지 않으면 지운 뒤에도 브라우저 캐시에 결과 그림이 남는다. 16번 1-13절이 삭제 대상에 브라우저 저장소까지 넣었기 때문이다. 화면은 localStorage 같은 브라우저 저장소를 쓰지 않는다.
- 완료 기준: 지운 뒤 작업 폴더에 파일이 0개이고, 체크하지 않으면 결과 폴더 파일이 남는다. 결과 그림 응답 머리말에 no-store가 있다.

### 4-9. 외부 전송 기록 대화상자

```
| 외부로 보낸 것 (외부 전송 기록)                                                     |
| 이번 실행에서 {{n}}건을 보냈고, 센터 데이터가 든 요청은 0건입니다.                     |
| 센터 파일이 들어온 {{잠긴 시각}}부터는 보낸 것이 없습니다.                             |
| +----------+----------------------+---------------------------+----------+------+ |
| | 시각      | 받는 곳                | 보낸 것                     | 센터 데이터 | 전문  | |
| | 10:12:03 | api.anthropic.com    | 행사 이름·기간·주관으로 장소 묻기 | 없음      | 보기  | |
| | 10:12:40 | open.jejudatahub.net | 대정읍 방문 인구 받기          | 없음      | 보기  | |
| +-------------------------------------------------------------------------------+ |
| 자가 점검: 표시값을 심은 가상 센터 파일로 처음부터 끝까지 돌린 뒤,                       |
| 외부로 보낸 요청에서 그 표시값을 찾습니다.                          [자가 점검 실행]   |

```

- "보기"를 누르면 그 요청에 실제로 보낸 내용 전문이 표 아래에 펼쳐진다(details 요소).
- 빈 상태: "아직 외부로 보낸 것이 없습니다."
- 자가 점검이 도는 동안: "자가 점검 중입니다." 결과가 0건이 아니면 빨강으로 "표시값이 {{n}}건 발견됐습니다. 센터 데이터를 다루지 말고 담당자에게 알려 주세요."
- 완료 기준: 예시를 한 번 돌린 뒤 기록 건수가 띠의 숫자와 같고, 잠긴 시각 이후 기록이 0건이며, 자가 점검 결과가 화면에 뜬다.

### 4-10. 도움말 대화상자

- "처음 쓰는 분께" 세 줄: "1. 처음이라면 예시로 해 보기를 누르세요. 2. 노란 상자는 AI가 짐작한 것이라 확인이 필요합니다. 3. 센터 데이터가 들어오면 외부 AI 연결이 잠기고 모든 계산은 이 PC에서 합니다."
- 용어 풀이 표(7절의 화면 용어와 풀이).
- 데이터 기준: 행사 목록 수집일, 저장된 방문 인구 저장일, 가상 카드 데이터라는 표시.

### 4-11. 모든 화면에 공통인 오류

- 서버와 연결이 끊김: 띠 아래에 빨간 줄 "프로그램과 연결이 끊겼습니다. 검은 창(run.bat)이 열려 있는지 확인하고, 닫혔다면 run.bat을 다시 실행한 뒤 이 화면을 새로고침(F5)하세요."
- 새로고침: 서버가 지금 단계를 기억하므로 같은 화면이 다시 열린다.
- 브라우저 탭을 두 개 열었을 때: 같은 서버 상태를 보므로 두 탭이 같은 화면을 보인다. 따로 막지 않는다.

## 6. 정적 HTML 구현 방식

### 6-1. 파일 구성 (추천안 기준)

- app/static/index.html: 여섯 단계의 영역(section)과 대화상자 세 개(끝내기, 외부 전송 기록, 도움말)를 모두 담는다. 지금 단계가 아닌 영역은 hidden 속성으로 숨긴다.
- app/static/app.js: 상태 조회, 단계 전환, 화면 채우기, 파일 보내기.
- app/static/app.css: 세 칸 격자 배치, 띠 색, 인쇄용 규칙.
- 외부 주소는 하나도 쓰지 않는다. 글꼴은 시스템 글꼴, 그림은 서버 png, 자물쇠 같은 작은 그림은 인라인 SVG다.
- 브라우저 기본 기능으로 해결한다. 대화상자는 dialog 요소, 펼침은 details 요소, 파일 고르기는 input type="file" multiple, 끌어다 놓기는 drop 이벤트, 복사는 navigator.clipboard, 인쇄는 window.print와 인쇄용 CSS를 쓴다. 화면 프레임워크와 빌드 도구는 쓰지 않는다.
- 이미 만든 index.html에서 유지할 것은 제목, 소개 문장, 띠 요소(id="band"), 글꼴 지정, "예시로 해 보기" 버튼이다. 바꿀 것은 너비 960px 한 칸 배치(세 칸 격자로), /api/health 호출(상태 조회로), 띠 문구("공개 데이터 모드: 외부 AI 연결 가능"을 3-2절 문구로)다.
- 규모는 index.html 약 250줄, app.js 약 450줄, app.css 약 200줄로 본다(추정). 일수는 30번의 로컬 웹 화면 0.5일에 ADR-148의 "Streamlit보다 약 1일 더"를 더해 약 1.5일로 본다(팀 추정을 그대로 씀).
- 화면 전체 완료 기준: static 폴더 안에 "http://"나 "https://"로 시작하는 주소가 0개다. 예시 경로에서 결과 화면까지 네 번 누른다. 1536×750 창에서도 행동 막대 버튼이 가려지지 않는다. 계산 도중 새로고침해도 같은 화면과 작업 기록이 돌아온다.

### 6-2. 선택지 비교 (모두 사용자 결정 필요)

## 8. 기획서 첫 쪽 그림과 화면 캡처 계획

### 8-1. 첫 쪽 그림

30번 6-1절의 구성을 따르고, 화면 설계에서 정할 것만 더했다.

- 맨 위: 이름 「행사 효과 나란히」와 한 문장 정의.
- 왼쪽 4분의 1: 선으로 그린 단순한 사람 그림, "축제 담당 공무원" 글자, 말풍선 "축제 덕분에 지역 소비가 늘었나?"
- 가운데 2분의 1: 결과 화면의 월별 두 선 png(앱이 만든 그림 그대로, "예시(가상 데이터)" 글자 포함)와 두 선 사이 폭에 "이 차이를 봅니다" 주석. 아래에 방문 인구 png를 작게 붙인다. 방문 인구 그림은 실제 허브 값이다(30번 6-2절).
- 오른쪽 4분의 1: 저장과 반출 화면 캡처에서 잘라 낸 PDF 미리보기, 반출 배지, 활용 사유 상자.
- 아래 띠 두 칸: 왼쪽 "공개 데이터(축제 정보, 방문 인구): AI가 직접 보고 비교 읍면을 고릅니다", 오른쪽 "센터 카드 데이터: 이 PC 안의 코드만 계산합니다. 외부 전송 0건". 오른쪽 칸 바로 위에 상단 띠 캡처(잠김 상태)를 가로로 붙인다.
- 그림 안 문장은 한 덩이에 30자 안쪽으로 둔다. 상호평가에서는 두 기획서를 나란히 보므로 첫 쪽이 작게 보일 것으로 본다(추론).
- 만드는 방법: 앱이 만든 png 두 장과 캡처 두 장을 슬라이드 도구에 배치한다. 이 그림을 위한 코드는 만들지 않는다.

## 10. 아키텍트와 맞출 화면별 API 목록

실행은 한 번에 하나만 있다고 보고 실행 번호를 두지 않았다. 127.0.0.1에서 한 사람이 쓰는 프로그램이기 때문이다. 오류 응답은 이용자에게 보일 한국어 문구를 message 필드에 담는다.

| 화면 | 호출 | 보내는 것 | 받는 것 |
|---|---|---|---|
| 모든 화면 | GET /api/status?after={번호} | 마지막으로 받은 작업 기록 번호 | step(지금 단계), mode(example 또는 real), band{example, center_loaded, locked, plan_source(ai 또는 prepared), ai_key, ai_failed, sent_total, sent_center, delete_on}, job{name, state(running, done, failed), stage, message}, log[{seq, at, kind(ai, code, check, user, send, warn, prepared), text}], log_next |
| 첫 화면 | POST /api/start | example(참·거짓) | step, 예시면 event와 place(장소 확인 화면에 바로 쓸 값) |
| 행사 고르기 | GET /api/events?q=&year=&only_ok= | 검색어, 연도, 볼 수 있는 것만 | source_note, items[{id, name, start, end, days, organizer, host, ok, reason, short, prepared}] |
| 행사 고르기 | POST /api/event | event_id | event{...}, place{emd 또는 비어 있음, kind(eupmyeon, dong, unknown), reason, source(ai 또는 prepared)} |
| 장소 확인 | POST /api/place | emd | visit{chart_url, increased, segments[{text, basis_id}], source_note}, candidates[{rank, emd, reason, same_month_event, chart_url}], excluded[{emd, reason}], enough |
| 방문과 비교 확인 | POST /api/compare | order[emd 순서] | checklist{dataset, condition, unit, months[{ym, purpose, required}]}. 이 호출이 계산 계획 작업을 서버 뒤에서 시작하고 진행은 status의 job으로 본다. 예시면 계획이 끝난 뒤 서버가 가상 파일을 넣는다 |
| 센터 파일 넣기 | PUT /api/files/{파일 이름} | 파일 내용을 요청 본문 그대로 | {ym, status(ok, replaced, unneeded, error), message}. 계획이 준비되기 전이면 409와 message. 첫 파일이 들어오는 순간 잠근다 |
| 센터 파일 넣기 | GET /api/files | 없음 | months[{ym, purpose, required, status(ok, missing), file}], ready |
| 센터 파일 넣기 | POST /api/calculate | 없음 | 202. 진행은 status의 job |
| 결과 | GET /api/result | 없음 | verdict(higher, lower, no_diff, none), headline_segments[{text, basis_id}], chips{example, plan_source}, chart_url, checks{pretrend{text, swapped}, placebo{text 또는 비어 있음}, masking{text}}, limits{can[], cannot[]}, basis[{id, value_text, meaning, method, source, masking}], code_number_count, ai_number_count(늘 0), none_reason |
| 저장과 반출 | GET /api/outputs | 없음 | folder, files[{name, kind(pdf, png), title, url, badge{level(ok, public, warn), text, reason}}], reason_template(마지막 빈칸 하나), usage_options[], form{title, description, files[{name, data_name, category}]} |
| 저장과 반출 | GET /out/{파일 이름}, GET /work/{그림 이름} | 없음 | 파일. 머리말 Cache-Control: no-store |
| 저장과 반출 | POST /api/open-folder | 없음 | ok, message |
| 외부 전송 기록 | GET /api/sent | 없음 | items[{at, host, purpose, center_data(늘 거짓), body}], locked_at, selfcheck{at, markers_found} 또는 비어 있음 |
| 외부 전송 기록 | POST /api/selfcheck | 없음 | 202. 진행은 status의 job, 결과는 GET /api/sent |
| 상단 띠 | PUT /api/settings | delete_on | band |
| 끝내기 | GET /api/finish | 없음 | delete_on, delete[{label, count}], keep[{label, count}], folders[] |
| 끝내기 | POST /api/finish | delete_outputs(참·거짓) | deleted, kept, note |

- 이미 있는 /api/health는 화면이 쓰지 않게 된다. 남길지 지울지는 아키텍트가 정한다.
- 잠긴 뒤 /api/event, /api/place, /api/compare처럼 AI를 부르는 호출은 서버가 409로 거절한다.
- 결과 문장은 서버가 숫자를 채운 조각(segments)으로 보내고, 화면은 basis_id가 있는 조각 뒤에만 위 첨자 번호를 붙인다. 화면이 숫자를 조합하지 않게 하려는 것이다.

## 11. 다른 설계자와 맞출 것, 확인하지 못한 것

### 11-1. 맞출 것

- 아키텍트: 2-3절의 잠금 규칙(계획을 파일보다 먼저, 잠긴 뒤 AI 호출 거절, 잠금 해제 조건), 상태 조회 하나로 진행과 복원 처리, 파일을 요청 본문으로 받기, 결과 파일의 no-store 머리말, 폴더 열기, 사용자 이름이 없는 설치·결과 폴더 경로.
- AI 엔지니어: 같은 달 다른 행사가 있는 읍면을 빼려면 그 달 행사들의 장소도 AI가 함께 짐작해야 한다. 행사 파일에 장소 열이 없기 때문이다. 방문 증가 판단 문장도 숫자는 코드가 채워야 "AI가 쓴 숫자 0개" 배지가 참이 된다. 결과 문장 틀, 한계 문장, 활용 사유 틀은 잠금 전 계획 단계에서 나와야 한다. 작업 기록 문장과 꼬리표를 어디서 만들지 정해야 한다.
- 분석 설계자: 받을 달 규칙(행사 날짜에서 코드가 정해 재실행 때 같은 목록이 나오게), 필수 달과 아닌 달, 볼 수 있는 행사의 기준(행사 전 몇 달), "뚜렷한 차이"의 판정 기준, 증가율과 차이의 정의 문장, 예시 행사 선택.
- 컴플라이언스: 공개 데이터 그림 png의 반출 신청 "활용 데이터" 칸 값, 배지 문구.
- 기획서 담당: 8절의 첫 쪽 그림 구성과 캡처 12장.
