# 50. 개발 계획서 초안: 「행사 효과 나란히」

작성: 통합 PM, 2026-11-13 20시 무렵. 근거는 40_plan_brief.md(원칙), 설계 문서 7개(41~47), 00·30·21·16번의 해당 절, app/ 아래 기존 코드와 오늘 직접 확인한 것이다. 오늘 직접 확인한 것은 다음 다섯 가지이고, 본문에서 "오늘 확인"이라고 적는다. (1) 행사 파일에서 43번의 분석 가능 규칙을 만족하는 행사가 52건이다. (2) 맥에서 pip 시험 해석(설치하지 않는 dry-run)으로 통일한 패키지 목록이 윈도우용 휠 26개(공식 SDK를 넣으면 33개)로 풀린다. (3) PyPI 메타데이터로 fpdf2 2.9.0이 LGPL-3.0-only이고 anthropic 2.8.0이 Apache-2.0이다. (4) 허브 수집기는 20:03 기준 한림읍·애월읍을 끝냈고 구좌읍을 받는 중이며, 오늘 로그에 6번 연속 실패로 멈춘 기록이 2번 있다(수집기는 멈추면 다시 실행할 때 마지막 날짜 다음부터 이어 받는다). (5) 시험 행사 후보 주변 기간에 같은 지역 이름이 든 행사가 있는지 행사 파일을 이름으로 검색했다. Anthropic 참고 자료의 사실(모델별 제한, 가격)과 한림읍 스냅샷 행 수는 오케스트레이터가 오늘 확인해 넘긴 것을 그대로 썼다. 코드는 만들거나 고치지 않았다. 유료 API는 부르지 않았다.

이 문서에서 쓰는 말은 처음 나올 때 풀어 쓴다. 자주 쓰는 말 다섯 개만 먼저 정한다.

- **설계 결정 기록(ADR)**: 사용자가 노션 「설계 결정 로그」에 남기는 결정 기록이다. ADR-147은 주제, ADR-148은 화면 기술(FastAPI와 정적 HTML), ADR-149는 설치 방식(Python 통째 동봉)이다.
- **계획 묶음**: LLM(외부 언어 모델, 여기서는 Claude)이 공개 정보만 보고 낸 판단 전부를 담은 JSON 하나다. 센터 CSV를 넣은 뒤의 계산은 이 묶음만 보고 돈다.
- **리허설**: 센터 형식 그대로 만든 가상 카드 CSV에 계획 묶음을 실제로 돌려 보는 것이다.
- **잠금**: 센터 형식 CSV를 읽기 직전에 외부 통신 모듈이 모든 외부 요청을 거절하게 되는 상태다.
- **판**: 가상 카드 데이터의 한 벌이다. 효과를 심은 판, 심지 않은 판, 리허설용 판이 있다.

## 2. 제품 정의

### 2-1. 이용자

- 실제 이용자는 행정시·읍면 축제 담당 공무원, 축제추진위원회 사무국, 관광 관련 협회 직원이다. 결과보고서나 다음 해 예산 요구 자료에 숫자 한 줄과 그림 한 장이 필요하다(30번).
- 심사위원은 매뉴얼대로 설치한 뒤 "예시로 해 보기"를 누르고 3~5분 안에 판단한다. 오류가 나도 참가자에게 묻지 않는다(00번). 상호평가 투표자는 기획서 PDF의 캡처만 본다.

### 2-2. 이용자 흐름

**예시 경로(심사위원).** 누르는 횟수는 결과 화면까지 네 번, 활용 사유 복사까지 여섯 번이다.

1. 첫 화면에서 "예시로 해 보기"를 누른다. 예시 행사(14절 결정 1, 추천은 가파도청보리축제)가 골라진다.
2. 장소 확인 화면에서 AI가 추정한 개최 읍면(노란 상자, 이유 포함)을 보고 "장소 확인"을 누른다.
3. 서버가 방문 판단과 비교 읍면 고르기(LLM 단계 1·2)를 돌린다. 방문 인구 그래프, 방문 판단 문장, 비교 읍면 1~3순위와 이유, 뺀 읍면과 이유가 나온다. "이 순서로 비교하기"를 누른다.
4. 받아 올 센터 파일 체크리스트가 나오고, 그동안 서버가 계산 계획(LLM 단계 3)을 세워 리허설하고 고친다. 계획이 준비되면 서버가 동봉 가상 CSV를 넣고, 상단 띠가 "센터 데이터 모드: 외부 AI 연결 잠김"으로 바뀐다. "계산 시작"을 누른다.
5. 결과 화면이 나온다. 결과 문장(숫자는 코드가 채움), 월별 두 선 그래프, 행사 전 흐름 확인과 1순위 교체 기록, 행사 없던 달로 한 시험, 작은 칸 처리, 말할 수 있는 것과 없는 것.
6. "저장과 반출로"를 누르면 결과 파일, 반출 배지, 활용 사유 문안이 나온다. "복사"를 누른다. "끝내기"는 지울 목록을 보여 주고 확인을 받은 뒤 지운다.

**직접 분석 경로(집에서 계획).** "직접 분석하기"를 누르고 행사 목록에서 행사를 고른다. 목록은 행사마다 "볼 수 있음", "희석 주의", "볼 수 없음"과 이유를 보여 준다. 이후 2~4단계는 예시와 같다. 4단계의 체크리스트를 인쇄하거나 적어 둔다.

**실제 센터 경로.**

1. 센터 PC에서 같은 프로그램을 켜고 같은 행사를 고른다. 공개 단계(장소 확인, 방문 판단, 비교 읍면, 계산 계획)는 공개 정보만 외부로 보내므로 센터 PC에서 다시 돌려도 된다. 집에서 만든 파일을 들고 갈 필요가 없다("반입은 CSV만" 규칙).
2. 받을 달 목록은 코드가 행사 날짜에서 규칙으로 정하므로(14절 결정 6의 추천안) 집에서 본 체크리스트와 같다.
3. 센터 조회 화면에서 「카드 이용 현황(읍면동)_v02」를 조건 없이 한 달씩 받거나, 달이 많으면 운영자에게 요청해 바탕화면 "요청파일" 폴더로 받는다.
4. 받은 CSV를 프로그램에 넣는다(넣는 방법은 14절 결정 16). 첫 파일을 읽기 직전에 잠긴다. 연월은 파일 이름이 아니라 파일 안의 base_year_month로 판별한다.
5. "계산 시작"을 누르면 이 PC 안에서만 계산한다. LLM 호출은 없다.
6. 결과 PDF·png를 센터 반출 시스템에 올려 반출 신청을 한다. 활용 사유 문안과 반출 신청 항목(제목, 설명, 파일별 활용 데이터와 구분)을 복사해 넣는다.
7. "끝내기"로 작업 기록, 외부 전송 기록, 메모리의 센터 집계를 지운다. 반출 신청을 마쳤으면 결과 파일도 함께 지운다.

## 3. 구조와 인터페이스

### 3-1. 경계 규칙

QA가 정적 검사 한 줄로 확인할 수 있게 단순하게 둔다.

1. 네트워크 모듈(anthropic, urllib.request, http.client, httpx, socket)을 불러오는 런타임 파일은 egress.py 하나다. tools/는 런타임에서 불러오지 않으므로 예외다.
2. agent.py의 함수는 공개 자료형만 받는다. 센터 집계(CardTable)와 계산 결과(Result)를 받는 함수를 agent.py에 만들지 않는다.
3. CardTable은 calc.py와 report.py로만 간다. API 응답, 작업 기록, 파일에 CardTable 원본을 넣지 않는다.
4. 잠금은 card.py가 파일을 열기 직전에 server.py가 건다. `egress.unlock()`은 `server.reset()` 안에서만 부른다.
5. 디스크 쓰기는 `config.out_path()`를 거쳐 app/out 아래로만 한다.

### 4-1. LLM이 판단하는 일과 흐름

| 단계 | 언제 | 입력(모두 공개 정보) | LLM이 내는 것 | 실패 때 |
|---|---|---|---|---|
| 장소 추정표 | 개발 때 한 번(결정 7 추천안) | 행사 213건의 이름, 날짜, 주관·주최 | 행사마다 장소(읍면 12곳, 동 지역, 여러 곳, 도 전역, 모름), 구체 장소, 종류(축제, 공연·전시, 상시·장기 운영, 기타), 확신도, 이유 | 60건씩 4번 보낸다. 검사를 못 넘은 묶음은 "모름"으로 저장하고 이용자가 장소를 고르게 한다 |
| 장소 확인 | 실행 때 | 장소 추정표 한 줄 | 없음(LLM 호출 없음) | "동 지역"이면 계산할 수 없다고 알린다 |
| 단계 1 방문 판단 | "장소 확인" 뒤 | 행사 읍면 일별 방문 인구, 코드가 계산한 요약값(**직전 4주 같은 요일 대비 비율, 비교 후보 가운데 값 대비 상대 비율**) | 증가 뚜렷, 약함, 없음, 판단 불가 중 하나와 근거 키, 이유 | "증가 없음"이면 경고하고 이용자가 계속할지 고른다(막지는 않는다) |
| 단계 2 비교 읍면 | 단계 1 바로 뒤, 같은 대화 | 코드가 계산한 거리 표, 같은 기간 행사와 추정 장소 | **규칙 밖의 추가 제외와 이유, 남은 후보의 이유.** 순위는 코드가 거리 순으로 정한다(결정 6 추천안) | 남은 후보가 2곳 미만이면 "비교할 수 있는 읍면이 부족합니다"로 멈춘다 |
| 단계 3 계산 계획과 문장 틀 | "이 순서로 비교하기" 뒤, 같은 대화 | 확정된 행사·후보, 코드가 정한 달, 업종 목록, 빈칸 목록 | **업종 범위와 이유, 경우별 결과 문장 4가지, 방법 문단, 이 행사만의 한계(많아야 3개).** 42번의 단계 3과 4를 합쳤다 | 리허설과 검사를 3번째 제출까지 못 넘으면 대체 경로. 문장 틀만 못 넘으면 그 칸을 기본 문장으로 바꾼다 |

- **42번의 4단계를 3단계로 줄였다.** 달·지표·이용자 구분을 코드가 정하면(결정 6) 계산 계획에서 LLM이 정할 것이 업종 범위뿐이라 문장 틀 단계와 합쳐도 된다. 대화가 짧아지고 호출이 줄어든다.
- 화면이 단계 2와 3 사이에서 이용자 확인을 받으므로, 대화 객체(messages 배열)를 작업 상태에 메모리로 들고 있다가 단계 3에서 이어 쓴다.
- 섬 지역(우도면, 추자면)은 본섬 행사의 비교 후보에서 코드 규칙으로 뺀다(43번). 42번 프롬프트처럼 LLM 판단에 맡기지 않는다.
- 같은 기간 다른 축제가 있는 후보는 장소 추정표에서 종류가 "축제"이고 걸침 비중이 0.25 이상이면 코드가 빼야 할 목록을 만들고, 검사가 LLM의 제출에 그 읍면이 제외로 들어 있는지 본다(42번 3-2절 규칙). LLM은 상시·장기 운영 행사나 확신도가 낮은 장소처럼 규칙이 정하지 못하는 경우를 판단하고 이유를 쓴다.

### 4-2. 도구와 형식 강제

- 도구는 조회 도구 하나(`get_visit_series`, 공개 스냅샷에서 읍면 하나의 일별 방문 인구를 최대 120일까지)와 단계별 제출 도구 3개(`submit_place_table`, `submit_judgement`, `submit_plan`)다. 모든 요청에 같은 순서로 넣어 프롬프트 캐시가 깨지지 않게 한다.
- 형식은 결정 9의 추천안대로 제출 도구에 `strict: true`를 걸고 `tool_choice: auto`로 둔다. 강제 도구 호출은 Sonnet 5.5에서 400이므로 쓰지 않는다. 구조화 출력(`output_config.format`)을 고르면 Haiku 5.5에서 실제로 되는지 첫 호출로 확인한다.
- `auto`는 도구 호출을 보장하지 않는다. 제출 도구 없이 글만 오면 "이 단계는 submit_plan 도구를 불러 끝내 주세요"를 보내고 제출 1번으로 센다.
- strict가 지원하지 않는 규칙(목록 길이, 달이 이어지는지 등)은 이 PC의 검사기가 본다. 검사 실패는 `is_error: true` 도구 결과로 돌려준다.

### 4-3. 재시도 정의

- **한 단계의 제출은 첫 제출을 포함해 최대 3번이다.** 3번째 제출도 검사나 리허설에서 떨어지면 그 단계는 실패다(결정 8 추천안). 화면 문구 "최대 3번"(44번)과 11/14 판정의 "3회 안에 통과"(30번 3-2절)가 같은 뜻이 된다.
- 조회 도구는 단계마다 4번까지, 실행 1회의 LLM 호출 합계는 16번까지다. 넘으면 egress가 "cap"으로 막고 대체 경로로 간다.
- 측정 기록에는 몇 번째 제출에서 통과했는지를 남긴다.

### 4-4. 숫자 환각 차단

42번 4절을 그대로 쓴다. LLM이 쓴 모든 글에서 빈칸(`{{키}}`), 입력에 나온 행사 이름·날짜·달, 업종 코드를 지운 뒤 아라비아 숫자나 숫자를 말로 쓴 표현(두 배, 절반, 퍼센트 등)이 남으면 돌려보낸다. 결과의 방향("높았습니다", "낮았습니다")도 LLM이 정하지 않고, 코드가 결과에 맞는 경우별 틀을 고른다. 빈칸 하나라도 값이 없으면 그 칸을 기본 문장으로 바꾼다. 화면과 PDF의 숫자는 구조상 코드가 채운 빈칸에서만 나온다.

빈칸 키는 calc.PLACEHOLDER_KEYS가 소유한다. `{{차이}}`는 결정 18에서 고른 주 숫자를 코드가 단위와 함께 채우므로, 그 결정이 늦어도 11/14의 프롬프트는 바꾸지 않아도 된다.

- 횟수: 행사마다 3번. 11/14 판정용 15회가 곧 개발 집합 측정이다(결정 11).
- 사람 정답표: 시험 행사의 개최 읍면, 같은 달 다른 축제가 있는 읍면, 장소 추정표 무작위 30건의 장소. 검사 통과율만 보면 우리가 만든 검사기를 우리 프롬프트가 통과하는지만 보는 셈이라 이 정답표를 반드시 같이 본다.
- 고르는 규칙은 측정 전에 정한다(결정 12). 추천은 Haiku가 기준을 넘으면 Sonnet은 측정하지 않는 방식이다.

## 5. 분석 방법

43번을 요약하고 다른 문서와 맞춘 결과를 반영했다. 기호는 이 절에서만 쓰고, 다른 절에서는 이름으로 부른다.

### 5-1. 무엇을 세나

- 대상 행: bjd가 행사 읍면 또는 비교 읍면이고 tour_type이 개별 또는 단체인 행. user_type은 가리지 않는다(내국인·외국인 관광객 모두).
- 업종 범위: 계획의 업종 목록, 비어 있으면 42개 전체.
- 월 값 Y(읍면, 달) = 대상 행 use_amt 합(원). 이용 건수는 방향 확인에, 이용자 수는 10 미만 검사에만 쓴다. 업종에 걸쳐 더한 이용자 수는 사람 수가 아니기 때문이다. 건수로 방향을 확인하는 문장은 처음부터 뺐다(자르는 순서 1번).

### 5-2. 기간(코드가 행사 날짜로 정함)

- 걸침 비중 = 그 달에 든 행사 일수 ÷ 그 달의 일수.
- 행사 달: 걸침 비중 0.5 이상인 달. 없으면 가장 큰 달 하나("희석 주의" 행사).
- 제외 달: 걸쳤지만 행사 달이 아닌 달. 어디에도 넣지 않는다.
- 기준 기간: 처음 걸친 달 바로 앞 3개월. 사전 추세용 기간: 그 앞 3개월.
- 처음 걸친 달 앞 6개월이 2023년 8월 이후여야 하므로 2024년 2월 이후 시작한 행사만 계산한다.
- **전년 같은 달은 쓰지 않는다**(결정 2 추천안). 축제는 대부분 매년 열려 작년 같은 달에도 행사 효과가 들어 있고, 카드 자료가 2023년 8월부터라 2024년 7월 이전 달은 전년 값이 없다. 이중차분이라는 틀(ADR-147)은 그대로이고, 비교 읍면과의 차이가 계절 변화를 걸러 낸다.

### 5-3. 수식

- 증가율: g = 행사 달 평균 ÷ 기준 기간 평균 − 1. 행사 읍면은 g_T, 비교 읍면은 g_C.
- 상대 효과: E = (1 + g_T) ÷ (1 + g_C) − 1. 로그 이중차분과 같다.
- 퍼센트포인트 차이: Δ = g_T − g_C = E × (1 + g_C). 성수기에는 같은 효과를 부풀려 보이므로 43번은 E를 주 숫자로 권한다(결정 18).
- 지수, 증가율, 효과만 결과에 쓴다. 지수는 정수, 증가율과 효과는 소수 첫째 자리로 반올림한다.

### 5-4. 비교 읍면

- 후보: 행사 읍면을 뺀 11곳에서 섬 2곳(본섬 행사일 때)을 뺀 9곳. 섬 행사는 계산하지 않는다.
- 같은 시기 행사로 흐려진 후보 제외: 계산에 쓰는 모든 달(처음 걸친 달 앞 6개월부터 마지막 걸친 달까지)에 걸침 비중 0.25 이상인 다른 축제가 있으면 뺀다. 판단 재료는 장소 추정표다.
- 행사 읍면 자신이 기준 기간이나 사전 추세용 기간에 다른 축제로 흐려지면 계산하지 않는다("기준 기간 오염"). 이 규칙 때문에 휴애리 유럽 수국축제와 한림공원 연꽃축제는 계산 대상이 아니다.
- **순위 지표는 로그 차이의 표준편차다**(16절 j). 공개 유동인구 월평균 V로 d(달) = ln V(행사 읍면) − ln V(후보)를 구하고, 처음 걸친 달 앞 12개월(같은 달 숫자의 달은 뺌) 동안의 표준편차가 작을수록 나란하다. 상관계수는 계절 진폭이 두 배인 지역도 1에 가깝게 나와 쓰지 않는다. 스냅샷이 2023-08-01부터라 2024년 7월 이전 행사는 쓸 수 있는 달이 12개보다 적다(가파도청보리축제는 8개월). 6개월 미만이면 계산하지 않는다.
- 거리 상위 3곳이 1·2·3순위이자 교체 순서다. 비교 읍면은 1곳을 쓴다(결정 2 추천안).

### 5-5. 사전 추세 검사와 가짜 시점 검사

- 가짜 시점 값 Q: 행사가 없던 달 τ마다(τ와 그 앞 3개월이 수록 기간 안, 이번 행사와 같은 달 숫자의 달은 모든 해에서 뺌, 두 읍면에 다른 행사가 있던 달은 뺌) 행사 달 = τ, 기준 = τ 앞 3개월로 같은 E를 계산한다. 평소 흔들림 σ = Q들의 표준편차.
- 사전 추세 값 L: 기준 기간을 가짜 행사 기간으로, 사전 추세용 기간을 가짜 기준으로 둔 같은 계산. |L| ≤ 2σ면 통과(결정 2 추천안), 실패하면 코드가 다음 순위로 바꾼다. 3순위까지 실패하면 결과를 내지 않는다.
- 결과 강도: p값 = (1 + |Q| ≥ |E|인 개수) ÷ (1 + Q의 개수). Q가 9개 이상일 때만 판정하고, 0.1 이하면 "평소 흔들림보다 뚜렷한 차이", 아니면 "평소에도 생기는 크기의 차이"로 쓴다. 가짜 시점 검사는 후보를 바꾸지 않는다.
- **30번 자르는 순서 4번(가짜 시점 검사 빼기)은 쓰지 않는다.** σ가 사전 추세 기준에 들어가므로 가짜 시점 값 계산은 빼면 안 된다. 잘라도 되는 것은 p값과 강도 문장뿐이다(자르는 순서 5번).
- 화면과 보고서에는 "평행 추세가 확인됐다"고 쓰지 않고 "행사 전 3개월에는 큰 어긋남이 보이지 않았다"고 쓴다.

### 5-6. 방문 판단(공개 유동인구)

visitPop은 연인원이라 "명"으로 쓰지 않고 지수로 보인다. 코드가 행사 읍면의 R_T(행사 기간 일평균 ÷ 각 행사일의 직전 4주 같은 요일 평균의 평균 − 1)와 후보들의 가운데 값 R_C, 상대 비율 V = (1 + R_T) ÷ (1 + R_C) − 1을 계산해 LLM에 준다. 43번이 제안한 "지난 같은 길이 창의 90번째 백분위수" 기준은 처음부터 뺐다(자르는 순서 2번). 이 판단은 경고이고 카드 계산을 막지 않는다.

### 5-7. 분석 가능 판정(행사 목록)

| 조건 | 상태 |
|---|---|
| 종료일이 시작일보다 앞섬 | 볼 수 없음: 날짜 오류 |
| 기간 92일 초과 | 볼 수 없음: 장기 행사 |
| 가장 큰 걸침 비중 0.25 미만 | 볼 수 없음: 한 달 합계에 묻히는 짧은 행사 |
| 처음 걸친 달 앞 6개월이 2023년 8월 이전 | 볼 수 없음: 행사 전 자료 부족 |
| 장소가 동 지역, 섬 행사, 기준 기간 오염 | 장소 확인 뒤 볼 수 없음과 이유 |
| 가장 큰 걸침 비중 0.25 이상 0.5 미만 | 희석 주의 |
| 그 밖 | 볼 수 있음 |

오늘 확인한 결과 앞의 네 조건을 통과하는 행사는 52건이다(43번과 같음). 기준값 0.25·0.5는 결정 2에 넣었다.

### 5-8. 10 미만 처리

- 검사 칸: (읍면, 달, 업종 범위)의 관광객 행 묶음. 계산에 쓰는 모든 달과 두 읍면 모두.
- 건수 = use_cnt 합, 인원 = 업종별 user_cnt 합 중 가장 큰 값(인원의 하한). 둘 중 하나라도 10 미만이면 그 칸의 금액도 쓰지 않는다.
- 처리 순서(코드 고정, 두 읍면에 함께): 계획의 범위, 중분류(업종 코드 앞 세 자리), 대분류(첫 글자), 42개 전체. 그래도 10 미만이면 비교 읍면은 다음 순위로 교체, 행사 읍면은 계산하지 않음. 달을 빼는 처리는 하지 않는다(효과의 정의가 바뀜).
- 넓힌 사실은 화면과 보고서에 적고 LLM에는 보내지 않는다.

### 5-9. 고정 한계 문구

30번의 네 가지(인과 효과가 아님, 월 단위, 비씨카드 한정·실소유자 기준, 공식 통계가 아님)에 43번의 네 가지(전년 같은 달을 쓰지 않은 이유, 인접 읍면 소비로 차이가 작게 나올 수 있음, 방문 인구는 내국인 연인원, 사전 추세 검사 통과가 행사 뒤 나란함을 보장하지 않음)를 더해 여덟 개를 코드 상수로 둔다.

## 9. 윈도우 묶음

47번을 요약하고 다른 문서와 맞춘 결과다.

- **Python 본체**: python.org의 윈도우 embeddable 3.11.9 zip(11.2MB, 3.11의 마지막 윈도우 바이너리)에 맥에서 받은 윈도우용 휠을 넣는다(결정 5 추천안). 개발 venv와 버전이 같고, 본체가 서명되어 있어(기억 기반, 11/15에 확인) 스마트 앱 컨트롤 위험이 가장 작다. 막히면 python-build-standalone 3.11.18로 바꿔 끼운다(반나절 안쪽, 추정).
- **휠 받기**: `pip install --no-compile --target build/EventEffect/python/Lib/site-packages --platform win_amd64 --python-version 3.11 --implementation cp --abi cp311 --only-binary=:all: -r requirements-lock.txt` 뒤 `bin/`을 지운다. `--no-compile`은 맥 경로가 박힌 .pyc를 넣지 않기 위해서다. 완료 기준: `.pyd`가 있고 `.so`와 `darwin`이 든 파일이 0개.
- **`python311._pth`**: `python311.zip`, `.`, `Lib\site-packages`, `..\app`, `import site` 다섯 줄. 격리 모드라 `PYTHONUTF8`가 무시될 가능성이 커 bat에서 `-X utf8`로 실행한다. matplotlib은 코드에서 `matplotlib.use("Agg")`, MPLCONFIGDIR은 app/out/cache로 지정한다.
- **bat 두 개**: 영문만, CRLF, 모든 경로를 따옴표로. install.bat은 압축 해제 확인과 install_check.py 실행만, run.bat은 폴더 고정과 server.py 실행만 한다. 이미 실행 중 확인(상태 조회의 앱 표시값, 맞으면 브라우저만 열고 종료 코드 3), 브라우저 열기, 한글 경로 경고는 Python 코드에 둔다.
- **포트**: 8501은 Streamlit 기본 포트라 다른 참가작과 겹칠 수 있어(47번, 추정) 18501로 바꾼다. 다른 프로그램이 같은 포트를 쓰면 run.bat이 멈춰 오류를 보여 준다.
- **ZIP 구조**: `EventEffect\`(짧은 영문 루트) 아래 install.bat, run.bat, README.txt(한국어 매뉴얼 PDF를 가리키는 영문 안내), docs\manual_ko.pdf, python\, app\. app\ 안에 server.py와 모듈, static, spec, assets, data, tests, manifest.txt가 있고 out\은 실행 때 app\out으로 생긴다(47번은 out을 루트에 두었으나 경로를 server.py 기준으로 맞춤). 모든 이름은 영문이고 Python zipfile로 NFC 이름을 만든다.
- **크기**: 47번은 40개 패키지 기준 ZIP 약 100~150MB로 추정했다. 패키지가 26~33개로 줄고 가상 데이터는 세 판(판마다 약 19MB)이 되어, 빌드 때 실제 크기를 측정해 기록한다. 상한 100GB와 비교하면 문제가 아니다.
- **빌드 스크립트**: tools/build_zip.py 하나로 잠금 파일, 본체 풀기, `._pth`, site-packages, 앱 파일 복사(포함 목록 방식), bat CRLF 변환, manifest.txt(파일 목록, 최장 경로, 파일 수), ZIP 만들기, ZIP 정적 검사(46번 7-1절 목록)를 한다. 11/13 밤에 만들고 11/18·11/19에 다시 돌린다.
- **윈도우 함정과 대응**(47번 6절): 스마트 앱 컨트롤(서명된 본체), Visual C++ 런타임 누락(설치 점검의 import 항목, 빠지면 재배포 DLL을 python\ 옆에), 260자 경로(짧은 루트, `C:\EventEffect` 권장, 최장 경로 측정, 파일 목록 대조), 인터넷에서 받은 파일 표시(매뉴얼에 차단 해제 화면), 한글·공백 경로(따옴표, 설치 점검), 콘솔 선택 멈춤(uvicorn 접근 기록 끄기, 매뉴얼에 Esc 안내), 엑셀로 다시 저장한 CSV(거절하고 원본을 다시 받으라고 안내, 16절 새 불일치 12).

## 11. 자르는 순서

### 11-1. 처음부터 범위에서 뺀 것

설계 문서에 있었지만 이 계획의 기본 범위에 넣지 않은 것이다. 이유는 2-4절에 적었다. 허브 실시간 호출, find_events 조회 도구, 사용자 입력 숫자 검문, LLM이 쓰는 활용 사유 문안, 짧은 행사의 방문 변화 결과, 결과 폴더 열기 버튼, 인쇄용 화면, 도움말 대화상자, 감사 훅, pandas·DuckDB다.

### 11-2. 밀릴 때 자르는 순서

값이 낮은 것부터 자른다. 1~3번은 일정 계산(10-1절)에 따라 처음부터 적용했다.

### 11-3. 끝까지 자르지 않는 것

윈도우 설치 두 단계와 실기 시험, "예시로 해 보기", 장소 확인과 LLM의 방문 판단·비교 읍면 판단, strict 스키마 제출과 검사·리허설·재시도와 작업 기록, 로컬 계산(월 판별, 누락 월 경고, 이중차분, 사전 추세 검사, 교체, 가짜 시점 값), 10 미만 처리, 빈칸 채움 결과 문장과 png와 고정 한계 문구, 외부 전송 경계(한 모듈, 기록, 잠금, 자가 점검 버튼), 결과 삭제 켜기·끄기, 대체 경로(미리 만든 계획 1개 이상), 매뉴얼.

### 11-4. 모두 잘랐을 때 남는 최소 제품

예시 버튼을 누르면 장소 추정표의 장소를 확인하고, LLM이 공개 유동인구로 방문을 판단하고 비교 읍면 제외와 이유, 업종 범위, 문장 틀을 낸다. 가상 데이터 리허설로 계획을 고친다. 가상 센터 CSV를 넣으면 잠기고, 코드가 이중차분, 사전 추세 검사, 교체, 10 미만 처리를 해서 결과 화면에 숫자(코드가 채움), 지수 두 선 png, 방문 인구 png, 한계 문구, 근거표, 반출 배지, 활용 사유 문안을 보여 준다. 끝내기로 결과를 지운다. PDF는 없고, 미리 만든 계획은 예시 행사 하나이며, 리허설 통과율은 개발 집합 결과만 있다.
