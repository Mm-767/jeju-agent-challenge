# 테크 리드 보고서: 8개 후보의 구현·시연 가능성 판정

작성 2026-11-13, 테크 리드(소프트웨어 아키텍트). 근거는 공용 브리핑(00번), 후보 정리(20번), 1단계 보고서 11~16번, 센터 데이터 명세서 추출 요약(`dl_spec/spec_summary.txt`), 이번에 확인한 웹 문서 4건(맨 끝 출처)이다. 일수는 모두 추정이고, 개발자 1명이 AI 코딩 도움을 쓴다는 가정이다. 이번에 확인하지 못한 기술 사실에는 "추정" 또는 "기억 기반"을 붙였다.

## 결론 5줄

1. 공통 엔진은 최소 범위로 잡아도 약 4.75일이 들어 사실상 일정 전체를 차지하고, 실제 개발 가능 시간은 약 5.25일이므로 주제별 추가 작업은 1일 안팎이어야 마감에 들어간다. 그래서 엔진은 지원 데이터 1~2종, 질문 유형 4개(추이, 비교, 순위, 구성비)로 좁혀 만든다.
2. 구현과 시연 점수를 합친 상위 3개는 A 반출 통과형 현황보고서(구현 4점, 시연 5점), D 센터 방문 설계도(구현 4점, 시연 5점), E 버스 정류소·노선 수요 진단(구현 4점, 시연 3점)이다. E와 C 농산물 시세 브리핑은 허브 API가 2026년 값을 주는지 확인되면 시연 점수가 5점까지 오르고, 확인 전에는 3점이다.
3. B 행사 효과 검증과 G 상권·관광 소비 진단은 카드 데이터의 법정동 73개와 유동인구의 행정동 43개를 잇는 대응표가 새로 필요해 구현 3점이다. H 기업 데이터와 B의 탐나는전 변형은 명세서 추출 요약에서 컬럼 칸이 비어 있어, 원본 시트를 직접 확인하기 전까지는 명세대로 가상 데이터를 만들 근거가 없다.
4. 기술 스택은 화면 Streamlit, 설치는 ZIP에 넣은 uv 실행 파일과 고정된 잠금 파일, 차트는 matplotlib png, PDF는 순수 Python 라이브러리 fpdf2와 동봉한 나눔고딕 글꼴을 추천한다. Streamlit은 사용 통계 전송이 기본으로 켜져 있으므로 설정과 실행 인자 양쪽에서 끄고 127.0.0.1에만 열어야 한다.
5. 기술적으로 가장 큰 위험은 맥에서만 개발하고 윈도우에서는 한 번도 돌려 보지 않는 것이다. 11/15과 11/19에 실제 윈도우 PC에서 매뉴얼만 보고 설치하는 시험을 일정에 고정하고, 오늘은 허브 API 키 발급과 2026년 값 확인, 명세서 원본 시트 확인부터 한다.

### 3-2. A 반출 통과형 현황보고서 Agent

- 추가로 필요한 것: 반출 검사기를 전체 범위로 올리기(상보 억제, 산출물 4유형 판정, 합계 대신 비율·증감률·순위를 고르는 지표 규칙) 0.5일, 반출 신청 활용 사유 문안과 정책 조항을 인용한 근거표 0.25일, 결과 삭제 기능 0.25일. 허브 유동인구는 넣지 않아도 주제가 완결된다.
- 시연 신뢰도: 높음. 헤더가 확인된 카드 이용 현황(읍면동)_v02로 가상 CSV를 만들고, 처음부터 끝까지 로컬에서 돈다. 외부 의존은 LLM 계획 한 군데이고 대체 경로가 덮는다.
- 막히는 미확인 사항: 재집계 순서에 쓸 상위 범주(age, user_type, tour_type 코드값, 법정동에서 7권역으로 가는 대응)가 명세 시트에 있는지. 10 미만 기준을 금액 컬럼에도 적용하는지는 확인할 길이 없으므로, 인원·건수가 10 미만인 칸은 금액도 함께 가리는 보수적 규칙으로 간다.
- 첫날 확인: `dl_spec/spec_kr.xlsx`의 1-08 시트에서 코드값 칸을 직접 읽는다(30분).
- 구현 4점, 시연 5점.
- 참고: 경쟁이 가장 몰린 영역이다(15번). 기술 판정과는 별개다.

### 3-3. B 행사·정책 효과 검증 Agent

- 추가로 필요한 것: 허브 유동인구 API 부품 0.5일, 법정동과 행정동 대응표 만들기와 검증 0.5일, 행사 전 흐름이 비슷한 비교 지역 고르기(일별 유동인구 곡선의 거리 계산) 0.5일, 이중차분 계산과 행사 전 추세 검사 0.25일, 가상 카드 CSV에 행사 효과 심기 0.25일.
- 기술 함정: 비교 지역은 허브 유동인구(행정동 단위로 추정)로 고르고, 소비 차이는 센터 카드(법정동 73개)로 계산한다. 두 단위를 잇는 대응표가 없으면 비교 지역 선택 결과를 카드 계산에 쓸 수 없다. 대응표는 행정안전부 공개 자료로 만들 수 있지만 일대일이 아니라서 검증에 시간이 든다(13번 1-4절).
- 시연 신뢰도: 중간. 비교 지역 선택 장면은 허브 API가 2025년 행사 기간 값을 주는지에 달려 있다. 13번은 상세 페이지 미리보기 값이 2019-02-01이라고 적었다.
- 탐나는전 변형: 명세서 추출 요약에서 1-32 탐나는전 이용 현황의 컬럼 칸이 비어 있다. 추출이 놓쳤을 수도 있으므로 원본 시트를 봐야 하고, 거기에도 없으면 가상 데이터를 명세대로 만들 수 없어 이 변형은 진행하지 않는다.
- 축소안: 허브 API와 대응표를 빼고, LLM이 공개 명세의 법정동 목록에서 비교 지역 후보를 제안하고 사용자가 확정한 뒤 가상 카드 CSV로 행사 전 추세 검사와 차이 계산을 로컬에서 하면 추가 0.75일, 합계 5.5일로 구현 4점, 시연 5점이 된다. 대신 "LLM이 공개 데이터를 직접 보고 판단한다"는 장면이 사라진다.
- 첫날 확인: 허브 키로 읍면동 단위 내국인 유동인구를 2025-10 기간으로 한 번 호출하고, VISIT JEJU 축제행사콘텐츠 파일을 내려받아 날짜·장소 컬럼을 본다(1시간).
- 구현 3점, 시연 3점(축소안은 4점, 5점).

### 3-4. C 농산물(월동채소) 시세·출하 브리핑 Agent

- 엔진에서 빠지는 것: 가상 데이터 생성기, 반출 검사기, 명세 로더 대부분. 공개 데이터만 쓰므로 LLM이 값을 직접 보는 도구 호출 고리를 쓴다.
- 추가로 필요한 것: 허브 API 부품 0.5일, LLM이 값을 보며 추가 조회를 정하는 도구 호출 고리 0.25일, LLM 문장 속 숫자를 도구 결과와 대조하는 검사 0.25일, 가격 곡선이 비슷한 과거 해 찾기 0.25일.
- 시연 신뢰도: 지금은 낮음과 높음 사이에서 정해지지 않았다. 핵심 장면 전부가 농산물 거래 API에 달려 있는데, 어떤 품목과 시장을 담는지, 2026년 값이 오는지 확인되지 않았다. 데이터 목록상 수정일은 2025-09-12다. 확인되면 스냅샷을 ZIP에 넣어 5점이 되고, 월동무·당근·양배추가 없으면 주제가 성립하지 않는다.
- 첫날 확인: 농산물 품종별 일일 거래 정보를 2026-10-01~2026-11-12로 호출해 품목 이름 목록과 마지막 날짜를 본다(30분).
- 구현 4점, 시연 3점.
- 참고: 센터 데이터와의 연결이 없다(12·13·15번). 허브에 농산물 분석 메뉴가 이미 있다(13번).

### 3-5. D 센터 방문 설계도 Agent (공개 쌍둥이 리허설 포함 여부 따로 판정)

- 추가로 필요한 것: 설계 모드(목적 문장으로 받아야 할 데이터·조회 조건·월별 체크리스트를 만들고 설계도 파일로 저장) 0.5일, 실행 모드(LLM 호출 코드를 아예 불러오지 않고 네트워크 호출도 하지 않는 모드, CSV 헤더로 데이터 종류 판별, base_year_month로 누락 월 경고) 0.25일. 설계도 파일은 엔진의 계획 JSON에 체크리스트를 붙인 것이라 새 형식을 만들지 않는다.
- 공개 쌍둥이 리허설은 넣지 않는 것을 권한다. 허브 공개 파일과 센터 데이터의 컬럼 대응표가 확인되지 않았고(16번), 엔진의 가상 데이터 리허설이 같은 "계획, 실행, 검증, 재시도" 고리를 이미 보여 준다. 넣으면 추가 1일이 더해져 합계 6.5일이 된다.
- 시연 신뢰도: 높음. 설계 모드는 LLM과 ZIP 안 명세 JSON만 쓰고, 실행 모드는 인터넷을 끊어도 돈다. 대체 경로로 미리 만든 설계도 파일 몇 개를 넣으면 키 없이도 시연된다.
- 막히는 미확인 사항: 명세서 추출 요약에서 컬럼 칸이 빈 데이터(1-31 온라인 카드 제주기업, 1-32 탐나는전, 2-01~2-08 기업 데이터 등)는 설계 모드가 추천하지 못하게 막아야 한다. 대회 제공 데이터 목록 xlsx는 "Daker 홈페이지 외 배포 금지"라서 ZIP에 넣지 않는 쪽이 안전하다. 허브 데이터 안내는 실제로 쓰는 몇 종의 공개 상세 페이지 정보만 직접 정리해 넣는다(컴플라이언스 확인 필요).
- 첫날 확인: 명세서 원본에서 컬럼이 있는 데이터 목록을 뽑는다(30분).
- 구현 4점, 시연 5점.
- A와 D는 엔진이 같고 출력만 다르다. 한쪽을 고르면 다른 쪽의 핵심 기능은 0.75~1일이면 붙는다. 결합은 11/17 저녁에 윈도우에서 전체 시나리오가 통과했을 때만 한다.

### 3-6. E 버스 정류소·노선 수요 진단 Agent

- 엔진에서 빠지는 것: 허브만 쓰는 기본 기능에는 가상 데이터 생성기와 반출 검사기가 필요 없다.
- 추가로 필요한 것: 허브 API 부품 0.5일, 정류소 이름 퍼지 매칭 0.25일, 정류소 좌표와 가장 가까운 기상관측소 연결 0.25일, 비 온 날과 안 온 날 비교 0.25일.
- 센터 데이터 경로(선택): 명세서에서 3-04 버스 정류소별 이용 현황의 컬럼(base_date, day_of_week, base_hour, bus_station_id, bus_station_name, get_on_off_type, user_category, pay_type, user_count)이 확인됐고 원본까지 반출 가능 등급이다. 허브 API는 일 단위(baseDate, stationId, userCount)이고 3-04는 시간 단위라 센터 데이터가 시간대 분석을 더해 준다. 정류소 ID는 허브 정류소 기본 정보에서 실제 값을 가져오면 가상 데이터를 쉽게 만들 수 있다. 이 경로는 엔진 부품을 더해 추가 1일이라 일정이 밀리면 가장 먼저 자른다. 승객별 이용 현황(3-05)과 카드 승하차 정보(3-06)는 개인 단위 기록이라 그럴듯한 가상 데이터를 만들기 어렵다(13번). 넣지 않는다.
- 시연 신뢰도: 지금은 3점. API 형식과 일일 쿼터 1000은 13번이 상세 페이지에서 확인했지만, 2026년 값이 오는지와 쿼터가 데이터별인지 키별인지는 모른다. 평가자 여러 명이 같은 키로 여러 번 돌리면 쿼터가 문제 될 수 있으므로 스냅샷을 기본값으로 두고 "최신 값 받기" 버튼으로 실제 호출을 보여 주는 편이 안전하다.
- 첫날 확인: 일일 정류소별 버스 이용자 정보를 2026-10 한 달로 호출해 마지막 날짜, 응답 형식, 한 번에 오는 행 수를 본다(30분).
- 구현 4점, 시연 3점(API 확인 뒤 5점까지).

### 3-7. F 행정동 생활폐기물 현황·예측 Agent

- 추가로 필요한 것: 허브 유동인구·기상 API 부품 0.5일, 허브 읍면동 이름과 센터 종량제봉투 행정동 이름 맞추기 0.25일, 기상관측소 연결 0.25일, 다음 달 예상 범위(계절 단순 모형) 0.25일.
- 데이터 근거: 명세서에서 5-03 종량제봉투판매실적의 컬럼(pt_year, pt_month, base_date, city_name, emd_name, wastebag_type, wastebag_liter, sale_count, sale_amount)이 확인됐다. 가상 데이터는 쉽다.
- 시연 신뢰도: 중간. 결합 장면이 허브 API에 달려 있다. 또 가상 데이터로는 예측의 정확도를 보여 줄 수 없어서, "예측"을 내세우면 결과 신뢰성 설명이 약해진다. 예상 범위와 그 계산 방법만 보여 주는 것으로 범위를 묶어야 한다.
- 첫날 확인: 허브 읍면동 단위 내국인 유동인구 응답의 지역 이름 목록을 받아 센터 행정동 43개와 대조한다(30분).
- 구현 3점, 시연 3점.

### 3-8. G 상권·관광 소비 진단 Agent

- 추가로 필요한 것: 법정동과 행정동 대응표 또는 7권역 단위 결합 0.5일, 허브 유동인구 API 부품 0.5일, 허브 상가(상권) 정보 파일의 주소에서 읍면동 뽑기 0.5일, 감소분을 권역·업종·연령으로 나눈 기여도 계산 0.25일.
- 기술 함정: 카드 시간대(오전·점심·오후·저녁·밤)의 시각 경계를 명세서에서 찾지 못했다(13번). 유동인구 01~24시와 맞출 근거가 없으므로 시간축 결합은 하지 않고 권역과 월로만 잇는다.
- 시연 신뢰도: 비교적 높음. 센터 카드 부분은 헤더가 확인된 데이터로 가상 CSV를 만들 수 있고, 허브 부분만 외부에 기댄다.
- 첫날 확인: 명세서 1-14 카드 시간대 시트의 비고 칸 확인(15분), 행정안전부 법정동·행정동 연계 자료의 공개 위치 확인(30분).
- 구현 3점, 시연 4점.
- 참고: 경쟁이 몰린 영역이다(13·15번).

### 3-9. H 기업 데이터 지배기업 보호 Agent

- 추가로 필요한 것: 칸별 기업 수 세기와 상위 1~2개 기업 비중 규칙 0.5일, 기업명·식별 컬럼 제거 0.25일. 로직 자체는 단순하다.
- 막히는 사항: 명세서 추출 요약에서 2-01~2-08 한국기업데이터 8종의 컬럼 칸이 모두 비어 있다. 추출 스크립트가 다른 시트 배치를 놓쳤을 가능성도 있어 아직 "컬럼이 없다"고 단정하지는 않는다. 원본 시트에도 컬럼이 없으면 "명세서 구조를 따른 가상 데이터"를 만들 수 없고, 운영진에게 물어 답을 받을 시간도 없다. 자료 기준 시점도 2019~2021년이다.
- 첫날 확인: 원본 엑셀에서 2-01 시트를 직접 연다(15분). 컬럼이 있으면 구현 4점, 시연 4점으로 다시 본다.
- 구현 2점, 시연 2점.

### 3-10. 상위 3개

구현과 시연 점수 합으로 A(9점), D(9점)가 앞서고 E·C·G가 7점으로 같다. 셋 중 E를 골랐다. E는 API 형식이 상세 페이지에서 확인됐고, API가 기대에 못 미쳐도 컬럼이 확인된 센터 3-04로 가상 데이터 경로를 만들 수 있기 때문이다. C는 첫날 API 확인 결과 월동채소 품목과 2026년 값이 나오면 E와 같은 일정 틀로 바꿔 끼울 수 있다. G는 시연 점수는 높지만 결합 부품 때문에 필요 일수가 가용 시간을 1일 넘는다.

## 5. 기술 스택과 패키징 추천

아래는 선택지가 둘 이상인 결정이다. 각 표에 추천을 적었지만 최종 선택은 사용자가 하고, 고른 뒤 바로 ADR로 남겨야 한다.

### 5-1. 화면

| 기준 | Streamlit | Gradio | FastAPI와 정적 HTML |
|---|---|---|---|
| 백엔드 개발자 1명의 개발 속도 | 가장 빠름. Python만으로 표·차트·진행 상태를 그린다 | 빠름. 채팅형 화면이 기본 제공 | 느림. 작업 기록 갱신과 폼을 HTML·JS로 직접 써야 해서 약 1일 더 든다(추정) |
| 기본 외부 통신 | 사용 통계 수집 `browser.gatherUsageStats`가 기본 켜짐. 끌 수 있다(출처 1) | 사용 통계가 기본 켜짐(기억 기반, 이번에 확인 안 함) | 없음 |
| 첫 실행 함정 | 첫 실행 때 터미널에서 이메일을 묻는 안내가 기본 켜짐. headless 모드에서는 뜨지 않는다고 문서에 적혀 있다(출처 1). 윈도우 서비스로 돌린 경우 headless에서도 막혔다는 보고가 있다(출처 2) | 의존 패키지가 많다(기억 기반) | 거의 없음 |
| 여러 단계 에이전트 표현 | 버튼을 누를 때마다 스크립트 전체가 다시 실행되는 구조라, 계획과 결과를 세션 상태에 저장하지 않으면 LLM이 다시 불린다 | 이벤트 함수 단위라 자연스럽다 | 자유 |
| 큰 CSV 불러오기 | 업로드 위젯 대신 폴더 경로 입력으로 디스크에서 바로 읽는다 | 같음 | 같음 |

추천은 Streamlit이다. 개발 속도 차이가 1일 가까이 나고, 단점 셋은 설정으로 막을 수 있다. 막는 방법은 다음과 같다.
- 프로젝트 안 `.streamlit/config.toml`에 `[browser] gatherUsageStats = false`, `[server] headless = true`, `address = "127.0.0.1"`을 쓴다. 이 설정 파일은 실행한 폴더 기준으로 읽히므로(추정) run.bat 첫 줄에서 `cd /d "%~dp0"`로 폴더를 고정하고, 같은 값을 실행 인자로도 한 번 더 넘긴다.
- 127.0.0.1에만 열면 윈도우 방화벽의 "액세스 허용" 창이 뜨지 않는다(기억 기반). 모든 주소로 열면 그 창이 뜨고, 비개발자 평가자가 취소를 누르면 혼란이 생긴다.
- 분석은 "실행" 버튼을 눌렀을 때만 돌리고, 계획과 결과는 질문 문자열을 열쇠로 세션 상태에 저장한다.

### 5-2. 설치

| 기준 | python.org 설치 프로그램을 평가자가 직접 설치 | uv 실행 파일을 ZIP에 넣기 | Python 본체와 패키지 파일을 ZIP에 통째로 넣기 |
|---|---|---|---|
| 평가자 단계 | 많음. "PATH에 추가" 체크를 놓치면 실패한다 | install.bat 더블클릭 한 번 | install.bat 더블클릭 한 번 |
| 필요한 외부 주소 | python.org, pypi.org, files.pythonhosted.org | Python 내려받기용 GitHub(uv는 python-build-standalone 배포본을 쓴다, 출처 3), pypi.org, files.pythonhosted.org | 없음 |
| ZIP 크기 | 작음 | uv 실행 파일만큼 늘어남 | 100MB 이상으로 커질 수 있다(추정) |
| 실패 모드 | 윈도우 11에서 Python이 없을 때 `python`을 치면 마이크로소프트 스토어가 열린다(기억 기반) | GitHub 주소가 차단되면 Python을 못 받는다 | 제출 용량 제한에 걸릴 수 있다 |

추천은 uv 실행 파일을 ZIP에 넣는 방식이다. `uv sync --frozen`이 잠금 파일대로 Python과 패키지를 한 번에 설치해 버전이 고정된다. GitHub 차단에 대비해, 제출 용량 제한이 허락하면 Python 배포본 압축 파일 하나를 ZIP에 넣고 `UV_PYTHON_INSTALL_MIRROR`를 그 폴더로 지정한다. 이 변수는 GitHub 배포 주소 앞부분을 바꿔 주는 설정이고 로컬 폴더도 지원한다(출처 4, 로컬 폴더 지정 방법은 실제로 시험해 봐야 한다). 기획서의 외부 주소 목록에는 api.anthropic.com, open.jejudatahub.net, pypi.org, files.pythonhosted.org, github.com을 적는다.

run.bat의 모양은 다음 정도면 된다. 파일 안에는 한글을 쓰지 않는다.

```bat
@echo off
cd /d "%~dp0"
set PYTHONUTF8=1
start "" cmd /c "timeout /t 4 >nul & start http://127.0.0.1:8501"
uv.exe run streamlit run app\main.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

### 5-3. 나머지 라이브러리

- 계산: DuckDB(월별 CSV를 한 번에 읽고 SQL로 집계)와 pandas(표 다듬기). 센터 CSV는 숫자까지 큰따옴표로 감싸 있으므로 형식 자동 추론에 맡기지 않고, 명세 JSON의 형식을 명시해 읽는다. 코드 컬럼은 문자열로 읽어 앞자리 0을 지킨다.
- 차트: matplotlib으로 png만 만든다. 반출 정책이 png·jpg만 인정하기 때문이다(16번 2-2절). 글꼴은 시스템 글꼴을 찾지 않고 ZIP에 넣은 나눔고딕(OFL 라이선스, 기억 기반) 파일을 직접 등록한다. 개발 PC가 맥이라 맑은 고딕이 없으므로, 동봉한 글꼴을 써야 맥과 윈도우의 결과가 같다.
- PDF: fpdf2를 추천한다. 순수 Python이고 TTF 글꼴을 넣어 한글을 쓸 수 있다(기억 기반). WeasyPrint는 윈도우에서 GTK가 필요해 피한다(14번 6절). Edge의 머리 없는 인쇄 기능으로 HTML을 PDF로 바꾸는 방법도 있으나 실행 파일 경로가 PC마다 다를 수 있다(추정).
- LLM: Anthropic Python SDK. 계획은 도구 정의의 JSON 스키마로 형식을 강제한다. 모델은 14번 1-4절대로 Haiku를 기본으로 두고, 시험 질문으로 리허설 통과율을 측정해 정한다.
- 허브 API: httpx로 호출하고 응답을 JSON 스냅샷으로 저장한다. 호출이 실패하면 스냅샷으로 자동 전환하고 화면에 "스냅샷 값(저장일)"이라고 표시한다.
- 로컬 LLM: 넣지 않는다. 엔진 어디에서도 필요하지 않고, 같은 사양의 시험 PC가 없다(14번 3절).

## 6. 기술적으로 가장 위험한 함정과 피하는 방법

위험이 큰 것부터 적었다.

1. **윈도우에서 한 번도 돌려 보지 않고 제출하기.** 맥에서 되는 것이 윈도우에서 깨지는 경로가 아래 2~8번이다. 11/15과 11/19의 실제 PC 시험을 일정에서 빼지 않는다.
2. **윈도우 기본 문자 인코딩.** 윈도우의 Python은 인코딩을 지정하지 않으면 한국어 로캘 인코딩(CP949)으로 파일을 연다(기억 기반). 센터 CSV는 UTF-8이라 바로 깨진다. bat에서 `PYTHONUTF8=1`을 걸고, 코드에서도 모든 파일 열기에 인코딩을 명시한다. bat 파일 안에 한글을 쓰면 명령 창에서 깨지므로 영문만 쓴다.
3. **맥에서 만든 ZIP의 한글 파일 이름.** 맥은 한글 파일 이름을 자모가 분리된 형태(NFD)로 저장해, 윈도우에서 "ㅅㅓㄹㅊㅣ"처럼 보일 수 있다(기억 기반). ZIP 안 파일 이름은 영문으로 하고, 한글 매뉴얼 PDF도 영문 이름으로 둔다. ZIP은 Python의 zipfile로 이름을 NFC로 바꿔 만든다.
4. **한글과 공백이 든 경로.** 센터 안내의 "바탕화면\요청파일"처럼 한글 경로에서 CSV를 읽는 경우를 반드시 시험한다. DuckDB가 윈도우의 비영문 경로에서 문제를 일으킨 적이 있다는 기억이 있으나 확인하지 못했다(추정). 시험에서 실패하면 pandas로 파일을 연 뒤 DuckDB에 넘긴다.
5. **Streamlit 기본 설정.** 사용 통계 전송, 첫 실행 이메일 안내, 모든 주소로 열기의 세 가지다. 5-1절 방법으로 막고, 외부 전송 기록 화면에 "Streamlit 통계 전송 꺼짐"을 표시한다.
6. **Python 설치 경로.** python.org 설치 프로그램의 PATH 체크 누락, 마이크로소프트 스토어 별칭, uv가 Python을 받는 GitHub 주소 차단이다. uv 실행 파일을 동봉하고, 가능하면 Python 배포본도 동봉한다.
7. **인터넷에서 받은 ZIP의 실행 파일 경고.** 내려받은 ZIP에서 꺼낸 실행 파일에는 윈도우의 "PC 보호" 경고가 뜰 수 있다(추정). 매뉴얼에 "압축을 풀기 전 ZIP 파일 속성에서 차단 해제"와 경고가 떴을 때 누를 버튼을 화면 캡처로 넣는다.
8. **큰따옴표로 감싼 숫자와 앞자리 0.** 모든 값이 큰따옴표라 형식 추론이 문자열로 잡거나, 코드 "01"이 숫자 1로 바뀔 수 있다. 명세 JSON의 형식대로 읽는다.
9. **센터 값이 오류 메시지와 기록으로 새는 경우.** DuckDB의 형식 변환 오류 메시지에는 셀 값이 그대로 들어간다(기억 기반). 실제 데이터 실행에서 난 오류는 종류와 컬럼명만 남기고 LLM에 보내지 않는다. 표시값을 심은 가상 CSV로 자가 점검을 돌려 확인한다.
10. **LLM이 쓴 코드나 SQL을 실행하기.** 하지 않는다. 계획 JSON을 허용된 연산 목록으로만 SQL로 바꾼다.
11. **LLM 문장 속 지어낸 숫자.** 빈칸 채움만 허용하고, 틀에 숫자가 있으면 버린다. 공개 데이터만 쓰는 C·E는 LLM 문장의 숫자를 도구 결과와 하나씩 대조한다.
12. **평가 도중 키 한도·쿼터 소진.** 평가자가 여러 명이고 여러 번 돌릴 수 있다. LLM은 대체 경로로, 허브 API는 스냅샷 기본값으로 막는다. 평가용 키는 평가가 끝난 11/27 23:59 뒤 폐기한다.
13. **결과와 임시 파일이 PC에 남는 경우.** DuckDB는 메모리 모드로 쓰고, 결과는 한 폴더에만 쓰며, 결과 삭제 켜기·끄기로 그 폴더를 지운다(00번 4절).
14. **소스 코드 안 데이터 출력.** 반출 정책상 코드에 데이터 출력이 남으면 반출 불가다(16번 2-2절). 데이터를 화면에 찍는 디버그 코드를 남기지 않고, 출력이 저장된 노트북 파일을 ZIP에 넣지 않는다.
15. **너무 깨끗한 가상 데이터.** 10 미만 칸, 결측 NA, 누락 월, 주제별 변화를 일부러 심지 않으면 재집계와 경고 장면이 시연에서 나오지 않는다.
16. **패키지 버전 변화.** 잠금 파일로 고정하고 `--frozen`으로만 설치한다.
17. **마감 직전 제출.** 큰 ZIP 업로드가 느리거나 실패할 수 있다. 11/20 08:00까지 제출하고, 11/19 18:00 뒤에는 코드를 바꾸지 않는다.
