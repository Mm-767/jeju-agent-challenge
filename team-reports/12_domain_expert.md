# 제주 지역·공공정책 도메인 전문가 보고서

작성: 2026-11-13. 조사 방법: 웹 검색 11회와 기사 원문 19건의 작성일·본문 확인, 제주데이터허브 데이터 목록 xlsx 키워드 검색(필요한 데이터 이름만 인용). 검색 도구(Firecrawl)가 도중에 일일 한도에 걸려, 기사 날짜 확인은 공개 기사 페이지를 직접 읽어서 했다.

## 결론 5줄

1. 2026년 제주에서 가장 크고 시급한 현안은 내국인 관광 감소다. 2026년 10월 1~25일 내국인 관광객이 전년보다 12.7% 줄었고, 연초 이후 누적도 0.5% 감소로 돌아섰다. 같은 흐름 위에 소비 위축과 상가 공실, 소상공인 경영난이 겹쳐 있다.
2. 지역화폐 탐나는전은 2026년 2월 적립률 20% 상향 뒤 이용이 몰려 캐시백이 일시 중단됐고, 발행 규모가 본예산 추계 3,600억 원에서 추경 8,000억 원으로 늘었다는 도의회 질의가 나왔다. "그래서 효과가 어디로 갔나"를 답할 도구가 없다는 점이 Agent 기회다.
3. 데이터 뒷받침은 관광·소비 현안이 가장 강하다. 허브의 「읍면동 단위 내국인 유동인구」(일 단위 자동갱신 API)와 센터의 카드·탐나는전·외식업 포스 데이터가 맞물린다. 반면 청년 유출, 쓰레기, 전기차는 허브 데이터가 2019~2023년에 멈춰 있어 Agent가 할 일이 적다.
4. 아이디어 3개를 낸다. 탐나는전 효과 점검 Agent(센터 데이터 중심, 도정 현안 직결, 겹칠 가능성 낮음~중간), 내국인 관광 감소 진단 Agent(허브 API 실데이터로 시연 가능, 겹칠 가능성 중간), 월동채소 출하 상황 브리핑 Agent(공개 데이터만 써서 외부 LLM 제약이 없음, 겹칠 가능성 낮음). 도메인 관점의 1순위는 탐나는전이지만, 센터 탐나는전 데이터에 업종·읍면동 구분이 있는지 데이터 분석가가 확인해야 확정할 수 있다.
5. 제주도와 제주테크노파크는 '지역 주도형 AI 대전환'(국비 140억 원대, 2025-10)과 'AX 대전환 기획·타당성 검증' 용역(2026-07)을 추진 중이지만, 대상 산업은 에너지·청정바이오·우주항공이다. 관광·지역화폐·1차산업 Agent를 주최 측이 반길 것이라는 판단에는 직접 근거가 없고 추론이다.

### 제주도·제주테크노파크의 데이터·AI 정책 방향

- 제주도와 제주테크노파크는 중소벤처기업부의 '지역 주도형 AI 대전환' 공모에서 13개 지자체 가운데 5곳 중 하나로 선정돼 국비 140억 원대를 확보했다. 목적은 지역 주력산업과 AI를 연계한 인프라 구축, 솔루션 도입, 인재 양성이다(헤드라인제주 2025-10-01). 제주도는 2024년 12월 '제주 인공지능·디지털 대전환 로드맵'을 발표했다(같은 기사).
- 제주테크노파크는 4억 4천만 원으로 '제주 AX 대전환 사업 기획 및 타당성 검증 지원' 용역을 추진하며, 에너지·청정바이오·우주항공 산업의 가치사슬과 데이터센터 후보지를 검토한다(제주의소리 2026-07-08, 다음 뉴스 게재).
- 제주테크노파크는 제주빅데이터 플랫폼과 빅데이터센터 인프라로 도내 기업에 맞춤 데이터 가공·분석을 지원해 왔다고 밝혔다(미디어제주 2021-03-10, 데이터바우처 공급기관 선정 기사).
- 해석(추론): 정책 문서의 AI 대전환 대상은 주력 제조·바이오 산업이라 관광·지역화폐 Agent와 직접 연결되지 않는다. 다만 빅데이터센터는 기관·기업 이용자가 SQL 없이 현황자료를 만드는 곳이므로(브리핑 6절과 4절), 도정 현안에 대한 질문을 센터 데이터로 바로 답해 주는 Agent가 센터의 존재 이유와 맞는다는 판단은 가능하다. 대상이 도지사상이라 도정 현안(관광, 지역화폐, 1차산업)과 맞닿은 주제가 유리할 수 있다는 것도 추론이다.

## 아이디어 3개

세 아이디어 모두 같은 기준으로 적었다. 경쟁 쏠림은 브리핑 7절의 게시판 신호, 시연 가능성은 "가상 데이터와 허브 공개 API로 평가 환경에서 실제로 돌아가는가"로 판단했다.

### 아이디어 1: 탐나는전 효과 점검 Agent

- 한 줄 요약: 센터의 탐나는전 이용 CSV와 카드 이용 CSV를 넣으면, 적립률·한도가 바뀐 시기 전후로 탐나는전 결제가 어느 업종·지역으로 움직였는지 일반 카드 결제와 비교해 정책 검토용 보고서와 반출 가능한 표를 만든다.
- 누가 쓰나: 제주도 경제활력국 지역화폐 담당 공무원, 도의회 예산 심사를 돕는 정책지원 인력, 제주연구원 연구원. 상황 예시는 2026년 7월 추경 심사에서 "발행 규모가 두 배 넘게 늘었는데 이유가 무엇이냐"는 질의에 답할 자료를 만들어야 할 때다.
- 해결하는 문제: 지금은 발행액과 캐시백 총액은 말할 수 있어도, 그 돈이 골목상권으로 갔는지 대형 매장으로 갔는지는 센터에서 월별 CSV를 여러 번 받아 엑셀로 손으로 합쳐야 알 수 있다. 센터 이용자는 SQL을 쓰지 않고, 반출하려면 10 미만 칸을 상위 단위로 다시 묶는 작업도 손으로 해야 한다.
- 쓰는 데이터:
  - 센터(필수): 「탐나는전 이용 현황」(센터 명세서 번호 1-32), 「카드 이용 현황(읍면동)_v02」(비교군), 「제주도 내 업종별 매장 수」.
  - 허브: 「제주특별자치도 상가(상권) 정보」(2025-09-18 등록), 「업종별 성별 카드 이용 정보」(File, 2018-01~2025-06), 「소상공인시장진흥공단 소상공인 경기동향(BSI) 현황」.
- AI가 맡는 일:
  - LLM이 판단·계획·도구 호출하는 부분: 사용자의 자연어 질문을 분석 계획으로 바꾼다(비교 기간, 비교군, 지역 단위, 업종 묶음). 계획에 필요한 센터 파일 목록과 조회 조건(데이터 이름, 월, 조건)을 사용자에게 안내한다. 불러온 CSV가 계획과 맞는지 스키마 검사 도구를 부르고, 결과 표에 10 미만 칸이 생기면 읍면동에서 권역·시 단위로 다시 집계하도록 스스로 재계획한다.
  - 일반 코드가 하는 부분: CSV 읽기와 헤더 검증, 월별 집계, 이벤트 전후 비교(탐나는전 증가율에서 같은 업종 일반 카드 증가율을 뺀 값), 10 미만 범주처리와 역산 가능성 점검, 차트와 PDF 보고서 생성, 결과 삭제 기능.
- 센터 데이터를 외부 LLM에 보내지 않는 방법: 외부 LLM에는 사용자 질문(숫자가 섞이면 전송 전에 막는다), 공개된 센터 데이터 명세서의 컬럼 이름, 허브 공개 데이터 값, 도구 실행 성공·실패 같은 구조 정보만 보낸다. 센터 CSV에서 나온 수치는 로컬 메모리 안에서 표·차트·고정 문장 틀로만 채운다. 수치 해석 문장까지 필요하면 로컬 소형 모델을 쓰는 선택지가 있다(가능 여부는 AI 엔지니어 판단).
- 시연 방법: 센터 CSV 형식(영문 헤더, 모든 값 큰따옴표, NA 결측, Results_YYYYMMDD_HHMMSS.csv 파일명)을 따른 가상 탐나는전·카드 CSV 6개월치를 준비하고, 적립률 상향 달에 음식점 업종 결제가 늘도록 값을 심어 둔다. 평가 화면에서 "적립률을 올린 달에 원도심 음식점 결제가 늘었는지 보여줘"라고 입력하면 Agent가 받을 파일 목록을 안내하고, 비교 계획을 보여 준 뒤, 차트와 함께 10 미만 칸을 권역 단위로 묶은 반출용 표를 만든다.
- 다른 팀과 겹칠 가능성: 낮음~중간. 게시판에 탐나는전 데이터 언급은 있지만 정책 효과 점검 구상은 드러나지 않았다. 다만 화면만 보면 "CSV를 넣으면 분석해 주는 범용 분석기"(브리핑 7절에서 경쟁이 몰린 유형)와 비슷해 보일 수 있으므로, 질문과 보고서 양식을 탐나는전 정책 질문에 고정해야 차별화된다.
- 가장 큰 위험:
  - 센터 「탐나는전 이용 현황」의 컬럼이 확인되지 않았다. 업종이나 읍면동 구분이 없으면 핵심 비교가 불가능하다. 수록 기간이 2025-09까지라면 2026년 20% 적립 기간은 분석할 수 없고, 그 이전의 적립률 변경 이력을 공개 기사로 확정해야 한다.
  - 전후 비교를 인과 효과처럼 말하면 결과 신뢰성 점수를 잃는다. 보고서에 "전후 비교이며 다른 요인을 통제하지 않았다"는 한계를 고정 문구로 넣어야 한다.

### 아이디어 2: 내국인 관광 감소 진단 Agent

- 한 줄 요약: 월간 관광객 통계가 나오면 내국인 감소가 어느 권역·읍면동, 어떤 업종, 어떤 연령층에 몰렸는지 허브 유동인구 API와 센터 카드 데이터로 쪼개 보여 주고, 다음 달에 확인할 항목을 제안한다.
- 누가 쓰나: 제주도 관광정책 부서와 제주관광공사 담당자, 관광협회, 숙박·렌터카 업체 기획 담당, 관광 연구원. 상황 예시는 "10월 내국인 12.7% 감소" 같은 보도가 나온 직후 원인 설명 자료를 만들어야 할 때다.
- 해결하는 문제: 관광객 수는 입도객 총량으로만 나와서 지역·업종별 영향을 보려면 여러 데이터를 따로 받아 맞춰야 한다. 실종 사건 파문, 엔저, 고비용 같은 원인 설명이 분분한데(JIBS 기사 제목 "사건 하나로 설명되지 않는 흐름"), 감소분을 축별로 나눠 보여 주는 도구가 없다.
- 쓰는 데이터:
  - 허브(필수): 「읍면동 단위 내국인 유동인구」(API, 일 갱신), 「제주관광공사_제주방문관광객_통계」(Link, 연 갱신), 「일별 기상 정보」(API, 일 갱신), 「관광 숙박업 정보」(API).
  - 센터: 「내국인·중국인 카드 이용 현황과 이용 금액(관광업종)」, 「카드 이용 현황(읍면동)_v02」(user_type, tour_type, age, sex 컬럼으로 관광객과 도민, 연령 분해), 「내국인 유동인구(읍면동 v02)」.
- AI가 맡는 일:
  - LLM이 판단·계획·도구 호출하는 부분: 질문을 받아 분해 축(7개 권역, 업종, 연령, 관광객·도민)의 순서를 정하고, 허브 API 조회 기간을 정해 호출한다. 특정 읍면동 급감 같은 이상치가 나오면 기상 데이터로 교차 확인할지 판단한다. 공개 데이터 부분의 해석 문장을 쓴다.
  - 일반 코드가 하는 부분: API 호출과 캐시, 전년 동월 대비 계산, 감소분 기여도 분해(어느 축이 감소분의 몇 퍼센트인지), 차트와 보고서 생성.
- 센터 데이터를 외부 LLM에 보내지 않는 방법: 허브 유동인구·기상·관광객 통계 값은 공개 데이터라 외부 LLM에 보낼 수 있다. 센터 카드 수치는 로컬에서 계산해 표·차트로만 내보내고, LLM에는 "카드 데이터 분해 표 생성 완료" 같은 상태만 전달한다. 보고서는 공개 데이터 해석 구역과 센터 데이터 표 구역을 나눠 섞이지 않게 한다.
- 시연 방법: 평가 환경은 인터넷이 되므로 허브 API를 실제로 호출해 최근 달 읍면동 유동인구를 받고, 가상 카드 CSV를 넣어 "2026년 6월 내국인 감소가 어디에 몰렸나" 보고서를 생성한다. 실제 공개 데이터가 시연에 들어간다는 점이 장점이다. API 장애에 대비해 허브 데이터 스냅샷을 ZIP에 넣는다(브리핑 6-2절에 따라 허용).
- 다른 팀과 겹칠 가능성: 중간. 게시판에서 관광 감소 진단 구상은 드러나지 않았지만, 허브 데이터의 약 3분의 1(433건)이 관광이고 카드 데이터가 센터의 대표 데이터라 관광 분석 팀은 적지 않을 것이다(추론).
- 가장 큰 위험:
  - 허브 유동인구 API의 visitPop 등은 하루 시간대별 인구의 합(연인원)이라 관광객 수로 오해하기 쉽다. 지표 정의를 화면과 보고서에 명시해야 한다.
  - 센터 「카드 이용 현황(읍면동)_v02」의 최신 수록 월이 2026년 감소 시기를 포함하는지 확인되지 않았다. 포함하지 않으면 2026년 분석은 허브 데이터만으로 하고 센터 데이터는 과거 비교에만 쓰게 된다.

### 아이디어 3: 월동채소 출하 상황 브리핑 Agent

- 한 줄 요약: 허브의 농산물 일일 거래 API와 기상 API로 품목별 가격·거래량 흐름을 요약하고, 과거에 가격 곡선이 비슷했던 해와 비교해 출하 조절 회의 자료를 만든다.
- 누가 쓰나: 제주도 농업기술원·농정 부서 담당자, 농협 지역조합 유통 담당, 작목반 대표. 상황 예시는 2025~2026년산처럼 생산량이 40% 넘게 늘어 가격이 떨어질 때 출하 시기와 물량을 논의하는 회의 직전이다.
- 해결하는 문제: 일일 거래 데이터는 공개돼 있지만 품목별로 매일 찾아 이동평균과 전년 비교를 엑셀로 만들어야 한다. 재배면적·기상과 엮어 "올해는 어느 해와 비슷한가"를 보려면 여러 데이터를 손으로 합쳐야 한다.
- 쓰는 데이터:
  - 허브(필수): 「농산물 품종별 일일 거래 정보」, 「농산물 품종별 일일 거래 통계」, 「농산물 품종별 거래 이동평균」(API, 일 갱신), 「일별 기상 정보」(API, 일 갱신), 「시도별 노지 채소 재배 면적」(File, ~2025-12), 「제주 채소류 재배 현황」(File, 2021).
  - 센터: 필수 아님. 쓰지 않는 것을 기본으로 한다.
- AI가 맡는 일:
  - LLM이 판단·계획·도구 호출하는 부분: "이번 주 당근 출하를 늘려도 되나" 같은 질문을 받아 품목, 기간, 비교 연도를 정하고 API를 호출한다. 결과를 보고 기상 이상 여부를 추가로 확인할지 판단하고, 회의용 요약문을 쓴다.
  - 일반 코드가 하는 부분: API 수집과 캐시, 이동평균과 전년 동기 대비 계산, 가격 곡선 거리로 유사 연도 찾기, 차트 생성.
- 센터 데이터를 외부 LLM에 보내지 않는 방법: 공개 데이터만 쓰므로 해당 사항이 없다. 기획서에 "센터 데이터 미사용, 외부 LLM에는 허브 공개 데이터만 전송"이라고 명시한다. 같은 Agent를 개인 PC에서도 실행할 수 있어(브리핑 4절) 센터 밖 농협 사무실에서도 쓸 수 있다.
- 시연 방법: 평가 환경에서 허브 API를 실제로 호출해 최근 30일 당근·월동무 거래 데이터를 받아 브리핑을 생성한다. 키 문제나 API 장애에 대비해 허브 데이터 스냅샷을 ZIP에 넣는다.
- 다른 팀과 겹칠 가능성: 낮음. 브리핑 7절의 게시판 신호에 농산물 주제는 없다.
- 가장 큰 위험:
  - 허브 농산물 API가 어느 시장(제주 지역 공판장인지 도외 도매시장 반입인지)과 어떤 품목을 담는지 확인되지 않았다. 월동무·당근·양배추가 없으면 주제를 바꿔야 한다.
  - 센터 데이터를 쓰지 않아 "빅데이터센터 PC에서 실행하는 Agent"라는 대회 취지와 거리가 있어 보일 수 있다. 허브 데이터도 필수 데이터로 인정되지만, 심사위원이 센터 데이터 활용을 더 높게 볼지는 알 수 없다(추론). 또 가격 예측으로 범위를 넓히면 정확도 검증이 어려우므로 현황과 유사 연도 비교로 범위를 묶어야 한다.

### 같은 기준으로 검토했지만 아이디어로 올리지 않은 후보

- 원도심 상권 공실 진단: 문제 크기와 데이터 뒷받침은 크지만, 허브에 공실 데이터가 없어 공실을 직접 볼 수 없고, 상권분석·소상공인·외식업 포스 주제는 브리핑 7절에서 경쟁이 몰릴 것으로 추정된 영역이라 겹칠 가능성이 높다.
- 버스 노선 개편 효과 점검: 허브 일 갱신 API가 풍부하고 공개 데이터라 시연이 가장 쉽다. 다만 확인한 현안 근거가 2024년 개편이고 2025~2026년 후속 기사를 찾지 못했으며, 수요응답형 버스 분석 팀(게시판 신호)과 겹칠 가능성이 중간이다. 팀이 "시연 안정성"을 가장 중요하게 본다면 아이디어 3 대신 올릴 만하다.
- 청년 유출, 쓰레기·클린하우스, 전기차: 허브 데이터가 2019~2023년에 멈춰 있어 Agent가 반복해서 할 일이 적고, 클린하우스와 전기차는 게시판에 이미 같은 주제 팀이 있다.

## 다른 팀원이 확인해 주면 좋을 질문

- 데이터 분석가에게: 센터 명세서에서 「탐나는전 이용 현황」(1-32)의 컬럼(업종, 읍면동, 이용자 구분 유무)과 실제 수록 기간을 확인해 주세요. 「카드 이용 현황(읍면동)_v02」의 최신 수록 월이 2026년을 포함하는지도 필요합니다. 허브 「농산물 품종별 일일 거래 정보」 API가 담는 시장과 품목(월동무, 당근, 양배추 포함 여부)도 확인 부탁드립니다.
- 컴플라이언스 책임자에게: 공개된 센터 명세서의 컬럼 이름(값 없이)을 외부 LLM에 보내는 것은 외부 전송에 해당하지 않는다고 보는데(명세서가 외부 공개 자료이므로, 추론), 이 해석이 맞는지 판단해 주세요. 사용자 질문 문장에 센터 수치가 섞여 외부로 나가는 것을 막는 방식도 기준이 필요합니다.
- AI 엔지니어에게: GTX 1060(VRAM 3GB)과 RAM 32GB 환경에서 센터 수치 해석 문장을 로컬 소형 모델로 쓸 수 있는지, 아니면 고정 문장 틀로 충분한지 판단해 주세요.
- 사용자 리서처에게: 지역화폐 담당 공무원이나 도의회가 실제로 원하는 지표(골목상권 결제 비율, 업종 쏠림, 캐시백 1원당 결제액 등)와, 농협·농업기술원이 출하 조절 회의에서 쓰는 자료 형태를 확인해 주세요.
- 경쟁 분석가에게: 관광 감소, 지역화폐, 농산물 주제를 다루는 팀 신호가 게시판 밖(공개 저장소, 블로그 등)에 있는지 확인해 주세요.
