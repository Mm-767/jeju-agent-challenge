# 보안·컴플라이언스 구현 설계: 「행사 효과 나란히」

작성: 보안·컴플라이언스 설계자 / 작성일 2026-11-13 / 근거: 40_plan_brief.md, 16_compliance_officer.md(전문), 00_brief.md 4·5절, 30_pm_decision.md 2-1·4-2·6·7절, app/ 코드와 설치된 패키지를 직접 확인한 결과. 이 문서는 설계만 담고 코드는 만들거나 고치지 않았다. .env는 존재와 권한(600)만 확인하고 내용은 열지 않았다.

## 결론 5줄

1. 외부 통신은 파일 하나(가칭 egress.py, 아래에서는 "외부 통신 모듈")에서만 하고, 같은 파일이 파이썬 표준 기능인 감사 훅(sys.addaudithook, 프로그램 안의 모든 소켓 연결 시도를 가로채는 장치)을 걸어 이 모듈 밖이나 잠금 상태에서 일어나는 외부 연결을 운영체제 수준 직전에서 막고 기록한다. 이렇게 하면 라이브러리가 몰래 통신해도 걸러지고, 그 건수를 화면에 0건으로 보여 줄 수 있다.
2. 잠금은 센터 형식 CSV를 읽기 시작하는 순간(파일 내용을 열기 전) 걸리고, 잠금 뒤에는 외부 요청이 한 건도 나가지 않는다. 사용자가 직접 친 문장은 공개 행사 이름, 읍면 이름, 정해진 날짜 형식을 지운 뒤 숫자가 하나라도 남으면 보내지 않는다. 자가 점검은 실제로 나올 수 없는 9자리 숫자와 문자열(표시값)을 심은 가상 CSV로 전체 흐름을 돌려, 전송 기록과 보고서 글자에 표시값과 그 합계가 0건인지, 잠금 뒤 전송이 0건인지, 모듈 밖 외부 연결이 0건인지를 한 화면에서 보여 준다.
3. 반출 정책 조항 7개는 모두 코드 위치와 확인 방법을 붙였다. 결과물은 증가율·퍼센트포인트 차이·지수만 내고, 바탕 칸은 인원·건수 10 이상만 쓰며(범주처리 먼저, 그다음 삭제처리), 합계·원래 금액·행 수는 반출 파일에 넣지 않고, 내보내는 파일은 png와 PDF뿐이다. 다만 읍면이 카드 데이터의 제공 단위와 같아 "제공 단위 그대로의 통계 처리 반출 불가" 조항에 걸리는지는 운영진 답을 받아야 확정된다.
4. 오늘 확인한 사실 중 계획에 반영해야 할 것이 셋 있다. 첫째, 설치된 fastapi 0.162.5에는 원격 측정 기능(OpenTelemetry)이 내장돼 있어 opentelemetry-api가 필수로 깔리지만, 실제로 밖으로 보내는 부품(opentelemetry-sdk, OTLP 내보내기)은 설치돼 있지 않으므로 계속 설치하지 않는 것을 확인 항목으로 둔다. 둘째, 맥에서 윈도우용 패키지를 받을 때 pip이 만드는 .pyc 파일에 맥의 개인 경로가 박히므로 --no-compile로 받고 __pycache__를 ZIP에서 뺀다. 셋째, Python과 패키지를 ZIP에 넣기로 했으므로(ADR-149) 실행 중 외부 주소는 api.anthropic.com과 open.jejudatahub.net 두 곳뿐이다.
5. 사용자 결정이 필요한 것은 네 가지다. 외부 통신을 표준 라이브러리로 할지 Anthropic SDK로 할지(추천: 표준 라이브러리), 잠금 해제를 "새로 시작" 버튼으로 허용할지 프로그램 재시작으로만 할지(추천: 버튼, 메모리 비우기와 묶음), 결과 삭제 기본값(추천: 켜짐), 평가용 키를 ZIP의 .env에 미리 넣고 README에도 적을지(추천: 둘 다)다.

## 0. 오늘 직접 확인한 것

- app/.gitignore는 .env, .venv/, __pycache__/, out/ 네 줄이다. app/는 git 저장소가 아니다. 결과물을 out/ 한 폴더에 쓰는 원칙과 맞는다. 지금 out/에는 수집기 로그(fetch_population.log)만 있다.
- server.py는 127.0.0.1:8501에만 열고, 데이터 출력(print, head)이 없다. tools/ 세 파일의 print는 개수와 경고만 찍고 데이터 행은 찍지 않는다.
- tools/fetch_population.py는 표준 라이브러리 urllib로 허브를 부른다. 허브 프로젝트 키가 주소 경로에 들어간다(`/api/proxy/{데이터ID}/{프로젝트키}?...&emd=애월읍`). 오류 메시지에는 주소 대신 요청 조건만 찍어서 키가 로그에 남지 않는다. 이 방식은 외부 통신 모듈에서도 그대로 지켜야 한다.
- 설치된 패키지 18개의 라이선스를 패키지 메타데이터에서 직접 읽었다(6절 표). 모두 MIT, BSD-3-Clause, Apache-2.0, PSF-2.0이라 센터 비독점 이용과 충돌하지 않는다.
- 네트워크 코드를 가진 패키지를 찾았다. 소켓·HTTP 모듈을 불러오는 파일이 있는 패키지는 anyio, uvicorn(로컬 서버용), starlette(시험용 클라이언트와 예외 처리), fastapi(openapi/utils.py 한 파일, 상태 문구 표를 쓰는 것으로 보임, 추정), opentelemetry(주소 문자열 처리), pip·setuptools(설치 도구)다. 실행 중 외부로 연결하는 코드는 찾지 못했다. 이 점검은 정적 검색이라 "없음"을 증명하지 못하므로 1-2절의 감사 훅으로 실행 중에도 막는다.
- fastapi 0.162.5에는 fastapi/telemetry/ 폴더가 있고, `FastAPI(telemetry={...})` 설정과 OTEL_EXPORTER_OTLP_ENDPOINT 같은 환경변수로 OTLP 내보내기를 켤 수 있다는 설명이 있다. 설치된 opentelemetry 폴더에는 API 모듈만 있고 SDK와 내보내기 부품은 없다. 따라서 지금 상태로는 밖으로 보낼 수 없다. 내보내기가 어떤 환경변수로 기본 켜짐이 되는지는 끝까지 읽지 않았다.
- 차단 키워드 133개 전체 목록은 웹 검색으로 찾지 못했다. 브리핑에 있는 예시 14개만으로 대조했다(5절).

## 1. 외부 전송 경계 구현

### 1-1. 외부 통신을 한 파일로 모은다

- 규칙: 외부로 나가는 요청은 외부 통신 모듈의 함수 두 개(외부 AI 호출, 허브 유동인구 호출)로만 보낸다. 다른 파일은 urllib.request, http.client, socket, httpx, requests, anthropic을 불러오지 않는다.
- 허용 목적지는 코드에 고정한 두 곳이다. api.anthropic.com(외부 AI), open.jejudatahub.net(허브 Open API). 다른 주소로 가는 요청은 이유 "허용되지 않은 주소"로 막고 기록한다.
- 비용 상한도 이 모듈에 둔다. 한 세션의 외부 AI 호출 횟수 상한과 요청 본문 크기 상한을 상수 두 개로 둔다(값은 리허설 측정 뒤 정한다). 센터가 API 비용을 낸다는 운영진 답변(브리핑 3절)에 대응한다.
- 키는 환경변수를 먼저 읽고 없으면 .env를 읽는다. 운영 시 센터 담당자가 환경변수로 넣는다는 운영진 답변에 맞춘다.

확인 방법: 정적 검사 한 줄을 자가 점검과 제출 전 점검에 넣는다. app/ 아래에서 외부 통신 모듈을 뺀 파이썬 파일에 위 모듈 이름을 불러오는 줄이 0개여야 한다.

**사용자 결정 필요: 외부 AI를 부르는 방식**

| 비교 | 표준 라이브러리 urllib (추천) | Anthropic 공식 SDK |
|---|---|---|
| 추가 패키지 | 0개. 이미 fetch_population.py에서 쓰는 방식 | anthropic, httpx, httpcore, certifi, distro, jiter 등 여러 개가 늘어난다. 라이선스 표와 정적 점검 대상도 늘어난다 |
| 센터 보안 장비와의 궁합 | 윈도우에서 파이썬 표준 ssl은 윈도우 인증서 저장소를 읽고, urllib은 윈도우 프록시 설정(레지스트리)을 읽는다. 센터 DLP가 암호화 통신을 검사하려고 자체 인증서를 쓰더라도 통과할 가능성이 높다(추론, 센터가 그런 검사를 하는지는 모른다) | httpx는 기본으로 certifi 인증서 묶음을 쓰고 프록시는 환경변수만 읽는다. 같은 상황에서 인증서 오류가 날 수 있어 `verify=ssl.create_default_context()`를 직접 넘겨야 한다 |
| 코드량 | 재시도·시간 제한을 직접 쓴다. 약 30줄. 수집기의 재시도 코드를 옮겨 쓴다 | 재시도, 형식 검사, 도구 호출 형식이 들어 있다 |
| 보내는 내용 | 필요한 머리글 세 개(키, API 버전, 형식)만 보낸다 | 운영체제, CPU 종류, 파이썬 버전을 담은 머리글(X-Stainless 계열)을 함께 보낸다. 데이터는 아니지만 외부 전송 명세표에 적어야 한다 |
| 감사 | 요청 본문이 우리가 만든 JSON 그대로라 기록과 실제 전송이 같다 | SDK가 본문을 다시 만들므로 기록 시점과 전송 시점의 본문이 같은지 따로 확인해야 한다 |

추천 이유: 이 제품의 외부 AI 호출은 Messages API에 JSON 하나를 보내는 일이라 SDK의 편의가 크지 않다. 반면 센터 보안 장비 아래에서 인증서와 프록시를 덜 신경 쓰고, 패키지와 점검 대상이 늘지 않는 이득이 확실하다. AI 엔지니어나 아키텍트가 SDK를 고르면 위의 verify 설정과 머리글 기록을 조건으로 붙인다.

### 1-2. 라이브러리가 몰래 통신하지 못하게 하는 감사 훅

- 외부 통신 모듈을 불러오는 순간 `sys.addaudithook`으로 감시 함수를 건다. 파이썬은 소켓 연결(socket.connect)과 주소 조회(socket.getaddrinfo) 직전에 이 함수를 부르고, 함수가 예외를 내면 연결이 일어나지 않는다. 한 번 건 감사 훅은 프로그램이 끝날 때까지 뗄 수 없다.
- 판단 규칙은 세 가지다.
  - 목적지가 루프백 주소(127.0.0.1, ::1, localhost)면 통과시킨다. 윈도우의 비동기 처리 기반은 내부적으로 127.0.0.1에 소켓을 연결하므로 이 예외가 없으면 서버가 멈춘다.
  - 외부 통신 모듈의 함수 안에서 일어난 연결이고, 잠금이 꺼져 있고, 목적지가 허용 두 곳이면 통과시킨다. "함수 안에서"는 contextvars 표시로 판단한다.
  - 나머지는 모두 막고 "모듈 밖 외부 연결 시도"로 전송 기록에 남긴다.
- server.py의 첫 import를 외부 통신 모듈로 해서, 다른 라이브러리가 불리기 전에 훅이 걸리게 한다.
- 한계: 파이썬 소켓 모듈을 거치지 않는 C 확장(예를 들어 자체 네트워크 라이브러리를 쓰는 확장)과 별도 프로세스는 이 훅에 잡히지 않는다. 지금 패키지 중 그런 것은 없다. 새 패키지를 넣을 때마다 0절의 정적 검색을 다시 돌린다. 같은 훅에서 subprocess.Popen 이벤트도 막아 별도 프로세스 실행을 차단한다.

확인 방법: 자가 점검 중 "잠금 상태에서 외부 통신 모듈 밖에서 일부러 example.com에 연결 시도"를 한 번 해서 막히는지 본다. 결과는 "모듈 밖 외부 연결 시도 1건, 성공 0건"으로 보인다.

### 1-3. 센터 CSV를 불러오면 외부 호출을 잠근다

- 잠그는 시점: 센터 파일 불러오기 경로의 첫 줄에서 잠근다. 파일 내용을 열거나 형식 검사를 하기 전이다. 형식 검사 오류 문장에는 센터 값이 들어 있을 수 있는데, 이 순서면 오류가 나도 이미 잠긴 상태다.
- 잠금 대상: 센터 형식 CSV는 출처와 상관없이 센터 데이터로 본다. "예시로 해 보기"가 동봉 가상 CSV를 넣을 때도 같은 경로를 타서 잠긴다. 그래야 시연에서 잠금 장면이 실제 동작으로 보인다.
- 리허설은 잠금과 별개다. 리허설은 동봉 가상 데이터(data/dummy/)를 별도 함수로 읽고, 그 결과가 외부 AI에 간다(30번 2-1절). 누군가 실제 센터 CSV를 data/dummy/에 넣는 경우를 막으려면, 리허설이 읽는 파일의 SHA-256 값을 빌드 때 목록으로 남기고 다르면 읽지 않게 한다. 약 5줄이며, 밀리면 자를 수 있는 항목으로 둔다.
- 잠금 중 외부 통신 모듈의 함수를 부르면 "센터 데이터 모드라 외부 AI를 부르지 않았습니다" 이유로 예외를 내고, 호출한 쪽은 미리 만든 계획이나 고정 문장으로 넘어간다. 30번 2-1절대로 후보 교체 순서는 잠금 전에 LLM이 정해 두므로 잠금 뒤에는 LLM이 필요 없다.
- 화면: 상단 띠가 "센터 데이터 모드: 외부 AI 연결 잠김"으로 바뀌고, 옆에 "잠금 뒤 외부 전송 0건"이 숫자로 붙는다.

**사용자 결정 필요: 잠금을 푸는 방법**

| 비교 | "새로 시작" 버튼으로 해제 (추천) | 프로그램 재시작으로만 해제 |
|---|---|---|
| 동작 | 버튼이 서버 메모리의 센터 데이터와 계산 결과를 모두 버리고, 결과 삭제가 켜져 있으면 out/도 지운 뒤 잠금을 푼다 | run.bat 창을 닫고 다시 실행해야 풀린다 |
| 사용 편의 | 다른 행사를 바로 분석할 수 있다 | 비개발자에게 "검은 창을 닫았다 다시 열라"는 단계가 생긴다 |
| 위험 | 결과 삭제가 꺼진 상태면 out/에 보고서 파일이 남은 채 잠금이 풀린다. 외부 AI에 보내는 내용은 공개 자료로만 만들고 out/를 읽지 않으므로 새는 길은 없다(정적 검사로 확인) | 가장 단순하고 설명하기 쉽다 |

추천 이유: 잠금 해제를 메모리 비우기와 한 동작으로 묶으면 "센터 데이터가 메모리에 있는데 잠금이 풀린 상태"가 생기지 않는다. 별도의 "잠금 해제" 버튼은 만들지 않는다.

### 1-4. 사용자가 직접 친 문장의 숫자 검문 규칙

설계 원칙은 "사용자 입력은 되도록 외부 AI에 보내지 않고, 로컬에서 빈칸에 채운다"이다. 활용 사유 문안의 "어디에 활용" 칸, 기관 이름 같은 입력은 외부 AI를 거치지 않는다. 그래도 외부 AI로 가는 사용자 입력(행사 검색어, 날짜·장소 정정 메모 등)에만 아래 규칙을 건다. 코드가 공개 자료로 만든 내용(허브 유동인구 숫자 등)에는 걸지 않는다.

1. 잠금 중이면 내용과 상관없이 보내지 않는다.
2. 유니코드 정규화(NFKC)로 전각 숫자를 일반 숫자로 바꾼다.
3. 허용 문자열을 지운다. 공개 행사 파일의 행사 이름과 정확히 같은 부분(예: "2025 보롬왓 튤립축제", "9.81파크 구팔일 억새바당"처럼 이름에 숫자가 있는 행사가 있다), 읍면 12곳 이름, 명세서의 업종코드(G47119 같은 6자리)다.
4. 날짜 형식을 지운다. 2017~2027 사이 연도의 `YYYY-MM-DD`, 실제 달력 날짜로 해석되는 8자리 `YYYYMMDD`, `YYYY년 M월 D일`, `M월 D일`. 8자리 숫자는 날짜로 해석될 때만 지운다. 그렇지 않으면 12345678원 같은 금액이 빠져나간다.
5. 남은 글자에 숫자가 하나라도 있으면 막는다. 파이썬 정규식의 `\d`는 모든 유니코드 숫자를 잡는다.
6. 한글 수 표현을 막는다. `만 원`, `억`, `천 명`, `퍼센트`, `프로`, `%`, 그리고 `[일이삼사오육칠팔구십백천만억]+`에 원·명·건이 붙은 형태다.
7. 막았을 때 보여 줄 문장: "숫자가 들어 있어 외부 AI로 보내지 않았습니다. 센터 데이터 값이 섞일 수 있어서입니다. 날짜는 2024-07-19처럼 쓰거나, 숫자를 빼고 다시 입력해 주세요."

한계: "일곱 명"처럼 고유어로 쓴 수는 다 잡지 못한다. 이 규칙은 센터 CSV를 불러오기 전(공개 단계)에만 의미가 있고, 남는 위험은 사용자가 예전 세션에서 본 값을 기억해 치는 경우다. 기획서 한계 항목에 그대로 적는다.

확인 방법: 표 형태 시험 20줄을 만든다. 막아야 할 예(`애월읍 매출 3,482만원`, `１２３４５`, `증가율 12.5%`, `이백만 원`, `12345678`)와 통과해야 할 예(`2025 보롬왓 튤립축제`, `2024-07-19부터 9월 15일까지`, `애월읍 행사 장소 확인`)가 기대대로 나오는지 assert로 확인한다.

### 1-5. 전송 기록 형식

- 위치: out/egress_log.jsonl. 한 줄에 요청 하나인 JSON Lines 형식이다. out/ 안이라 결과 삭제 대상에 들어간다.
- 보낸 요청 한 줄의 필드:

```json
{"seq": 3, "ts": "2026-11-17T14:03:22+09:00", "dest": "api.anthropic.com", "path": "/v1/messages",
 "purpose": "비교 읍면 고르기", "locked": false, "status": "sent", "http": 200, "ms": 2140,
 "bytes_out": 18234, "bytes_in": 2311, "sha256": "본문의 SHA-256", "body": "보낸 JSON 본문 전체"}
```

- 허브 요청은 path에 키 자리를 `{프로젝트키}`로 바꿔 적는다. 예: `/api/proxy/{데이터ID}/{프로젝트키}?startDate=20240701&endDate=20240706&emd=남원읍&limit=100&number=1`.
- 머리글(x-api-key 등)은 기록하지 않는다. 응답 본문도 기록하지 않는다(크기만 적는다).
- 막힌 요청은 `"status": "blocked"`, `"reason"`(잠금, 숫자 검문, 허용되지 않은 주소, 모듈 밖 연결, 호출 상한 중 하나), 보내려던 본문의 크기와 SHA-256만 적고 본문은 적지 않는다.
- 화면: "외부 전송 기록" 표에 시각, 받는 곳, 목적, 크기, 상태를 보이고, 줄을 누르면 본문 전체를 펼친다. 센터 담당자가 열람할 수 있게 한다는 16번 체크리스트 항목에 대응한다.

### 1-6. 자가 점검 설계

표시값은 실제 데이터에서 나올 수 없는 값을 일부러 심어, 그 값이 어디로 새는지 찾기 위한 값이다.

1. 표시값 CSV 만들기: 실행할 때마다 무작위 9자리 숫자 여러 개를 user_cnt, use_cnt, use_amt에 넣은 센터 형식 CSV를 out/tmp/에 만든다. 9자리로 하는 이유는 공개 유동인구 숫자와 우연히 겹치지 않게 하려는 것이다. 파일 이름은 `Results_20991231_235959.csv`로 하고, 한 행의 sex 값에 표시 문자열(예: `표시값Q7Z`)을 넣어 형식 검사 오류를 일부러 낸다. 오류 문장이 외부로 가는지 보기 위해서다.
2. 전체 흐름 실행: 공개 단계(키가 있으면 실제 외부 AI, 없으면 미리 만든 계획)를 돌리고, 표시값 CSV를 센터 불러오기 경로로 넣어 잠근 뒤, 계산·png·PDF를 out/selfcheck/에 만든다. 잠금 상태에서 외부 AI 호출을 한 번 일부러 시도하고, 1-2절의 모듈 밖 연결 시도도 한 번 한다.
3. 판정 항목과 통과 기준:

| 항목 | 통과 기준 |
|---|---|
| 잠금 뒤 실제로 나간 외부 요청 | 0건 |
| 잠금 뒤 일부러 한 외부 AI 호출 | 1건 시도, 1건 막힘 |
| 모듈 밖 외부 연결 시도 | 1건 시도(일부러 한 것), 성공 0건 |
| 전송 기록 전체에서 표시값 발견 | 0건. 원래 숫자, 쉼표 넣은 숫자, 만 단위 표기, 읍면·달별 합계를 모두 찾는다. 표시 문자열과 표시 파일 이름도 찾는다 |
| 보고서 글자와 png를 만든 글자에서 표시값과 그 합계 발견 | 0건. 반출 파일로 원래 값이 새는지도 같은 방법으로 본다 |
| 반출 폴더의 파일 종류 | .pdf와 .png만 |
| 원격 측정 부품 | opentelemetry.sdk와 OTLP 내보내기 모듈을 불러올 수 없어야 한다 |

4. 끝나면 자가 점검 결과물을 지우고 잠금을 푼다. 결과 요약(항목, 건수, 통과 여부, 실행 시각)은 화면에 보이고, 기획서와 결과 설명자료에 캡처로 넣는다. 표시값 자체는 가짜 값이라 보여 줘도 된다.
5. 같은 함수를 명령줄로도 돌릴 수 있게 해 개발 중 회귀 점검과 11/19 윈도우 시험에 쓴다.
6. 자가 점검 버튼은 첫 화면(잠금이 꺼진 상태)에서만 누를 수 있다. 사용자가 이미 센터 CSV를 불러온 뒤라면 공개 단계를 돌릴 수 없기 때문이다.

정직하게 적을 점: 키가 없거나 인터넷이 막힌 평가 PC에서는 공개 단계 외부 요청이 0건이라 "표시값 0건"이 당연한 결과가 된다. 이 경우 화면에 "외부 AI 없이 점검함"이라고 표시하고, 실제 외부 호출이 있었던 실행 결과 캡처를 기획서에 따로 싣는다.

### 1-7. 라이브러리 몰래 통신 점검: 할 일 목록

- fastapi는 기본 설치만 쓴다. `fastapi[standard]`나 `fastapi[all]`을 설치하면 opentelemetry-sdk와 OTLP 내보내기가 함께 깔리므로 설치하지 않는다(메타데이터에서 확인). `FastAPI(telemetry=...)` 설정도 쓰지 않는다.
- run.bat에서 `OTEL_SDK_DISABLED=true`를 걸고 OTEL_EXPORTER_OTLP_ENDPOINT를 비운다. 센터 PC에 다른 프로그램이 OTEL 환경변수를 걸어 두었을 경우에 대비한 것이다.
- 화면에는 외부 CDN을 쓰지 않는다. 차트 라이브러리, 글꼴, 아이콘을 모두 static/에 넣는다. static/ 안에서 `http://`와 `https://` 문자열이 0건이어야 한다(오늘 확인하지 않았다).
- 새 패키지(차트, PDF 등)를 넣을 때마다 0절의 정적 검색을 다시 돌려 결과를 계획서 부록에 남긴다. matplotlib는 글꼴 캐시를 사용자 폴더에 만들지만 네트워크는 쓰지 않는 것으로 알고 있다(추정, 넣을 때 확인).
- 브리핑에 있던 "Streamlit 사용 통계 끄기"는 ADR-148로 FastAPI를 골랐으므로 해당이 없다. 기획서 10쪽의 그 문장은 "FastAPI 내장 원격 측정 미사용, 내보내기 부품 미설치"로 바꾼다.

### 1-8. 완료 기준

- 자가 점검 표의 모든 항목이 맥과 윈도우 시험 PC에서 통과한다.
- 숫자 검문 시험 20줄이 통과한다.
- 정적 검사(외부 통신 모듈 밖 네트워크 모듈 불러오기 0줄, static/ 외부 주소 0건)가 통과한다.

## 2. 반출 정책 조항별 구현 체크리스트

조항은 16번 2-2절이 원문에서 뽑은 것이다. "코드 위치"의 모듈 이름은 아키텍트와 맞출 가칭이다. 반출 처리 모듈은 10 미만 검사·묶기·내보내기 검사를 맡는 파일, 보고서 모듈은 png·PDF를 만드는 파일을 뜻한다.

| 조항(원문 요지) | 우리 결과물에서의 의미 | 코드 위치와 방법 | 확인 방법 |
|---|---|---|---|
| 응용집계(차이, 증감률, 비율, 순위, 지수, 검정값)는 수치를 포함해 반출 가능 | 반출 파일에 넣는 수치는 증가율(%), 두 증가율의 차이(퍼센트포인트), 행사 전 평균을 100으로 둔 월별 지수, 사전 추세 검사 값뿐이다. 소수 첫째 자리로 반올림한다 | 보고서 모듈이 받는 표에 "수치 종류" 칸을 두고 증가율·차이·지수·검정값만 허용한다. 원래 금액·건수·인원 칸이 들어오면 내보내기를 거절한다 | 원래 금액 합계를 일부러 넘기는 시험이 거절되는지 assert. 자가 점검의 "보고서 글자에서 표시값 합계 0건" |
| 시각화는 png·jpg만. SVG·HTML은 캡처로만 | 반출 파일은 png와 PDF뿐이다. 월별 두 선 그래프는 원래 금액이 아니라 지수로 그린다 | 그림은 서버에서 png로 저장한다(dpi 150). 화면 차트를 JS로 그리더라도 반출용은 서버 png를 쓴다. 활용 사유 문안은 txt로 저장하지 않고 화면 복사 버튼으로 준다 | 내보내기 뒤 반출 폴더의 확장자 집합이 {.pdf, .png}의 부분집합인지 assert |
| 소스코드에 데이터 출력(data.head() 등)이 있으면 반출 불가 | 이 제품은 코드나 노트북을 반출 파일로 만들지 않는다. 그래도 센터가 탑재 심사 때 코드를 볼 수 있으므로 코드에 데이터 출력을 두지 않는다 | 로그와 화면 오류에는 파일 이름과 개수만 쓰고 값과 행은 쓰지 않는다 | 제출 전 정적 검사: `.head(`, `.tail(`, `.sample(`, `print(df`, `to_string(`, `display(`가 app/ 안에 0건 |
| 10 미만 처리는 범주처리, 삭제처리, 비식별처리 중 하나 | 증가율을 계산하는 바탕 칸(읍면 × 달 × 관광객 × 업종 범위)의 인원·건수가 10 미만이면 처리한다. 인원·건수가 10 미만인 칸은 금액도 함께 가린다(30번 4-2절) | 반출 처리 모듈이 계획 JSON의 묶는 순서대로 처리한다. 먼저 범주처리(세부 업종을 대분류로, 그다음 전체 업종으로 묶음), 그래도 10 미만이면 삭제처리(그 비교 후보 또는 그 달 제외). 비식별처리(같은 값 처리)는 쓰지 않는다. 값을 바꾸면 증가율이 틀어지기 때문이다. 보고서에 "처리 방법: 범주처리(업종 대분류로 묶음), 삭제처리(○○면 제외)"를 적는다 | 가상 데이터(원본 행의 약 51%가 10 미만)로 돌린 뒤 계산에 쓴 모든 바탕 칸의 인원·건수가 10 이상인지 assert |
| 합계 등으로 가린 값을 역산할 수 있으면 반려 | 반출 파일에 합계 행, 원래 금액, 기준 달의 절대값, 행 수를 넣지 않는다. 증가율과 그 기준 금액을 함께 싣지 않는다 | 보고서 모듈의 표 허용 규칙(첫 줄)이 이것까지 막는다. PDF 끝의 "계산 근거표"에는 쓴 달, 읍면 이름, 업종 범위, 묶은 업종 이름, 적용 규칙, 월별 증가율·지수만 넣고 기준 금액은 넣지 않는다. 불러온 행 수는 화면에만 보이고 반출 파일에는 넣지 않는다 | 자가 점검의 표시값·합계 검색. 보고서 글자에 9자리 이상 숫자가 0건인지 확인 |
| 원본 제공 불가 데이터는 제공 단위 그대로의 합계·평균도 원칙적으로 반출 불가 | 읍면은 카드 데이터의 제공 단위(법정동)와 같다. 읍면별 금액 합계·평균은 절대 내보내지 않는다. 읍면별 증가율·지수가 이 조항에 걸리는지는 미확정이다 | 첫 줄의 허용 규칙으로 합계·평균을 막는다. 배지는 "반출 신청 가능(사전 점검 기준)"으로만 쓰고 "통과"라는 말은 쓰지 않는다. 운영진 답이 "불가"면 9절 질문의 선택지에 따라 권역 단위로 올리거나, 반출 파일에서 읍면 수치를 빼고 센터 안에서 읽는 보고서로 바꾼다 | 운영진 답변 기록. 답이 없으면 기획서 한계에 "운영진 확인 전"이라고 적는다 |

## 3. 결과 삭제 켜기·끄기

### 3-1. 지우는 것

| 위치 | 내용 | 지우는 방법 |
|---|---|---|
| out/ 전체 | 반출용 png·PDF, 전송 기록, 작업 기록, 자가 점검 결과물, out/tmp/의 임시 파일 | 폴더 안을 모두 지운다 |
| 서버 메모리 | 불러온 센터 CSV 내용, 합친 표, 계산 결과, 결과 문장, 센터 값이 들어간 계획 객체 | 세션 객체를 비우고 잠금을 푼다 |
| 운영체제 임시 폴더 | 파일 업로드 때 생기는 임시 파일 | 서버 시작 시 `tempfile.tempdir`을 out/tmp로 바꿔, 임시 파일이 생겨도 out/ 안에 생기게 한다. 한 줄이다 |
| 브라우저 | 없음 | 화면은 localStorage, sessionStorage를 쓰지 않는다. 끝내기 뒤 페이지를 새로 고친다 |

- 임시 파일 관련 아키텍트 권고: 브라우저 파일 선택으로 받은 CSV를 multipart 형식으로 올리면 Starlette가 일정 크기(기본 약 1MB로 알고 있음, 추정)를 넘는 파일을 운영체제 임시 폴더에 쓰고, python-multipart 패키지도 하나 더 필요하다. 브라우저에서 `fetch('/api/center/load', {method: 'POST', body: file})`로 파일 내용을 그대로 보내고 서버가 메모리로 읽으면 임시 파일도 추가 패키지도 생기지 않는다.
- 사용자가 센터에서 내려받은 원본 CSV(예: 다운로드 폴더의 Results_...csv)는 Agent가 만든 파일이 아니므로 기본으로 지우지 않는다. 확인 화면에 불러온 파일 이름 목록과 "센터 퇴실 규정에 따라 직접 지워 주세요" 안내를 보인다. 체크하면 함께 지우는 선택 칸(기본 꺼짐)은 밀리면 자를 항목이다.
- 수집기 로그(out/fetch_population.log)는 개발용이며 결과 삭제 때 함께 지워진다. 개발 중에는 알고 쓰면 된다.

### 3-2. 기본값

**사용자 결정 필요**

## 4. 키 관리

### 4-1. 원칙

- 키는 코드에 쓰지 않는다. 환경변수를 먼저 읽고, 없으면 .env를 읽는다.
- 개발 키(현재 app/.env)는 ZIP에 넣지 않는다.
- 허브 프로젝트 키는 ZIP에 넣지 않는다. 이유는 세 가지다. 개인 허브 계정에 묶인 키이고, 운영진이 ZIP에 넣으라고 한 것은 평가용 외부 AI 키뿐이며, 평가에는 동봉한 허브 스냅샷으로 충분하다. 코드는 허브 키가 없으면 스냅샷을 쓰고 화면에 "데이터 기준일"을 보인다. 센터 운영 때는 센터 담당자가 자기 허브 키를 환경변수로 넣는다.
- 평가용 외부 AI 키는 대회 전용으로 새로 만든다. Anthropic 콘솔에서 평가용 작업 공간을 따로 만들고 사용 한도를 건 뒤 그 안에서 키를 만든다. 한도 금액은 리허설에서 측정한 질문당 비용으로 정한다.
- 평가용 키는 전문가 평가가 끝나는 11/27 23:59 뒤에 폐기한다. ZIP은 대회 뒤에도 센터가 보관하고 쓰므로, 폐기하지 않으면 참가자 비용으로 계속 호출될 수 있다. 12/7 시상식 시연은 새 키를 쓴다.

### 4-2. ZIP에 평가용 키를 넣는 방식

**사용자 결정 필요**

| 비교 | .env에 미리 넣고 README에도 적음 (추천) | README에만 적고 평가자가 붙여 넣음 |
|---|---|---|
| 평가자 편의 | 아무것도 하지 않아도 AI 장면이 돈다 | 비개발자 평가자가 메모장으로 .env를 고치다 .env.txt로 저장하는 실수가 생길 수 있다(추론) |
| 운영진 답변 문구 "ZIP 매뉴얼에 넣어" | README의 "평가용 설정" 절에 같은 키를 적어 문구도 만족한다 | 문구 그대로다 |
| 노출 범위 | 둘 다 ZIP 안이라 같다. ZIP은 전문가 평가에만 쓰이고 상호평가에는 PDF만 공개된다 | 같다 |

- ZIP의 .env에는 `ANTHROPIC_API_KEY=(평가용)`, `HUB_PROJECT_KEY=`(빈칸), `RESULT_DELETE=on`만 둔다. .env.example도 함께 넣는다.

### 4-3. 기획서 PDF·캡처·ZIP 점검 (11/19 18:00 코드 동결 뒤)

ZIP 점검은 깨끗한 폴더에 푼 뒤 스크립트로 하고, 결과는 일치한 파일 이름만 찍는다. 키 값 자체는 화면에 찍지 않는다.

- `sk-ant-`로 시작하는 문자열이 있는 파일: 평가용 .env와 README의 평가용 절, 이 두 곳만이어야 한다.
- 개발 키와 허브 키: 개발용 .env에서 값을 읽어 ZIP 안 파일과 문자열 대조만 하고, 결과는 파일 이름만 찍는다. 0건이어야 한다. 평가용 키와 개발 키의 SHA-256이 다른지도 "같음/다름"으로만 찍는다.
- 개인 경로: `/Users/`, 사용자 계정 이름, `C:\Users\` 문자열이 0건이어야 한다.
- .pyc 파일과 __pycache__ 폴더, .DS_Store가 0개여야 한다. 파이썬은 .pyc에 컴파일한 위치의 절대 경로를 넣는다. 맥에서 윈도우용 패키지를 받을 때 `pip install --target ... --platform win_amd64 --only-binary=:all: --no-compile`처럼 --no-compile을 붙인다. 이것을 빼면 맥 경로가 든 .pyc가 생긴다.
- 패키지 메타데이터의 direct_url.json에 `file:///Users/...`가 들어갈 수 있다. 위 개인 경로 검색이 잡는다.
- .xlsx 파일이 0개여야 한다. 대회 제공 「제주데이터허브 데이터목록」 xlsx는 배포 금지이고, 센터 명세서 xlsx도 넣을 필요가 없다(spec/card_v02.json으로 충분하다).
- 기획서 PDF: PDF 뷰어에서 `sk-ant`, `KEY`, `/Users`, `C:\Users`, 사용자 계정 이름을 검색해 0건인지 본다. 맥에서는 `mdls -name kMDItemAuthors 파일.pdf`로 작성자 메타데이터에 개인 이름이 들어갔는지 확인한다. 상호평가가 익명인지 모르므로 지우는 쪽이 안전하다(추론).
- 캡처: 주소창(127.0.0.1:8501만 보여야 한다), 파일 선택 창의 경로(시연은 `C:\jeju\` 같은 중립 폴더에서 한다), 작업 표시줄의 사용자 이름, 전송 기록 화면(허브 키는 `{프로젝트키}`로 가려져 있어야 한다)을 본다. 화면의 오류 메시지는 파일 이름만 보이고 전체 경로는 보이지 않게 설계한다.

- 허브 주소의 한글 읍면 이름은 전송될 때 퍼센트 인코딩(예: 애월읍은 `%EC%95%A0%EC%9B%94%EC%9D%8D`)으로 바뀐다. 차단 장비가 인코딩을 풀어 대조하는지는 모른다. 풀어 대조하더라도 12곳 이름은 예시 키워드와 겹치지 않는다. 기획서 외부 주소 표에는 읍면 12곳 이름을 모두 적어 둔다.
- 허브 프로젝트 키가 주소 경로에 들어간다. 키는 무작위 영문·숫자라 영문 짐작어(ice 같은)가 우연히 들어 있을 수 있다. 사용자가 개발 PC에서 키를 화면에 찍지 않고 일치한 키워드만 찍는 대조를 한 번 돌린다. 센터 담당자의 허브 키는 우리가 대조할 수 없으므로 매뉴얼 오류 항목에 "허브 호출이 막히면 동봉 스냅샷으로 동작합니다"를 적는다.
- 차단돼도 멈추지 않는다. 허브는 스냅샷, 외부 AI는 미리 만든 계획 3개로 넘어간다(30번 4-2절 10번).

| GET /api/egress/state | `{"locked": bool, "reason": "str 또는 null", "locked_at": "str 또는 null", "sent": int, "blocked": int, "sent_after_lock": int, "outside_attempts": int}` |
| GET /api/egress/log | 전송 기록 목록(본문은 앞 200자). `?seq=N`이면 그 줄의 본문 전체 |
| POST /api/center/load | 본문에 CSV 내용 그대로. 첫 줄에서 lock 호출. 형식 검사 결과(파일 이름과 문제 종류만, 값 없음) |
| POST /api/selfcheck | 1-6절 판정 표(항목, 건수, 통과 여부) |
| GET /api/finish/preview | `{"delete": bool, "files": [{"name", "bytes"}], "memory": [str], "loaded_files": [str]}` |
| POST /api/finish | 요청 `{"delete": bool}`. 응답 `{"deleted": int, "failed": [str], "remaining": int, "locked": false}` |

### 10-3. 아키텍트에게 요청하는 제약

- 결과물을 쓰는 곳은 out/ 하나다. 파일 경로를 만드는 함수를 하나 두고 모든 쓰기가 그 함수를 거치게 한다.
- 서버 시작 때 `tempfile.tempdir`을 out/tmp로 바꾼다.
- 외부 AI 요청 본문을 만드는 함수는 공개 자료(명세 JSON, 허브 스냅샷, 행사 파일, 리허설 결과)와 검문을 통과한 사용자 입력만 받는다. out/ 파일과 센터 세션 객체를 인자로 받지 않는다.
- 화면 차트는 서버 png로 그리는 쪽이 컴플라이언스상 유리하다. 반출 그림과 화면 그림이 같아지고, 외부 CDN이 필요 없고, SVG·HTML 반출 경로가 생기지 않는다. 이것은 ADR-148의 미정 항목이라 사용자 결정 필요로 넘긴다.

## 12. 이번에 확인하지 못한 것

- 허브 데이터별 이용허락 범위와 축제 파일의 정확한 데이터 이름.
